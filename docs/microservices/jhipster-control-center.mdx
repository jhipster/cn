## 概述

JHipster Control Center 的主要目的是监控和管理应用程序。

它的所有功能都打包在一个带有现代 Vue 用户界面的外部应用程序中。其源代码在 GitHub 上的 JHipster 组织下可获得：[jhipster/jhipster-control-center](https://github.com/jhipster/jhipster-control-center)。

![](/images/jhipster-control-center-animation.gif)


## 特定的 Spring 配置文件

**Control Center 使用常规的 JHipster `dev` 和 `prod` Spring 配置文件。但是，为了正常工作，它必须使用与 Spring Cloud 发现后端对应的 Spring 配置文件启动。**

- `eureka`：连接到 Eureka 服务器并获取其注册的实例，在 application-eureka.yml 中配置
- `consul`：连接到 Consul 服务器并获取其注册的实例，在 application-consul.yml 中配置
- `static`：使用作为属性提供的静态实例列表，在 application-static.yml 中配置
- `kubernetes`：在 application-kubernetes.yml 中配置

这对于微服务架构非常有用：这就是 Control Center 知道哪些微服务可用以及哪些实例正在运行的方式。

对于所有应用程序（包括单体应用），这就是 Hazelcast 分布式缓存可以自动扩展的方式，请参阅 [Hazelcast 缓存文档](/using-cache/)


## 安装

### 本地运行

* ### 步骤 1：运行 Spring Cloud 发现后端使用的服务器

    Eureka 和 Consul docker-compose 文件存在于 src/main/docker 下，以便于测试项目（参见[特定的 Spring 配置文件](#specific-spring-profiles)）。

    - 对于 Consul：运行 `docker-compose -f src/main/docker/consul.yml up -d`
    - 对于 Eureka：运行 `docker-compose -f src/main/docker/jhipster-registry.yml up -d`
    - 对于 Kubernetes：参见 [kubernetes 文档](https://www.jhipster.tech/kubernetes/#deploying-to-kubernetes)
    - 否则，要使用静态实例列表，您可以直接转到下一步。

* ### 步骤 2：选择您的身份验证配置文件

    有 2 种身份验证类型（参见[身份验证机制](#authentication-mechanism)）：

    - JWT：这是默认身份验证，如果您选择这个，您不需要做任何事情。
    - OAuth2：要使用 OAuth2 身份验证，您必须启动 Keycloak。运行 `docker-compose -f src/main/docker/keycloak.yml up -d`
    

* ### 步骤 3：运行克隆的项目

    根据您想要的特定 Spring 配置文件运行 Control Center，以下是一些示例：

    - 对于使用 JWT 和 Consul 的开发，运行 `./mvnw -Dspring.profiles.active=consul,dev`
    - 对于使用 JWT 和 Eureka 的开发，运行 `./mvnw -Dspring.profiles.active=eureka,dev`
    - 对于使用 JWT 和静态实例列表的开发，运行 `./mvnw -Dspring.profiles.active=static,dev`
    - 对于使用 OAuth2 和 Consul 的开发，运行 `./mvnw -Dspring.profiles.active=consul,dev,oauth2`
    - 对于使用 OAuth2 和 Eureka 的开发，运行 `./mvnw -Dspring.profiles.active=eureka,dev,oauth2`
    - 要在开发中启动，请运行 `./mvnw`，并在另一个终端中运行 `npm start` 以实现客户端代码的热重载

### 从 Docker 运行

在 Docker Hub 上提供了容器镜像。要使用它，请运行以下命令：

- `docker pull jhipster/jhipster-control-center`
- `docker run -d --name jhcc -p 7419:7419 jhipster/jhipster-control-center:latest`


## 架构

这是一个标准的 Web 应用程序，通过其管理 API 端点连接到一个或多个 JHipster 应用程序。这些管理端点可以在标准 API 端口（通常为 8080、8081...）上公开，或者更好地在专用管理端口（通常为 9999）上公开，以便它们与外部世界隔离。

Control Center 使用 [Spring Cloud Gateway](https://docs.spring.io/spring-cloud-gateway/docs/current/reference/html/) 进行 API 路由，使用 Spring Cloud LoadBalancer 在调用另一个微服务时提供客户端负载均衡（默认情况下禁用 Ribbons，以使用 Spring Cloud LoadBalancer 的负载均衡实现）。

## 身份验证机制

为了访问您的应用程序，JHipster Control Center 根据配置文件使用特定的安全机制。

#### ***JWT***
这是一个自定义的 JHipster 实现。用于签名请求的 JWT 密钥对于应用程序和 Control Center 应该是相同的：由于默认情况下 Control Center 通过 Spring Cloud Config 配置应用程序，这应该开箱即用，因为它将向所有应用程序发送相同的密钥。

#### ***OAuth2***
此配置文件使用第三方授权 - 身份验证服务器，如 Keycloak（或即将推出的 Okta）。当您连接到 Control Center 时，Control Center 将使用 OAuth2 协议在 Keycloak 中生成会话。

然后，我们在 Oauth2SecurityConfiguration.java 中的安全配置将使用 Spring Security 的过滤器链从 Keycloak 获取授权，并使用 `http.oauth2Login()` 生成 Spring 的 Principal（当前用户）。之后，Spring Security 的过滤器链将应用 `http.oauth2ResourceServer().jwt().jwtAuthenticationConverter(jwtAuthenticationConverter())` 来获取具有其角色的身份验证。通过这种方式，我们可以轻松地更改我们的提供商（Keycloak、Okta 等）。


## 功能特性

### ***实例***

JHipster Control Center 提供应用程序实例列表。只要应用程序在服务器（consul 或 eureka）上注册，它就会在列表中可用。

![](/images/jhipster-control-center-instances.png)

### ***指标***

指标页面使用 Micrometer 提供应用程序性能的详细视图。

它提供以下指标：

- JVM
- HTTP 请求
- 缓存使用情况
- 数据库连接池

通过点击 JVM 线程指标旁的展开按钮，您将获得正在运行的应用程序的堆栈跟踪，这对于找出被阻塞的线程非常有用。

![](/images/jhipster-control-center-metrics.png)

### ***健康***

健康页面使用 Spring Boot Actuator 的健康端点来提供应用程序各个部分的健康信息。

Spring Boot Actuator 开箱即用地提供了许多健康检查，您可以添加特定于应用程序的健康检查。

![](/images/jhipster-control-center-health.png)

### ***配置***

配置页面使用 Spring Boot Actuator 的配置端点来提供当前应用程序的 Spring 配置的完整视图。

![](/images/jhipster-control-center-configuration.png)

### ***日志***

日志页面允许在运行时管理正在运行的应用程序的 Logback 配置。

您可以通过点击按钮来更改 Java 包的日志级别，这在开发和生产中都非常方便。

![](/images/jhipster-control-center-logs.png)

### ***日志文件***

日志文件页面允许在运行时查看正在运行的应用程序的日志。默认情况下它是禁用的，您需要配置它。如果日志文件被禁用，将显示此消息：

```
No available logfile. Please note that it is not available by default, you need to set up the Spring Boot properties below! 
Please check:
 - if the microservice is up
 - if these properties are set: 
     - logging.file.path
     - logging.file.name (to avoid using the same spring.log)

See:
 - https://docs.spring.io/spring-boot/docs/current/reference/html/production-ready-endpoints.html
 - https://docs.spring.io/spring-boot/docs/current/reference/html/howto-logging.html
```

![](/images/jhipster-control-center-logfile.png)

### ***API***

API 页面允许查看您的应用程序的所有 API 文档，并通过单个 Swagger UI 框架测试它们的端点。

![](/images/jhipster-control-center-api.png)
