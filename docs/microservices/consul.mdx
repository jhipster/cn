## Consul 概述

[Consul](https://www.consul.io/) 用作默认的服务注册中心解决方案。
与 Eureka 相比，它具有以下优劣：

- 在多节点集群中比 Eureka 更容易操作。
- 它偏向于一致性而不是可用性，因此集群状态的变化传播得更快。
- Consul 服务发现可以通过其 [DNS 接口](https://www.consul.io/docs/agent/dns.html) 或 [HTTP API](https://www.consul.io/docs/agent/http.html) 与现有应用程序互操作。

## 开始使用

要开始开发依赖于 Consul 注册中心的应用程序，您可以在 Docker 容器中启动 Consul 实例：

- 运行 `docker-compose -f src/main/docker/consul.yml up` 在 `dev` 模式下启动 Consul 服务器。然后 Consul 将在您的 Docker 主机的端口 `8500` 上可用，所以如果它在您的机器上运行，它应该在 [http://127.0.0.1:8500/](http://127.0.0.1:8500/)。

您还可以使用 [Docker Compose 子生成器](/docker-compose/#generating-a-custom-docker-compose-configuration-for-multiple-applications) 为多个启用 Consul 的应用程序生成 Docker 配置。


## 使用 Consul 进行应用程序配置

如果您在生成 JHipster 微服务或网关应用程序时选择了 Consul 选项，它们将被自动配置为从 Consul 的 **键/值存储** 中检索其配置。

键/值（K/V）存储可以使用在 [http://localhost:8500/v1/kv/](http://localhost:8500/v1/kv/) 可用的 UI 或其 [REST API](https://www.consul.io/intro/getting-started/kv.html) 进行修改。但是，以这种方式进行的更改是临时的，在 Consul 服务器/集群关闭时将丢失。
因此，为了帮助您与键/值存储交互并将您的配置作为 YAML 文件管理，JHipster 团队开发了一个小工具：[consul-config-loader](https://github.com/jhipster/consul-config-loader)。
**consul-config-loader** 在从 `consul.yml` docker-compose 文件启动 Consul 时会自动配置，但它也可以作为独立工具运行。
它可以在两种模式下运行：

- **dev** 模式，其中 `central-server-config` 目录中的 YAML 文件被自动加载到 Consul 中。此外，对此目录的任何更改都将立即与 Consul 同步。
- **prod** 模式，使用 Git2Consul 将 Git 仓库中包含的 YAML 文件设置为键/值存储的配置源。

请注意，与 JHipster Registry 一样，您的配置文件需要命名为 `appname-profile.yml`，其中 appname 和 profile 对应于您要配置的服务的应用程序名称和配置文件。例如，在 `consulapp-prod.yml` 文件中添加属性将仅为以 `prod` 配置文件启动的名为 `consulapp` 的应用程序设置这些属性。此外，在 `application.yml` 中定义的属性将为您的所有应用程序设置。
