## 概述

JHipster Registry 是一个运行时应用程序，由 JHipster 团队提供。与 JHipster 生成器一样，它是一个开源的、Apache 2 许可的应用程序，其源代码在 GitHub 上的 JHipster 组织下可用，位于 [jhipster/jhipster-registry](https://github.com/jhipster/jhipster-registry)。

JHipster Registry 有三个主要用途：

- 它是一个 [Eureka 服务器](https://cloud.spring.io/spring-cloud-netflix/spring-cloud-netflix.html)，作为应用程序的发现服务器。该服务器维护并分发可用应用程序实例的动态列表，然后微服务使用这些列表进行 HTTP 请求路由和负载均衡。
- 它是一个 [Spring Cloud Config 服务器](https://cloud.spring.io/spring-cloud-config/spring-cloud-config.html)，为所有应用程序提供运行时配置。
- 它是一个管理服务器，具有用于监控和管理应用程序的仪表板。

所有这些功能都打包到一个方便的应用程序中，具有基于现代 Angular 的用户界面。

## 安装

### Spring 配置文件

JHipster Registry 使用通常的 JHipster `dev` 和 `prod` Spring 配置文件，以及 Spring Cloud Config 的标准 `composite` 配置文件（参见[官方文档](https://cloud.spring.io/spring-cloud-config/multi/multi__spring_cloud_config_server.html#composite-environment-repositories)）。

结果是：

- 使用 `dev` 配置文件将使用 `dev` 和 `composite` 配置文件运行 JHipster Registry。`dev` 配置文件将从文件系统加载 Spring Cloud 配置，在 `src/main/resources/config/bootstrap.yml` 文件中定义的相对于运行目录的 `central-config` 目录中查找。
- 使用 `prod` 配置文件将使用 `prod` 和 `composite` 配置文件运行 JHipster Registry。`prod` 配置文件将从 Git 仓库加载 Spring Cloud 配置，默认为 [https://github.com/jhipster/jhipster-registry-sample-config](https://github.com/jhipster/jhipster-registry-sample-config)。在实际使用中，应该更改此仓库，要么在 `src/main/resources/config/bootstrap-prod.yml` 文件中重新配置，要么重新配置 `spring.cloud.config.server.composite` Spring 属性。

一旦 JHipster Registry 运行，您可以在 `Configuration > Cloud Config` 菜单中检查其配置。请注意，如果您无法登录，可能是因为 JWT 签名密钥未正确设置，这表明您的配置不好。

### 使用预打包的 JAR 文件

JHipster Registry 作为可执行 JAR 文件在我们的[发布页面](https://github.com/jhipster/jhipster-registry/releases)上提供。

下载 JAR 文件，并像运行其他 JHipster 应用程序一样运行它，使用您想要使用的配置文件（参见前面关于配置文件的部分）。例如，要使用存储在 `central-config` 目录中的 Spring Cloud Config 配置运行它：

```shell
java -jar jhipster-registry-<version>.jar --spring.security.user.password=admin --jhipster.security.authentication.jwt.secret=my-secret-key-which-should-be-changed-in-production-and-be-base64-encoded --spring.cloud.config.server.composite.0.type=native --spring.cloud.config.server.composite.0.search-locations=file:./central-config
```

请注意，在启动时向注册中心提供 JWT 密钥非常重要，可以通过 `JHIPSTER_SECURITY_AUTHENTICATION_JWT_SECRET` 环境变量或如上所示的参数提供。另一种可能的方式是在您的集中配置源的 `application.yml` 文件中设置此值（该值在启动时由所有应用程序包括注册中心加载）。

请注意，自 JHipster 5.3.0 起，我们有一个新的 `jhipster.security.authentication.jwt.base64-secret` 属性，它更安全，但由于您可能仍在使用旧版本，我们在本文档中使用 `jhipster.security.authentication.jwt.secret`。有关这些属性的更多信息在我们的[安全文档](/security/)中提供。

同样，要使用 `prod` 配置文件运行注册中心，请根据您的设置调整参数，例如：

```shell
java -jar jhipster-registry-<version>.jar --spring.profiles.active=prod --spring.security.user.password=admin --jhipster.security.authentication.jwt.secret=my-secret-key-which-should-be-changed-in-production-and-be-base64-encoded --spring.cloud.config.server.composite.0.type=git --spring.cloud.config.server.composite.0.uri=https://github.com/jhipster/jhipster-registry-sample-config

java -jar jhipster-registry-<version>.jar --spring.profiles.active=prod --spring.security.user.password=admin --jhipster.security.authentication.jwt.secret=my-secret-key-which-should-be-changed-in-production-and-be-base64-encoded --spring.cloud.config.server.composite.0.type=git --spring.cloud.config.server.composite.0.uri=https://github.com/jhipster/jhipster-registry --spring.cloud.config.server.composite.0.search-paths=central-config
```

### 从源代码构建

JHipster Registry 可以直接从 [jhipster/jhipster-registry](https://github.com/jhipster/jhipster-registry) 克隆/分叉/下载。由于 JHipster Registry 也是一个 JHipster 生成的应用程序，您可以像运行任何其他 JHipster 应用程序一样运行它：

- 使用 `./mvnw`（用于 Java 服务器）和 `npm start`（用于管理前端）在开发中运行，它将默认使用 `dev` 配置文件，并在 [http://127.0.0.1:8761/](http://127.0.0.1:8761/) 上可用。
- 使用 `./mvnw -Pprod package` 打包生产环境，并生成通常的 JHipster 可执行 JAR 文件。然后您可以使用 `dev` 或 `prod` Spring 配置文件运行 JAR 文件，例如：`java -jar jhipster-registry-<version>.jar --spring.profiles.active=prod`

请注意，要使用 `dev` 和 `composite` 配置文件，您需要有一个包含配置的 `central-config` 目录，所以如果您运行 `java -jar jhipster-registry-<version>.jar --spring.profiles.active=dev`，您需要设置该目录。

### 使用 Docker

如果您更愿意从 Docker 镜像运行 JHipster Registry，它在 Docker Hub 上可用，位于 [jhipster/jhipster-registry](https://hub.docker.com/r/jhipster/jhipster-registry/)。每个微服务 `src/main/docker` 目录中都有一个 docker-compose 文件来运行此镜像：

- 运行 `docker-compose -f src/main/docker/jhipster-registry.yml up` 启动 JHipster Registry。它将在您的 Docker 主机的端口 `8761` 上可用，所以如果它在您的机器上运行，它应该在 [http://127.0.0.1:8761/](http://127.0.0.1:8761/)。

请阅读我们的 [Docker Compose 文档](/docker-compose/) 了解有关使用 Docker Compose 运行 JHipster Registry 的更多信息。

### 在云中运行

您可以在云中运行 JHipster Registry 实例。这在生产中是强制性的，但在开发中也很有用（无需在您的笔记本电脑上运行它）。

请阅读[生产中的微服务文档](/microservices-in-production/)了解如何将 JHipster Registry 部署到 Heroku。


## 使用 Eureka 进行服务发现

![](/images/jhipster-registry-eureka.png)

JHipster Registry 是一个 [Netflix Eureka 服务器](https://github.com/Netflix/eureka)，为所有应用程序提供服务发现。

- 这对微服务架构非常有用：这是网关知道哪些微服务可用以及哪些实例启动的方式
- 对于所有应用程序，包括单体应用，这是 Hazelcast 分布式缓存自动扩展的方式，参见 [Hazelcast 缓存文档](/using-cache/)


## 使用 Spring Cloud Config 进行应用程序配置

![](/images/jhipster-registry-spring-cloud-config.png)

JHipster Registry 是一个 [Spring Config 服务器](http://cloud.spring.io/spring-cloud-config/spring-cloud-config.html)：当应用程序启动时，它们首先连接到 JHipster Registry 以获取其配置。这对网关和微服务都适用。

此配置是一个 Spring Boot 配置，类似于 JHipster `application-*.yml` 文件中的配置，但它存储在中央服务器中，因此更容易管理。

在启动时，您的网关和微服务应用程序将查询注册中心的配置服务器，并用那里定义的属性覆盖其本地属性。

有两种配置源可用（由 `spring.cloud.config.server.composite` 属性定义）：

- 一个 `native` 配置，默认在开发中使用（使用 JHipster `dev` 配置文件），它使用本地文件系统。
- 一个 `Git` 配置，默认在生产中使用（使用 JHipster `prod` 配置文件），它将配置存储在 Git 服务器中。这允许使用常用的 Git 工具标记、分支或回滚配置，在这种使用场景中非常强大。

要管理您的集中配置，您需要在您的配置源中添加 `appname-profile.yml` 文件，其中 **appname** 和 **profile** 对应于您要配置的服务的应用程序名称和当前配置文件。
例如，在 `gateway-prod.yml` 文件中添加属性将仅为以 **prod** 配置文件启动的名为 **gateway** 的应用程序设置这些属性。此外，在 `application[-dev|prod].yml` 中定义的属性将为您的所有应用程序设置。

由于网关路由是使用 Spring Boot 配置的，它们也可以使用 Spring Config 服务器进行管理，例如您可以将应用程序 `app1-v1` 映射到您的 `v1` 分支中的 `/app1` URL，并将应用程序 `app1-v2` 映射到您的 `v2` 分支中的 `/app1` URL。这是在不中断最终用户的情况下升级微服务的好方法。


## 使用加密配置值

JHipster Registry 有一个特定的 `configuration > encryption` 页面，允许加密和解密配置值。

要加密配置值（例如，数据库密码），您需要：

- 下载 [JCE](http://www.oracle.com/technetwork/java/javase/downloads/jce8-download-2133166.html) 并按照下载文件中的说明安装（这仅在您使用 Oracle JDK 时需要）。
- 在 `bootstrap.yml`（不是 `application.yml`）中设置 `encrypt.key` 属性，或使用 `ENCRYPT_KEY` 环境变量与您的对称密钥密码。

如果一切设置正确，您应该能够使用特定的 `Configuration > Encryption` 页面，也可以向 `/config/encrypt` 和 `/config/decrypt` 端点发送 POST 请求，在请求的 `body` 中包含您想要操作的文本。

例如：`curl localhost:8761/config/encrypt -d mypassword`

密码文本必须以 `password= '{cipher}myciphertextafterencryotion'` 的形式放置在任何 `*.yml` 配置文件中，配置服务器将在发送给客户端之前对其进行解密。这样您的配置文件（存储在 Git 中或存储在您的文件系统上的"本地"）就不会有明文值。

有关更多信息，请参阅 Spring Cloud Config 的[加密和解密文档](http://cloud.spring.io/spring-cloud-config/spring-cloud-config.html#_encryption_and_decryption)。


## 管理仪表板

JHipster Registry 提供管理仪表板，用于所有应用程序类型。一旦应用程序在 Eureka 服务器上注册，它将在仪表板中可用。

为了从应用程序访问敏感信息，JHipster Registry 将使用 JWT 令牌（这就是为什么 JHipster Registry 仅适用于使用 JWT 的应用程序）。用于签署请求的 JWT 密钥应该对应用程序和 JHipster Registry 相同：由于默认情况下 JHipster Registry 通过 Spring Cloud Config 配置应用程序，这应该开箱即用，因为它会向所有应用程序发送相同的密钥。

### 指标仪表板

![](/images/jhipster-registry-metrics.png)

指标仪表板使用 Micrometer 提供应用程序性能的详细视图。

它提供以下指标：

- JVM
- HTTP 请求
- 缓存使用情况
- 数据库连接池

通过点击 JVM 线程指标旁边的展开按钮，您将获得正在运行的应用程序的堆栈跟踪，这对于查找被阻塞的线程非常有用。

注意：由于我们将 JHipster Registry 切换为监控来自 Micrometer 的指标而不是 Dropwizard 指标，这意味着所有使用 5.7.2 或更早版本生成的 JHipster 应用程序都应该迁移到 Micrometer 才能使用 JHipster Registry 进行监控。如果您不想迁移您的应用程序，请使用 JHipster Registry v4.0.6 或更早版本。

要迁移您的应用程序，您可以使用[JHipster 升级子生成器](/upgrading-an-application/)。

### 健康仪表板

![](/images/jhipster-registry-health.png)

健康仪表板使用 Spring Boot Actuator 的健康端点提供有关应用程序各个部分的健康信息。
Spring Boot Actuator 提供了许多开箱即用的健康检查，您可以添加特定于应用程序的健康检查。

### 配置仪表板

![](/images/jhipster-registry-configuration.png)

配置仪表板使用 Spring Boot Actuator 的配置端点提供当前应用程序的 Spring 配置的完整视图。

### 日志仪表板

![](/images/jhipster-registry-logs.png)

日志仪表板允许在运行时管理正在运行的应用程序的 Logback 配置。
您可以通过点击按钮更改 Java 包的日志级别，这在开发和生产中都非常方便。


## 保护 JHipster Registry

JHipster Registry 默认是安全的。您可以使用通常在正常 JHipster 应用程序中使用的 "admin/admin" 登录名和密码登录。

应用程序也使用相同的 "admin" 用户连接到 JHipster Registry，但使用 HTTP 基本认证。因此，如果您的微服务无法访问注册中心，并且您看到一些 "401 认证错误" 消息，那是因为您错误配置了这些应用程序。

为了保护您的 JHipster Registry：

- 您必须更改默认的 "admin" 密码。此密码使用标准 Spring Boot 属性 `spring.security.user.password` 设置，因此您可以使用通常的 Spring Boot 机制来修改它：您可以修改项目的 `application-*.yml` 文件，或添加 `SPRING_SECURITY_USER_PASSWORD` 环境变量。[Docker Compose 子生成器](/docker-compose/) 使用环境变量方法。
- 由于您的应用程序将使用 HTTP 连接到注册中心，保护该连接通道非常重要。有很多方法可以做到这一点，最简单的方法可能是使用 HTTPS。
