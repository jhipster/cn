# 使用 JHipster 开发微服务

## 微服务 vs 单体架构

JHipster 会问您的第一个问题是您想要生成的应用程序类型。您可以在两种架构风格之间进行选择：

- "单体"架构使用单一的、一刀切的应用程序，它同时包含前端代码和后端 Spring Boot 代码。
- "微服务"架构将前端和后端分离，这样您的应用程序更容易扩展并在基础设施问题中幸存。

"单体"应用程序更容易开发，所以如果您没有任何特定要求，这是我们推荐的选项，也是我们的默认选项。


## 微服务架构概述

JHipster 微服务架构的工作方式如下：

* [网关](/api-gateway/) 是一个 JHipster 生成的应用程序（使用微服务网关类型），旨在处理 Web 流量并提供 Angular、React 或 Vue 应用程序。虽然您可以遵循 [Backends for Frontends 模式](https://www.thoughtworks.com/insights/blog/bff-soundcloud) 拥有多个网关，但这不是必需的。网关构建在 Spring Cloud Gateway 库上，支持 MVC 和 WebFlux 框架。
* [Consul](/consul/) 是一个服务发现服务，同时也是一个键/值存储。
* [JHipster Registry](/jhipster-registry/) 是一个运行时应用程序，所有应用程序都在其中注册并从中获取配置。它还提供运行时监控仪表板。它可以用作 Consul 的替代方案。*（已弃用）*
* [微服务](/creating-microservices/) 是 JHipster 生成的应用程序（在生成它们时使用应用程序类型 `microservice application`），处理 REST 请求。它们是无状态的，可以并行启动多个实例来处理重负载。

此图展示了利用 JHipster 的微服务架构，包含了 Netflix OSS、Spring Cloud 和 Docker 等关键技术。它具有处理 Web 流量和用户身份验证的网关、用于后端操作的微服务，以及使用 OpenTelemetry、Elasticsearch、Logstash 和 Kibana 等工具的全面监控和日志记录。
