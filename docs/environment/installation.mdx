## 安装类型

我们提供了3种使用 JHipster 的方式。如果不确定，请选择第2种选项 "使用 NPM 本地安装"：

- [JHipster Online](https://start.jhipster.tech/) 无需安装 JHipster 即可生成应用程序。
- "使用 NPM 本地安装" 是使用 JHipster 的经典方式。所有组件都安装在您的机器上，设置可能有点复杂，但这是大多数人通常使用的方式。
- "[Docker](https://www.docker.io/)" 容器，为您提供一个安装了 JHipster 的轻量级容器。


## JHipster Online（适用于希望简化运行 JHipster 的用户）

[JHipster Online](https://start.jhipster.tech/) 允许您生成 JHipster 应用程序，而无需安装 JHipster。

这适用于第一次尝试 JHipster 的人，或者想了解 JHipster 提供哪些功能的人。

虽然它更容易使用，但这不是"完整的 JHipster 体验"，一旦生成了应用程序，您仍然需要遵循下一节（"使用 NPM 本地安装"）中的大部分步骤，因为您仍然需要 Java（运行应用程序）和 NPM（管理前端代码）。

未来，我们预计 JHipster Online 将提供更多功能。


## 使用 NPM 本地安装（推荐普通用户使用）

### 快速设置

1.  安装 Java 17 或 21 LTS。我们推荐您使用 [Eclipse Temurin builds](https://adoptium.net/temurin/releases/?version=21)，因为它们是开源且免费的。
2.  从 [Node.js 官网](http://nodejs.org/) 安装 Node.js（请使用 LTS 64位版本，不支持非LTS版本）
3.  安装 JHipster：`npm install -g generator-jhipster`
4.  （可选）如果您想使用模块或蓝图（例如来自 [JHipster 应用市场](/modules/marketplace/)），请安装 [Yeoman](https://yeoman.io/)：`npm install -g yo`

现在 JHipster 已安装，您的下一步是[创建应用程序](/creating-an-app/)

### 可选安装

1. 安装 Java 构建工具。
    *   无论您选择使用 [Maven](http://maven.apache.org/) 还是 [Gradle](http://www.gradle.org/)，您通常不必安装任何东西，因为 JHipster 将自动为您安装 [Maven Wrapper](https://github.com/takari/maven-wrapper) 或 [Gradle Wrapper](http://gradle.org/docs/current/userguide/gradle_wrapper.html)。
    *   如果您不想使用这些包装器，请访问官方 [Maven 网站](http://maven.apache.org/)或 [Gradle 网站](http://www.gradle.org/)进行自定义安装。
2.  从 [git-scm.com](http://git-scm.com/) 安装 Git。如果您刚开始使用 Git，我们推荐您也使用如 [SourceTree](http://www.sourcetreeapp.com/) 等工具。
    * 如果已安装 Git，JHipster 将尝试将您的项目提交到 Git。
    * [JHipster 升级子生成器](/upgrading-an-application/)需要安装 Git。

### 附加信息

JHipster 使用 [Yeoman](http://yeoman.io/) 进行代码生成。
要获取更多信息、技巧和帮助，在[提交错误报告](https://github.com/jhipster/generator-jhipster/issues?state=open)之前，请先查看 [Yeoman "入门"指南](http://yeoman.io/learning/index.html)。

配置将存储在生成的 `.yo-rc.json` 文件中，因此**强烈建议**不要在您的 HOME 目录中生成 JHipster 项目。如果您这样做了，您将无法在子目录中生成另一个项目。要解决此问题，请删除 `.yo-rc.json` 文件。


## Docker 安装（仅限高级用户）

:::note

此 Docker 镜像用于在容器内运行 JHipster 生成器。它与 JHipster 将生成的 [Docker 和 Docker Compose 配置](/docker-compose/)完全不同，后者的目标是在容器内运行您生成的应用程序

:::

### 信息

JHipster 有一个特定的 [Dockerfile](https://github.com/jhipster/generator-jhipster/blob/main/Dockerfile)，提供了 [Docker](https://www.docker.io/) 镜像。

它在以下地址提供 Docker "自动构建"：[https://hub.docker.com/r/jhipster/jhipster/](https://hub.docker.com/r/jhipster/jhipster/)

此镜像将允许您在 Docker 内运行 JHipster。

### 前置条件

1.  **（推荐）Docker Desktop：**构建、运行和测试容器化应用的最简单方式。[Docker Desktop](https://docs.docker.com/desktop/) 附带管理容器/镜像/卷的图形界面、Docker 开发工具、Kubernetes 支持等更多功能。
2.  **Docker Engine：**具有命令行界面 (CLI) 的客户端-服务器应用程序。请遵循 [Docker Engine](https://docs.docker.com/engine/install/) 安装说明

由于生成的文件在您的共享文件夹中，如果您停止 Docker 容器，它们不会被删除。但是，如果您不希望 Docker 在每次启动容器时继续下载所有 Maven 和 NPM 依赖项，您应该提交其状态或挂载一个卷。

:::warning

根据您的操作系统，您的 `DOCKER_HOST` 将有所不同。在 Linux 上，它将是您的 localhost。
对于 Mac/Windows，您必须使用以下命令获取 IP：`docker-machine ip default`

:::

在 Linux 上，如果您的用户不属于 docker 组，您可能需要以 root 用户身份运行 `docker` 命令。将您的用户添加到 docker 组是一个好主意，这样您就可以以非root用户身份运行 docker 命令。请遵循 [http://askubuntu.com/a/477554](http://askubuntu.com/a/477554) 上的步骤进行操作。

### 在 Linux/Mac Windows 上使用（使用 Docker）

#### 拉取镜像

拉取最新的 JHipster Docker 镜像：

```shell
docker image pull jhipster/jhipster
```

拉取开发版 JHipster Docker 镜像：

```shell
docker image pull jhipster/jhipster:master
```

您可以在[这里](https://hub.docker.com/r/jhipster/jhipster/tags/)查看所有标签

#### 运行镜像

:::warning

如果您在 Mac 或 Windows 上使用 Docker Machine，您的 Docker 守护进程对您的 OS X 或 Windows 文件系统的访问有限。Docker Machine 尝试自动共享您的 /Users (OS X) 或 C:\Users\<username> (Windows) 目录。因此，您必须在这些目录下创建项目文件夹，以避免任何卷挂载问题。

:::

在您的主目录中创建一个 "jhipster" 文件夹：

```shell
mkdir ~/jhipster
```

使用以下选项运行 Docker 镜像：

* Docker "/home/jhipster/app" 文件夹共享到本地 "~/jhipster" 文件夹
* 转发 Docker 暴露的所有端口（8080 用于 Java 应用程序，9000 用于 BrowserSync，3001 用于 BrowserSync UI）

```shell
docker container run --name jhipster -v ~/jhipster:/home/jhipster/app -v ~/.m2:/home/jhipster/.m2 -p 8080:8080 -p 9000:9000 -p 3001:3001 -d -t jhipster/jhipster
```

:::tip

如果您之前已经启动过一次容器，您不需要运行上述命令，您可以启动/停止现有容器。

:::

#### 检查容器是否正在运行

要检查您的容器是否正在运行，请使用命令：

```shell
docker container ps

CONTAINER ID    IMAGE               COMMAND                 CREATED         STATUS          PORTS                                                       NAMES
4ae16c0539a3    jhipster/jhipster   "tail -f /home/jhipst"  4 seconds ago   Up 3 seconds    0.0.0.0:9000-3001->9000-3001/tcp, 0.0.0.0:8080->8080/tcp    jhipster
```

#### 常用操作

* 停止容器运行：`docker container stop jhipster`
* 再次启动，运行：`docker container start jhipster`

如果您更新了 Docker 镜像（重新构建或从 Docker hub 拉取），最好删除现有容器，然后重新运行容器。要这样做，首先停止容器，删除它，然后再次运行：

1.  `docker container stop jhipster`
2.  `docker container rm jhipster`
3.  `docker image pull jhipster/jhipster`
4.  `docker container run --name jhipster -v ~/jhipster:/home/jhipster/app -v ~/.m2:/home/jhipster/.m2 -p 8080:8080 -p 9000:9000 -p 3001:3001 -d -t jhipster/jhipster`

### 访问容器

:::warning

在 Windows 上，您需要以管理员身份运行 Docker 快速终端，以便在 `npm install` 步骤中创建符号链接。

:::

登录正在运行的容器的最简单方法是执行以下命令：

```shell
docker container exec -it <container_name> bash
```

如果您复制粘贴了上面的命令来运行容器，请注意您必须指定 `jhipster` 作为容器名称：

```shell
docker container exec -it jhipster bash
```

您将以 "jhipster" 用户身份登录。

如果您想以 "root" 身份登录，由于 Ubuntu Xenial 中不可用 `sudo` 命令，您需要运行：

```shell
docker container exec -it --user root jhipster bash
```

### 您的第一个项目

然后您可以转到容器中的 /home/jhipster/app 目录，并开始在 Docker 内构建您的应用程序：

```shell
cd /home/jhipster/app

jhipster
```

创建应用程序后，您可以运行所有正常的 gulp/bower/maven 命令，例如：

```shell
./mvnw
```

**恭喜！您已经在 Docker 内启动了 JHipster 应用程序！**

在您的机器上，您应该能够：

* 在 `http://DOCKER_HOST:8080` 访问正在运行的应用程序
* 在您的共享文件夹中获取所有生成的文件

:::warning
默认情况下，Docker 未安装在 `jhipster/jhipster` 镜像内。

因此您将无法：
- 使用 docker-compose 文件
- 使用 docker 守护进程构建 Docker 镜像（Maven 目标：`jib:dockerBuild` 或 Gradle 任务：`jibDockerBuild`）

但是，您可以使用 [jib](https://github.com/GoogleContainerTools/jib) 的无守护进程模式，该模式可以在不访问 docker 守护进程的情况下构建 docker 镜像并将其推送到注册表（Maven 目标：`jib:build` 或 Gradle 任务：`jibBuild`）。
但是您需要在构建应用程序之前设置 docker 注册表的凭据作为前提条件。
有关更多详细信息，请参阅 [Jib 插件配置文档](https://github.com/GoogleContainerTools/jib/tree/master/jib-maven-plugin#configuration)。

:::
