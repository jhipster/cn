强烈建议在开发中使用 Docker 和 Docker Compose，这在生产环境中也是一个很好的解决方案。

Docker Compose 默认用于开发、测试和 CI 脚本，也可以[禁用](#disabling)。

## 描述

:::note

此 Docker 配置用于在容器镜像内运行您生成的应用程序。这与 JHipster 还提供的[Docker 设置](/installation/)完全不同，后者是为了在容器内运行 JHipster 生成器

:::

JHipster 提供完整的 Docker 支持，目的是：

- 便于开发，您可以使用单个命令启动完整的基础设施，即使使用复杂的微服务架构
- 对于使用 Docker Swarm 的人员，可以直接部署到生产环境，因为它使用相同的 Docker Compose 配置

使用 Docker Compose 的一个重要特性是您可以使用 `docker-compose scale` 命令扩展容器。如果您将 JHipster 与[微服务架构](#building-and-running-a-docker-image-of-your-application)一起使用，这会非常有趣。

生成应用程序时，JHipster 会为您生成多个 Docker Compose 配置，以帮助您运行应用程序与第三方服务（例如数据库）。这些文件位于 `src/main/docker/` 文件夹内。


## 先决条件

您必须安装 Docker 和 Docker Compose：

- [Docker](https://docs.docker.com/installation/#installation)
- [Docker Compose](https://docs.docker.com/compose/install)

Docker 现在需要创建 Docker Store 账户来下载 Docker for Mac 和 Docker for Windows。要绕过这个要求

:::tip

在 Windows 和 Mac OS X 上，Kitematic 是 Docker Toolbox 提供的易于使用的图形界面，这将使 Docker 的使用变得更加容易。

:::

:::warning

如果您在 Mac 或 Windows 上使用 Docker Machine，您的 Docker 守护进程只能有限地访问您的 OS X 或 Windows 文件系统。Docker Machine 尝试自动共享您的 /Users (OS X) 或 C:\Users\&lt;username&gt; (Windows) 目录。因此，您必须在此目录下创建项目文件夹以避免任何问题。

:::

如果在安装 JHipster UML（或任何未捆绑的包）时遇到错误 `npm ERR! Error: EACCES: permission denied`，您的容器可能没有安装 `sudo`（例如，sudo 没有与 Ubuntu Xenial 捆绑）。

__解决方案 1__

NPM 文档建议不要以 root 身份安装任何 NPM 包。请按照[官方文档](https://docs.npmjs.com/getting-started/fixing-npm-permissions)来解决此问题。

__解决方案 2__

  - `docker container exec -u root -it jhipster bash`,
  - `npm install -g YOUR_PACKAGE`,
  - 然后退出并正常登录到容器：`docker container exec -it jhipster bash`


## 构建和运行您应用程序的 Docker 镜像

使用 [Jib](https://github.com/GoogleContainerTools/jib) 连接到本地 Docker 守护进程来构建您应用程序的 Docker 镜像：

- NPM：`npm run java:docker`，在 Apple Silicon 上：`npm run java:docker:arm64`
- Maven：`./mvnw package -Pprod verify jib:dockerBuild`
- Gradle：`./gradlew -Pprod bootJar jibDockerBuild`

不使用 Docker 构建您应用程序的 Docker 镜像并直接推送到您的 Docker 仓库，运行：

- Maven：`./mvnw package -Pprod verify jib:build -Djib.to.image=<dockerhub-username>/<artifact-id>`
- Gradle：`./gradlew -Pprod bootJar jib -Djib.to.image=<dockerhub-username>/<artifact-id>`

如果这对您不立即工作，请参考 Jib 文档了解配置详细信息，特别是关于如何设置 Docker 仓库身份验证：

- [Jib maven 插件文档](https://github.com/GoogleContainerTools/jib/tree/master/jib-maven-plugin#configuration)
- [Jib gradle 插件文档](https://github.com/GoogleContainerTools/jib/tree/master/jib-gradle-plugin#configuration)

:::warning

由于 Jib 的工作方式，它将首先尝试从配置的 Docker 仓库中拉取基础 Docker 镜像的最新版本。这是有意为之的，因为在 CI 环境中，您必须确保始终在最新的修补基础镜像上构建。

然而在本地环境中，如果 jib 无法访问 Docker 仓库，这可能会导致构建失败。解决方案是使用 `--offline` 标志，只要 jib 在其缓存中已经拉取了基础 Docker 镜像，这就可以解决问题。

使用 Maven，输入：`./mvnw -Pprod package verify jib:dockerBuild --offline`
使用 Gradle，输入：`./gradlew -Pprod bootJar jibDockerBuild --offline`

如果 jib 尚未在其缓存中拉取基础 Docker 镜像，要这样做，您需要修改 pom.xml（在 Maven 情况下）或 docker.gradle（在 Gradle 情况下），在您的基础镜像前面添加 `docker://` 作为前缀（在“image”标签上，嵌套在“from”标签中）。

示例：`docker://imagename:latest`
这样 jib 将您本地 docker 守护进程中存在的镜像放入其缓存中。

:::

要运行此镜像，请使用位于您应用程序的 `src/main/docker` 文件夹中的 Docker Compose 配置：

- `docker-compose -f src/main/docker/app.yml up`

此命令将启动您的应用程序以及它依赖的服务（数据库、搜索引擎、Consul、JHipster Registry...）。

如果您选择 OAuth 2.0 进行身份验证，请务必阅读我们在此文档中的 [Keycloak 部分](#keycloak)。


## 为多个应用程序生成自定义 Docker-Compose 配置

如果您的架构由多个 JHipster 应用程序组成，您可以使用特定的 `docker-compose` 子生成器，它将为所有选定的应用程序生成全局 Docker Compose 配置。这将允许您使用一个命令部署和扩展您的完整架构。
要使用 `docker-compose` 子生成器：

- 您需要将所有的单体应用、网关和微服务放在同一个目录中。
- 创建另一个目录，例如 `mkdir docker-compose`。
- 进入该目录：`cd docker-compose`。
- 运行子生成器：`jhipster docker-compose`。
- 子生成器将询问您希望在架构中包含哪个应用程序，以及您是否要使用 ELK 或 Prometheus 设置监控。

这将生成全局 Docker Compose 配置，输入 `docker-compose up` 来运行它，并让您的所有服务同时运行。

在微服务架构的情况下，此配置还将预配置 Consul 或 JHipster Registry，它们将自动配置您的服务：

- 这些服务将等待 Consul（或 JHipster Registry）运行后才开始。这可以在您的 `bootstrap-prod.yml` 文件中使用 `spring.cloud[.consul].config.fail-fast` 和 `spring.cloud[.consul].config.retry` 键进行配置。
- 注册中心将配置您的应用程序，例如它将在所有服务之间共享 JWT 秘密令牌。
- 使用 Docker Compose 完成每个服务的扩展，例如输入 `docker-compose scale test-app=4` 来运行 4 个“test”应用程序实例。这些实例将自动由网关进行负载均衡，并将自动加入同一个 Hazelcast 集群（如果 Hazelcast 是您的 Hibernate 二级缓存）。


## 使用数据库

### MySQL、MariaDB、PostgreSQL、Oracle、MongoDB、Couchbase、Neo4j 或 Cassandra

运行 `docker-compose -f src/main/docker/app.yml up` 已经自动启动您的数据库。

如果您只想启动您的数据库，而不想启动其他服务，请使用您数据库的 Docker Compose 配置：

- 使用 MySQL：`docker-compose -f src/main/docker/mysql.yml up`
- 使用 MariaDB：`docker-compose -f src/main/docker/mariadb.yml up`
- 使用 PostgreSQL：`docker-compose -f src/main/docker/postgresql.yml up`
- 使用 Oracle：`docker-compose -f src/main/docker/oracle.yml up`
- 使用 MongoDB：`docker-compose -f src/main/docker/mongodb.yml up`
- 使用 Cassandra：`docker-compose -f src/main/docker/cassandra.yml up`
- 使用 Couchbase：`docker-compose -f src/main/docker/couchbase.yml up`
- 使用 Neo4j：`docker-compose -f src/main/docker/neo4j.yml up`

### MongoDB 集群模式

如果您想使用具有副本集或分片以及它们之间共享配置的 MongoDB，您需要手动构建和设置 MongoDB 镜像。
请按照以下步骤操作：

- 构建镜像：`docker-compose -f src/main/docker/mongodb-cluster.yml build`
- 运行数据库：`docker-compose -f src/main/docker/mongodb-cluster.yml up -d`
- 扩展 MongoDB 节点服务（您必须选择奇数个节点）：`docker-compose -f src/main/docker/mongodb-cluster.yml scale <name_of_your_app>-mongodb-node=<X>`
- 为 mongo 配置服务器初始化副本：`docker exec -it <name_of_your_app>-mongodb-config mongo  --port 27019 --eval 'rs.initiate();'`
- 初始化副本集（参数 X 是您在上一步中输入的节点数，文件夹是 YML 文件所在的文件夹，默认是 `docker`）：`docker container exec -it <yml_folder_name>_<name_of_your_app>-mongodb-node_1 mongo --port 27018 --eval 'var param=<X>, folder="<yml_folder_name>"' init_replicaset.js`
- 初始化分片：`docker container exec -it <yml_folder_name>_<name_of_your_app>-mongodb_1 mongo --eval 'sh.addShard("rs1/<yml_folder_name>_<name_of_your_app>-mongodb-node_1:27018")'`
- 构建您应用程序的 Docker 镜像：`./mvnw -Pprod clean verify jib:dockerBuild` 或 `./gradlew -Pprod clean bootJar jibDockerBuild`
- 启动您的应用程序：`docker-compose -f src/main/docker/app.yml up -d <name_of_your_app>-app`

如果您想添加或删除一些 MongoDB 节点，请重复步骤 3 和 4。

### Couchbase 集群模式

如果您想使用具有多个节点的 Couchbase，您需要手动构建和设置 Couchbase 镜像。
请按照以下步骤操作：

- 构建镜像：`docker-compose -f src/main/docker/couchbase-cluster.yml build`
- 运行数据库：`docker-compose -f src/main/docker/couchbase-cluster.yml up -d`
- 扩展 Couchbase 节点服务（您必须选择奇数个节点）：`docker-compose -f src/main/docker/couchbase-cluster.yml scale <name_of_your_app>-couchbase-node=<X>`
- 构建您应用程序的 Docker 镜像：`./mvnw -Pprod clean verify jib:dockerBuild` 或 `./gradlew -Pprod clean bootJar jibDockerBuild`
- 启动您的应用程序：`docker-compose -f src/main/docker/app.yml up -d <name_of_your_app>-app`

### Cassandra

与其他数据库不同（模式迁移由应用程序本身应用），Cassandra 模式迁移由专用的 Docker 容器应用。

#### 开发中的 Cassandra

要启动 Cassandra 集群以在本地运行您的应用程序，您可以使用用于开发的 docker_compose 文件：
`docker-compose -f src/main/docker/cassandra.yml up -d`

Docker-compose 将启动 2 个服务：

- `<name_of_your_app>-cassandra`：一个包含 Cassandra 节点联系点的容器
- `<name_of_your_app>-cassandra-migration`：一个自动应用所有 CQL 迁移脚本的容器（创建 Keyspace、创建表、所有数据迁移...）

有关如何在不重启本地集群的情况下添加新 CQL 脚本的更多信息，请参阅 [Cassandra 页面](/using-cassandra/)。

#### 生产中的 Cassandra：

`app.yml` docker-compose 文件使用 `cassandra-cluster.yml` 来配置集群。
应用程序在几秒后启动（参见 _JHIPSTER_SLEEP_ 变量），给集群启动和迁移应用的时间。

Cassandra 与其他数据库的一个大区别是，您可以使用 Docker Compose 扩展您的集群。要在您的集群中拥有 X+1 个节点，请运行：

- `docker-compose -f src/main/docker/cassandra-cluster.yml scale <name_of_your_app>-cassandra-node=X`

### Microsoft SQL Server

如果您想将 MSSQL Docker 镜像与 JHipster 一起使用，需要按照以下几个步骤：

- 将 Docker 可用的 RAM 增加到至少 3.25GB
- 运行数据库：`docker-compose -f src/main/docker/mssql.yml up -d`
- 使用您选择的 MSSQL 客户端创建数据库
- 启动您的应用程序：`docker-compose -f src/main/docker/app.yml up -d <name_of_your_app>-app`


## Elasticsearch

运行 `docker-compose -f src/main/docker/app.yml up` 已经自动启动您的搜索引擎。

如果您只想启动 Elasticsearch 节点，而不想启动其他服务，请使用其特定的 Docker Compose 配置：

- `docker-compose -f src/main/docker/elasticsearch.yml up`


## Sonar

生成了用于运行 Sonar 的 Docker Compose 配置：

- `docker-compose -f src/main/docker/sonar.yml up`

要分析您的代码，请在您的项目上运行 Sonar：

- 使用 Maven：`./mvnw initialize sonar:sonar`
- 使用 Gradle：`./gradlew sonar`

Sonar 报告将在以下位置可用：[http://localhost:9000](http://localhost:9000)


## Keycloak

如果您选择 OAuth 2.0 作为您的身份验证，Keycloak 被用作默认的身份提供者。运行 `docker-compose -f src/main/docker/app.yml up` 将自动启动 Keycloak。

要使 Keycloak 工作，您需要在您的 hosts 文件中添加以下行（Mac/Linux 上的 `/etc/hosts`，Windows 上的 `c:\Windows\System32\Drivers\etc\hosts`）。

```
127.0.0.1	keycloak
```

这是因为您将在您的机器上使用浏览器访问您的应用程序（名称是 localhost 或 `127.0.0.1`），但在 Docker 内部，它将在自己的容器中运行，名称是 `keycloak`。

如果您只想启动 Keycloak，而不想启动其他服务，请使用其特定的 Docker Compose 配置：

- `docker-compose -f src/main/docker/keycloak.yml up`

### 扩展容器

运行 `docker-compose scale test-app=4` 来运行 4 个“test”应用程序实例。

### 停止容器

`docker-compose -f src/main/docker/app.yml stop`

您也可以直接使用 Docker：

`docker container stop <container_id>`

当您停止容器时，数据不会被删除，除非您删除容器。

### 删除容器

请小心！所有数据都将被删除：

`docker container rm <container_id>`


<h2 id="memory-tweaking">内存调优</h2>

为了优化在容器中运行的应用程序的内存使用，您可以在 `Dockerfile` 或 `docker-compose.yml` 上设置 Java 内存参数。

### 向 Dockerfile 添加内存参数

设置环境变量。

ENV JAVA_OPTS=-Xmx512m -Xms256m

### 向 docker-compose.yml 添加内存参数

这个解决方案比 Dockerfile 更受青睐。这样，您就可以在组成应用程序的所有容器上的单个控制点上配置内存。

在 `environment` 部分中添加 `JAVA_OPTS`。

```yaml
environment:
  - (...)
  - JAVA_OPTS=-Xmx512m -Xms256m
```

根据 Docker 基础镜像，`JAVA_OPTS` 可能不会工作。在这种情况下，请尝试使用 `_JAVA_OPTIONS`：

```yaml
environment:
  - (...)
  - _JAVA_OPTIONS=-Xmx512m -Xms256m
```

## 禁用

根据您的应用程序配置添加到 src/main/resources/application.yml 或 application-dev.yml。

```yaml
spring:
  docker:
    compose:
      enabled: false
```
