JHipster-UML 是 JHipster 的一个子项目，可以用作使用[实体子生成器](/creating-an-entity)的替代品。这个想法是，使用可视化工具[管理关系](/managing-relationships)比使用传统的 Yeoman 问答方式要容易得多。

JHipster-UML 项目[在 GitHub 上可用](https://github.com/jhipster/jhipster-uml/)，它是一个像 JHipster 一样的开源项目（Apache 2.0 许可证）。如果您喜欢这个项目，别忘了在 GitHub 上给我们一个星号！


## 介绍

JHipster-UML 是通常 Q&A 的替代品，因为它为您提供了使用 UML 编辑器创建图表的可能性，该图表将由 JHipster-UML 解析。

以下是我们支持的编辑器列表：

- [Modelio](https://www.modeliosoft.com/);
- [UML Designer](http://www.umldesigner.org/);
- [GenMyModel](https://www.genmymodel.com/)（不免费，但在线）。

## 安装

要安装 JHipster UML，使用以下命令：

```shell
npm install -g jhipster-uml
```

但是，如果您不想全局安装最新版本，因为它与您的生成器版本不匹配（见下文），或者您希望将其限制在本地，请改用以下命令：

```shell
npm install jhipster-uml --save-dev
```

如果您想要"最前沿"（几乎完全安全使用）的版本，可以从[我们的 GitHub 项目](https://github.com/jhipster/jhipster-uml)克隆我们的 git 仓库：

HTTPS 方式：`git clone https://github.com/jhipster/jhipster-uml.git`

SSH 方式：`git clone git@github.com:jhipster/jhipster-uml.git`

JHipster UML 是一个_可以_与 JHipster 生成器一起使用的工具。如果您使用 v3.0.0 之前的生成器，则必须使用 JHipster UML v1.6.5（最新补丁版本）。否则，对于 v3.0.0+ 的生成器，应选择使用 v2.0.0+。


## 如何使用

要使用 JHipster-UML，您需要一个导出为 XMI 格式的类图，JHipster-UML 将解析它以创建您的实体。


## UML 文件

类图应该对您的 JHipster 应用程序域的实体进行建模，因此您有一些限制，必须遵循该方法论。

### 实体

每个实体由一个类表示，其字段是类的属性。属性必须具有 JHipster 支持的类型，否则将无法工作。要使用 JHipster 支持的类型（如 "BigDecimal"、"LocalDate" 等），您可以为其创建 _PrimitiveType_ 或 _DataType_。
您可以在[这里](#annexes)查看 JHipster 支持的所有类型以及每种类型可以使用的验证的表格。

![Book Entity](/images/jhipsteruml_book_datatype.png)

这是一个为 JHipster 正确创建的类的示例。我们将属性 _publicationDate_ 和 price 设置为我们创建的 _DataType_ 类型 _BigDecimal_ 和 _LocalDate_。

注意，您不需要将类型名称大写（**除了像 BigDecimal 这样的复合名称**，JHipster-UML 会将名称大写）。

### 关系

我们使用 JHipster 的示例来展示如何使用编辑器执行此操作。
请注意，我们**仅**支持[管理关系](/managing-relationships/)页面中列出的关系。

![One-to-One](/images/jhipsteruml_bi_oto.png)

这里，我们在 Driver 和 Car 之间有一个双向一对一关系，Driver 是关系的所有者。

如果您正在寻找单向关系：

![One-to-One2](/images/jhipsteruml_uni_oto.png)

注意，为了实现单向关系，我们删除了 `citizen` 标签，这样 `Passport` 就没有它了。

#### 一对多

![One-to-Many](/images/jhipsteruml_bi_otm.png)

在这个双向关系中，一个 Owner 可以拥有多辆汽车，而一辆 Car 只能有一个所有者。

JHipster（尚）不支持一对多关系的单向关系（有关此内容的更多信息，请参阅[此](/managing-relationships/#a-unidirectional-one-to-many-relationship)页面）。
这是此类关联的示例：

![One-to-Many2](/images/jhipsteruml_uni_otm.png)

#### 多对一

如前所述，一对多关系的等价物是多对一：

![One-to-Many2](/images/jhipsteruml_uni_mto.png)

现在汽车知道它们的所有者，但反之则不然。

#### 多对多

![Many-to-Many](/images/jhipsteruml_bi_mtm.png)

这里，我们在 Car（所有者）和 Driver 之间有一个多对多关系。

#### 声明您想要在 Angular 中用于显示关系的字段

为此，您必须在注入字段名称后的 `(``)` 之间添加字段名称。

在一对多关系中，您可以在关系的"多"端添加它：

- UML
  ![otherEntityField One-to-Many](/images/jhipsteruml_otherEntityFieldOM.jpeg)

- JDL
  ```jdl
  relationship OneToMany {
    One{many} to Many{one(<otherEntityField>)}
  }
  ```

在多对多关系中，您可以在实体的所有者端添加它：

- UML
  ![otherEntityField Many-to-Many](/images/jhipsteruml_otherEntityFieldMM.jpeg)

- JDL
  ```jdl
  relationship ManyToMany {
    Owner{notOwner(<otherEntityField>)} to NotOwner{owner}
  }
  ```

#### 自反性情况

![Reflexivity](/images/jhipsteruml_reflexivity.png)

如您所见，自反性有 3 种类型。JHipster-UML 仅支持前两种（一对一和一对多）。**不**支持多对多的情况，因为：

- 它可能导致过于复杂和错误的模型；
- JHipster 不支持它（这是件好事）。

## 使用 JHipster-UML

一旦您设置好 JHipster 应用程序并在 UML 编辑器中创建了类图，请按照以下步骤操作：

- 步骤 1 - 将您的类图导出为 XMI 文件格式
- 步骤 2 - 在您的 JHipster 应用程序根文件夹中，运行命令

`jhipster-uml <your_file.xmi>`

请注意，您不需要提供数据库类型（sql、mongodb 或 cassandra），因为 JHipster-UML 会为您检测类型（从 _.yo-rc.json_ 文件中）。

但是，如果您希望在 JHipster 应用程序之外运行 JHipster-UML，则需要传递一个额外的参数：数据库类型名称。
以下是要运行的命令：

`jhipster-uml <your_file.xmi> [--db (sql | mongodb | cassandra)]`

也可以生成 JHipster DTO，传递 `--dto` 参数以启用此功能。

`jhipster-uml <your_file.xmi> [--db (sql | mongodb | cassandra)] [--dto]`

您可以使用 `--paginate` 为您的实体选择分页。

`jhipster-uml <your_file.xmi> [--db (sql | mongodb | cassandra)] [--paginate]`

最后，您可以使用 `--service` 为您的实体选择服务。

`jhipster-uml <your_file.xmi> [--db (sql | mongodb | cassandra)] [--service]`

**请注意，使用 `paginate` 选项但不选择任何实体来生成分页会取消您使用此选项的选择。**

最后，如果您需要帮助，也有一个命令：

`jhipster-uml --help`

* 步骤 3 - 就是这样！

**注意：如果您想使用可用的类和方法，JHipster-UML 的首选入口点是 ParserFactory（这样您就不必打开文件、读取它、查找根元素等）。**


## JHipster-UML 文件

JHipster-UML 可以通过命令行和/或基于 JSON 的配置文件 `jumlfile` 进行配置。
帮助中描述的选项可以在两者中使用，但命令行优先于 `jumlfile`。

### 具体示例

jumlfile 内容：

```json
{
  "db": "sql",
  "force": "true"
}
```

调用：

```shell
jhipster-uml --no-force
```

您将拥有以下选项：

- db: sql
- force: false（不强制）


## 生成的内容

执行 JHipster-UML 后，将创建 _.jhipster_ 文件夹（如果之前不存在），并以 JSON 格式填充 XMI 文件中存在的实体。

请注意，至少有一个实体可能不会生成：User 实体。它实际上是在创建新应用程序时由 JHipster 脚手架生成的（JHipster-UML 会显示警告消息）。

接下来，这很简单：运行您的应用程序！


## JHipster 注意事项

JHipster 是一个出色的脚手架工具，具有许多约定，在使用 JHipster-UML 生成实体时，其中一些值得一提：

- 您不必在实体中使用 `id` 字段，因为 JHipster 默认生成一个，如果检测到字段为 ID，JHipster-UML 会删除任何字段；
- 您不必在关系中使用复数形式，JHipster 会在需要时添加 `s`。例如，如果实体 A 和实体 B 之间存在多对多关系，则不必将关系的末端命名为 `as` 或 `bs`，因为 JHipster 会为您执行此操作。


## 保留字

JHipster 维护一个禁用（*在某些条件下*）词汇列表。
例如，如果您想为应用程序生成实体，并且此应用程序使用 Cassandra，则不能在字段名称或表名称中使用 `BATCH` 一词。

从 v2.0.0 开始，JHipster UML 会检测此类词汇，如果遇到此类情况，会立即抛出异常。但是，JHipster UML 无法以 100% 的准确性断言何时可以或不能使用保留字。这就是为什么当可能存在使用此类关键字的风险时，它会向用户发出黄色消息警告。

## Modelio

**Mac 用户注意事项：Modelio 在 Mac 上的行为很奇怪（GUI），这可能是由 Mac 上的图形和窗口管理器引起的，因为在 Linux Ubuntu 上没有被诊断出来。它可以工作，但交互可能不太愉快。**

**重要版本注意事项：**

- Modelio v3.3 已测试并可以工作，但是 v3.4 中存在一个错误，阻止用户导出图表。此错误已在 v3.4.1 中修复。
- Modelio v3.5.X 在处理双向多对多关系时引入了一个错误（当 JHipster UML 解析 XMI 时，错误是 `Cannot read property '0' of undefined`）。此问题似乎已在更高版本（v3.6.X）中修复。

Modelio 可以在[此处](https://www.modelio.org/)免费下载。如果您下载任何 3.3+ 版本，请确保您拥有 Java 8（否则将无法工作）。

示例文件在[此处](https://github.com/jhipster/jhipster-uml/blob/master/test/xmi/modelio.xmi)。

启动后，创建一个项目，您将看到此视图：

![Empty Modelio project](/images/jhipsteruml_modelio_1.png)

注意左侧面板标题为"类模型"。您只需要"类"、"属性"、"聚合"、"组合"和"数据类型"对象。
您已经可以猜到为什么需要前 2 个。"聚合"对象用于定义聚合：
B 聚合到 A 意味着 A 有 0、1 或更多 (n) 个 B 的实例。A 不创建（和销毁）B 实例。
组合意味着如果 A 由 B 组成（0、1 或 n 个实例），那么它会创建、管理和销毁 B 实例。

您可以使用其中任何一个，解析器无论如何都只会将两者视为关联。

在这两种情况下，基数和关联名称都很重要。

最后，"数据类型"对象使您能够创建自定义类型（Modelio 未提供的类型），如 `BigDecimal` 或 `LocalDate`。

在此示例中，我们将解释如何连接两个类：

![Modelio composition example](/images/jhipsteruml_modelio_2.png)

如您所见，员工有一份工作（但也可以根本没有工作）。解析器会注意到一些事情：

- 两个类（Employee 和 Job）；
- 两个字段（email 和 title）、它们的类型、它们所属的类（每个类包含其字段）。它们的可见性不被考虑；
- 连接它们的关联以及关联的**方向**（这很重要！）
- 基数（1 和 0..1）意味着员工可以有一份工作（0 或 1），并且工作不会由两个员工共享（为了此示例，只有一个）；
- 有一个**注入字段**：job，在 employee 中。

此关联称为一对一。返回几节以查看其他类型的关联。

Modelio 支持约束。双击字段，转到"注释和约束"选项卡，第一个图标应该是"添加约束"，然后选择"约束"，双击约束，并为其命名（它应该是 JHipster 约束之一）。对于约束值，在"主体"字段中输入它。

最后，一旦您的图表完成，您必须将其导出。

![Export to XMI Modelio](/images/jhipsteruml_modelio_3.png)

检查模型透视图，一旦您找到您的项目，下降一级并右键单击最后一个元素（您的小写项目名称），XMI，导出 XMI。将弹出一个窗口，选择输出路径，将兼容性更改为 OMG UML2.4.1，将扩展名保留为 XMI，您就可以开始了。

GenMyModel 是一个浏览器内 UML 编辑器，可以在[此处](https://dashboard.genmymodel.com/)找到。您可以免费使用它，但有限制，我们希望此编辑器能够使用户在不下载应用程序的限制下使用 JHipster-UML 进行操作。

![GenMyModel diagram](/images/jhipsteruml_genmymodel_relation.png)

- 两个类，"Author"和"Book"。
- 两个 DataTypes，"LocalDate"和"BigDecimal"。

JHipster 和 JHipster UML 都支持枚举。

以下是定义它们的方法：

- 对于 Modelio，拖放 `Enumeration` 对象并将其放置在某处。最后，将 `Enumeration Literal` 对象添加到枚举中以添加它；
- 对于 UML Designer，有可以放置和使用的 `Enumeration` 对象。但是，字面量不称为 `Enumeration Literal`，而只是 `Literal`；

## 解析器修改

1.0.0 版本带来了一个新的解析器系统，使任何更改（解析器创建、更新、删除）都变得轻松，前提是可以解析 XMI。

### 添加解析器

#### 解析器实现

如果您是 Java 开发人员，您可能对 OOP 原则非常熟悉（无论如何我们希望如此）。在开发 JHipster-UML 时，我们像在 Java 中_通常_做的那样考虑其架构。

您必须"扩展"我们的抽象解析器（[AbstractParser](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/abstract_parser.js)），或实现我们的接口（[Parser](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/parser.js)）以添加您的解析器的具体实现。

您应该注意到 Parser 接口的某些方法会抛出 _UnimplementedOperationException_。这个想法来自 Java，您可以在具体解析器中实现此方法。

有些方法不抛出任何异常，但只调用其他方法。如果您熟悉 Java 8，我们复制了其出色的默认方法，并做了同样的事情（这样您就不必手动实现它们）。

与 Java 一样，您可以覆盖任何您想要的方法，并创建自己的方法。您不受限制（除非您想重载）。

AbstractParser 类提供了一些字段、默认构造函数和一些方法，这样您就不必稍后创建或实现它们。

您_应该_实现这些方法中的每一个（或覆盖 [#parse](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/parser.js#L13) 或 [#findElements](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/parser.js#L25) 方法）。

getter 不是强制性的，但可以作为获取某些重要字段的方法，并在发送这些字段之前提供修改它们的方法。

#### 编辑器检测

当您完成创建闪亮的新解析器后，您应该将其添加到可用编辑器的"列表"中：

- 首先像[此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editors.js#L3)一样引入它；
- 像[此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editors.js#L9)一样使其可用；
- 像[此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editors.js#L16)一样将其添加到列表中。

但是，必须遵守一些准则：

- 您的解析器名称必须是 \<editor_parser\>；
- 编辑器的 JS 文件不得大写，且不得包含任何空格（Modelio -> `modelio_parser.js`，UML Designer -> `umldesigner_parser.js`）；
- 编辑器的类名必须大写（Modelio -> `ModelioParser`，UML Designer -> `UMLDesignerParser`）。

关于 EditorDetector，它可以检测创建您的 XMI 文件的编辑器。为此，您必须首先找到 XMI 文件中提到编辑器的位置，然后添加像[此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editor_detector.js#L23)一样返回您的编辑器的代码。如果无法检测到您的编辑器，请在[此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editors.js#L23)添加它，并像为 UML Designer [此处](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editor_detector.js#L56)所做的那样指示其名称。

#### 测试

最后，在提交您的超级解析器之前，您需要做的下一件事是测试它。
因为我们相信测试，但真正喜欢良好的测试（使用 BDD），所以我们的测试是用 Mocha 和 chai 完成的。如果您还不知道它是关于什么的，我们建议您访问 [ChaiJS](http://chaijs.com/) 页面，并查看我们的[一个](https://github.com/jhipster/jhipster-uml/blob/master/test/editors/modelio_parser_test.js)测试文件以熟悉它。

您可能想知道应该使用哪种形式的测试。答案是：由您决定！无论是 [should](http://chaijs.com/guide/styles/#should) 还是 [expect](http://chaijs.com/guide/styles/#expect)（类似 RSpec），我们在这里不强制执行任何规则。但是，我们建议使用 Expect，因为我们这样做，它应该使测试更容易理解。

我们只是希望您测试所有"值得测试"的东西：

- 接口的方法（_公共_方法，而不是接口类！）；
- 您不必测试其他方法（_私有_方法，因为它们应该是安全的，并且在短期/长期内不断变化），但由于可见性未在 JS 中实现（据我们所知），您可能想测试它们（由您决定）。

名称和文件的一般准则：

- 您的测试文件名应遵守前面提到的相同规则。例如，如果您的解析器名称是"Modelio"，那么您的测试文件应该是 `modelio_parser_test.js`。
- 用于测试的 XMI 文件也是如此。如果您的解析器名称是 UMLDesigner，那么您的测试 XMI 文件名之一可以是 `umldesigner_parser_problem_test.[...]`（文件扩展名不是静态的）。

### 修改解析器

更改解析器（然后提交更改）非常简单：进行更改并测试它（如果需要，创建测试）。

如果您需要测试通过（抛出异常或不抛出等），您可以制作一个 XMI 文件。

如果您更改任何名称，请不要忘记修改[编辑器检测器](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editor_detector.js)。

### 删除解析器

首先，从编辑器（`editors/editors.js`）中删除它，然后从 EditorDetector（`editors/editor_detector.js`）中删除它。最后，删除解析器文件和为其创建的测试。

如果您删除任何解析器，请不要忘记修改[编辑器检测器](https://github.com/jhipster/jhipster-uml/blob/master/lib/editors/editor_detector.js#L38)。
