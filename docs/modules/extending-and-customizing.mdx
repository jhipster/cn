JHipster 支持`插件`，我们称之为`蓝图`和`模块`。

在 JHipster v7.9.0 之前，`模块`是使用 `yo` 执行的 Yeoman 生成器，扩展了 `generators-jhipster` 的 `generator-base` 类，并注册钩子来集成到 JHipster 的工作流程中。

从 JHipster v7.9.0 开始，`模块`是带有独立生成器（非蓝图化）和自定义 CLI 的`蓝图`。
从现在开始，我们将称它们为独立蓝图（或简称为蓝图）。


## JHipster 蓝图的基本规则

JHipster 蓝图：

- 是 NPM 包和 Yeoman 生成器。
- 遵循 [https://yeoman.io/authoring/index.html](https://yeoman.io/authoring/index.html) 中列出的 Yeoman 规则的扩展。不是以 `generator-` 为前缀，而是以 `generator-jhipster-` 为前缀，并且不只有 `yeoman-generator` 关键字，必须有 2 个关键字：`yeoman-generator` 和 `jhipster-blueprint`。


## 使用方法

要使用蓝图，请运行以下命令

```shell
jhipster --blueprints <blueprint name>
```

或使用提供的自定义 CLI：

```shell
jhipster-my-blueprint
```


## 示例

JHipster 有许多官方蓝图，一些示例：

- 后端
  - [JHipster Kotlin](https://github.com/jhipster/jhipster-kotlin) 蓝图将大部分服务器端 Java 代码替换为等效的 Kotlin 代码。
  - [JHipster.NET](https://github.com/jhipster/jhipster-dotnetcore) 蓝图用 .NET 实现替换整个服务器端。
  - [JHipster NodeJS](https://github.com/jhipster/generator-jhipster-nodejs) 蓝图用 NestJS 实现替换整个服务器端。
- 后端定制
  - [JHipster Native](https://github.com/jhipster/generator-jhipster-native) 蓝图通过 Spring Native 兼容性定制 JHipster 应用程序。
- 前端
  - [Svelte Hipster](https://github.com/jhipster/generator-jhipster-svelte) 蓝图用 Svelte 实现替换整个客户端。
- 移动端
  - [JHipster Ionic](https://github.com/jhipster/generator-jhipster-ionic) 蓝图生成一个 Ionic 应用程序。


## 并排蓝图

每个生成器都可以是并排（SBS）蓝图。SBS 蓝图不会改变原始生成器的行为，但可以自定义行为和结果。
SBS 蓝图使支持多个 JHipster 版本和移植到新的 JHipster 版本变得更容易。

要使生成器并排，请将以下内容添加到构造函数中：

```js
this.sbsBlueprint = true;
```

示例：[Native Blueprint 的服务器生成器](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L17)。
在该示例中，生成器[自定义 package.json](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L26-L35)、[删除文件](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L37-L40)、[自定义 pom.xml](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L42-L186)、[自定义 Java 文件](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L211-L307)、[自定义 Cypress](https://github.com/jhipster/generator-jhipster-native/blob/bb9c042f6bc70a26ba8037e951c93dc1d1820983/generators/server/generator.mjs#L321-L329) 等等。

并排蓝图可用于创建钩子并帮助迁移现有模块。这在[创建模块](/modules/creating-a-module)中有详细介绍。


## 自定义 CLI

独立蓝图可以使用 `yo` 执行，但 `yo` 在生成器发现方面很激进——这可能很慢——并且缺少一些改进。JHipster CLI 提供帮助和 JHipster 集成。
因此，我们建议使用 `jhipster` CLI 或基于 `generator-jhipster` 创建自定义 CLI。

`jhipster` 命令执行您全局安装的 `generator-jhipster` 版本。自定义 CLI 将执行依赖的 `generator-jhipster` 并确保使用支持的 `generator-jhipster` 版本。

自定义 CLI 允许您执行自定义生成器，这在[创建模块](/modules/creating-a-module)中有详细介绍。


## 本地蓝图

当自定义是由 jhipster 生成时，应用程序可以更容易地保持更新。本地蓝图就是为此目的而实现的。

整个蓝图在应用程序的 `.blueprint` 目录内实现。

一些好处：
- 在重新生成和升级时避免或减少冲突。
- 允许批量编辑实体文件。
- 不需要发布到 npm 仓库。
- 完全控制 jhipster 工作流程。
- 使用单个命令轻松生成。

## 应用程序配置：

JHipster 的配置遵循 [Yeoman 配置](https://yeoman.io/authoring/storage.html)模式，并为蓝图配置提供额外支持。

`config` 和 `jhipsterConfig` 属性存储通用配置并写入 `.yo-rc.json` 文件中的 `generator-jhipster` 键。
`blueprintStorage` 和 `blueprintConfig` 属性存储蓝图特定的配置并写入 `.yo-rc.json` 文件中的 `generator-jhipster-(my-blueprint)` 键。

`config` 和 `blueprintStorage` 是[存储实例](https://yeoman.github.io/generator/Storage.html)，
而 `jhipsterConfig` 和 `blueprintConfig` 是 `config` 和 `blueprintStorage` 存储的[代理对象](https://yeoman.github.io/generator/Storage.html#createProxy)，以便于使用。

## 在本地运行蓝图进行开发

在开发蓝图时，请注意以下步骤。它们非常重要。

1. 全局链接您的蓝图

注意：如果您不想将蓝图（步骤 3）链接到正在创建的每个项目。

```shell
cd generator-jhipster-my-blueprint
npm link
```

2. 将 JHipster 的开发版本链接到您的蓝图。注意：仅当您想使用未发布的 JHipster 版本（如 `main` 分支或您自己的自定义分支）时才需要

```shell
cd generator-jhipster
npm link

cd generator-jhipster-my-blueprint
npm link generator-jhipster
```

或从 git 安装 `generator-jhipster`：

```shell
cd generator-jhipster-my-blueprint
npm install jhipster/generator-jhipster
```

3. 为要生成的应用程序创建一个新文件夹，并运行 JHipster 忽略 JHipster 依赖项（否则每次调用 `npm install/ci` 时都会安装发布版本）

```shell
mkdir my-app && cd my-app

jhipster --blueprints my-blueprint --skip-jhipster-dependencies
```

4. 一旦蓝图/generator-jhipster 发布，重新添加 JHipster 依赖项以确保可重现性

```shell
jhipster --no-skip-jhipster-dependencies
```


## 将蓝图注册到 JHipster 市场

要使您的蓝图在 [JHipster 市场](/modules/marketplace)中可用，您需要确保在已发布的 npm `package.json` 中有两个关键字：`yeoman-generator` 和 `jhipster-blueprint`。
如果您在市场中发现任何不是 JHipster 模块或蓝图的条目，您可以通过将其添加到 [`modules-config.json 文件`](https://github.com/jhipster/jhipster.github.io/blob/main/modules/marketplace/data/modules-config.json) 的 `blacklistedModules` 部分来帮助将其列入拒绝名单，方法是向 [jhipster/jhipster.github.io 项目](https://github.com/jhipster/jhipster.github.io)提交 Pull Request。

一旦您将蓝图发布到 NPM，您的蓝图就会在我们的市场中可用。
