## 工具

Angular 使用 TypeScript 而不是 JavaScript，因此需要一些特定的工具来高效地工作。我们针对 Angular 2+ 应用程序的[开发](/development)工作流程如下。

1. 当您生成一个应用程序时，文件被创建，在生成结束时触发 `npm install` 任务。
2. 一旦 `npm install` 完成，它会调用 `package.json` 中的 `postInstall` 脚本，这一步触发 `webapp:build` 任务。
3. 现在您应该有所有生成的文件并编译到基于构建工具（Maven 或 Gradle）选择的 `target` 或 `build` 文件夹内的 `www` 文件夹中。
4. 现在运行 `./mvnw` 或 `./gradlew` 来启动应用程序服务器，它应该在 [localhost:8080](localhost:8080) 可用，这也会提供从上述步骤编译的客户端代码。
5. 现在在新终端中运行 `npm start` 来启动带有 BrowserSync 的 Webpack dev-server。这将负责编译您的 TypeScript 代码，并自动重新加载您的浏览器。

如果您在没有运行 `npm start` 的情况下开始对客户端代码进行更改，将不会反映任何内容，因为更改没有被编译，所以您需要在更改后手动运行 `npm run webapp:build` 或者运行 `npm start`。

您也可以在启动时通过传递 `webapp` 配置文件强制 Maven 运行 `webapp:dev` 任务，如 `./mvnw -Pdev,webapp`。

**注意** Gradle 在 `dev` 配置文件中如果前端有更改会自动运行 webpack 编译（仅在启动时，对于实时重新加载请使用 `npm start`）。

其他可用的 npm 命令可以在您项目的 `package.json` 文件的 `scripts` 部分中找到。

- 要在浏览器中处理您的代码，我们建议使用 [Angular DevTools](https://angular.io/guide/devtools)。Angular DevTools 是一个浏览器扩展，为 Angular 应用程序提供调试和性能分析功能（**注意** Angular DevTools 支持 Angular v12 及更高版本）。


## 项目结构

JHipster 客户端代码位于 `src/main/webapp` 目录下，并且密切遵循 [Angular 风格指南](https://angular.io/guide/styleguide)。如果您对我们的应用程序结构、文件名、TypeScript 约定等有任何问题，请先阅读这个指南...

这个风格指南得到了 Angular 团队的认可，并提供了每个 Angular 项目都应该遵循的最佳实践。

对于 Angular 路由，我们遵循破折号命名约定，以便 URL 清晰一致。
当您生成一个实体时，路由名称、路由 URL 和 REST API 端点 URL 都是按照这个约定生成的，并且在需要的地方，实体名称会自动复数化。

以下是主要的项目结构：

```
webapp
├── app                               - Your application
│   ├── account                       - User account management UI
│   ├── admin                         - Administration UI
│   ├── config                        - Some utilities files
│   ├── core                          - Common building blocks like configuration and interceptors
│   ├── entities                      - Generated entities (more information below)
│   ├── home                          - Home page
│   ├── layouts                       - Common page layouts like navigation bar and error pages
│       ├── main                      - Main page
│           ├── main.component.ts     - Main application class
│   ├── login                         - Login page
│   ├── shared                        - Common services like authentication and internationalization
│   ├── app.module.ts                 - Application modules configuration
│   ├── app-routing.module.ts         - Main application router
├── content                           - Static content
│   ├── css                           - CSS stylesheets
│   ├── images                        - Images
│   ├── scss                          - Sass style sheet files will be here if you choose the option
├── i18n                              - Translation files
├── swagger-ui                        - Swagger UI front-end
├── 404.html                          - 404 page
├── favicon.ico                       - Fav icon
├── index.html                        - Index page
├── robots.txt                        - Configuration for bots and Web crawlers
```

使用[实体子生成器](/creating-an-entity/)创建一个名为 `Foo` 的新实体，会在 `src/main/webapp` 下生成以下前端文件：

```
webapp
├── app
│   ├── entities
│       ├── foo                                    - CRUD front-end for the Foo entity
│           ├── foo.component.html                 - HTML view for the list page
│           ├── foo.component.ts                   - Controller for the list page
│           ├── foo.model.ts                       - Model representing the Foo entity
│           ├── foo.module.ts                      - Angular module for the Foo entity
│           ├── foo.route.ts                       - Angular Router configuration
│           ├── foo.service.ts                     - Service which access the Foo REST resource
│           ├── foo-delete-dialog.component.html   - HTML view for deleting a Foo
│           ├── foo-delete-dialog.component.ts     - Controller for deleting a Foo
│           ├── foo-detail.component.html          - HTML view for displaying a Foo
│           ├── foo-detail.component.ts            - Controller or displaying a Foo
│           ├── foo-dialog.component.html          - HTML view for editing a Foo
│           ├── foo-dialog.component.ts            - Controller for editing a Foo
│           ├── foo-popup.service.ts               - Service for handling the create/update dialog pop-up
│           ├── index.ts                           - Barrel for exporting everything
├── i18n                                           - Translation files
│   ├── en                                         - English translations
│   │   ├── foo.json                               - English translation of Foo name, fields, ...
│   ├── fr                                         - French translations
│   │   ├── foo.json                               - French translation of Foo name, fields, ...
```

请注意，默认语言翻译将基于您在应用程序生成期间选择的语言。这里显示 'en' 和 'fr' 仅作为演示。


## 授权

JHipster 使用 [Angular 路由器](https://angular.io/docs/ts/latest/guide/router.html) 来组织客户端应用程序的不同部分。

对于每个状态，所需的权限在状态的数据中列出，当权限列表为空时，意味着该状态可以匿名访问。

权限也在服务器端的 `AuthoritiesConstants.java` 类中定义，逻辑上客户端和服务器端的权限应该相同。

在下面的示例中，'settings' 状态被设计为只能由具有 `ROLE_ADMIN` 权限的认证用户访问：

```ts
export const settingsRoute: Route = {
    path: 'sessions',
    component: SettingsComponent,
    title: 'global.menu.account.settings',
    data: {
        authorities: ['ROLE_ADMIN'],
    },
    canActivate: [UserRouteAccessService]
};
```

一旦在路由器中定义了这些权限，它们就可以通过 `jhiHasAnyAuthority` 指令使用，该指令根据参数类型有 2 个变体：

- 对于单个字符串，该指令只有在用户具有所需权限时才显示 HTML 组件
- 对于字符串数组，该指令在用户具有列出的权限中的任一个时显示 HTML 组件

例如，以下文本只会对具有 `ROLE_ADMIN` 权限的用户显示：

```html
<h1 *jhiHasAnyAuthority="'ROLE_ADMIN'">Hello, admin user</h1>
```

例如，以下文本只会对具有 `ROLE_ADMIN` 或 `ROLE_USER` 权限中的任一个的用户显示：

```html
<h1 *jhiHasAnyAuthority="['ROLE_ADMIN', 'ROLE_USER']">Hello, dear user</h1>
```

*请注意*，这些指令只在客户端显示或隐藏 HTML 组件，您还需要在服务器端保护您的代码！


## ng-jhipster 库

ng-jhipster 库是免费的开源软件，可以在 [https://github.com/jhipster/ng-jhipster](https://github.com/jhipster/ng-jhipster) 上获得。

ng-jhipster 库包含 Angular 2+ 应用程序使用的实用函数和通用组件。它们包括：

- 验证指令
- 国际化组件
- 常用的管道，如大写、排序和单词截断
- Base64、日期和分页处理服务
- 一个通知系统（请参见下面）

### 通知系统

JHipster 使用自定义通知系统将事件从服务器端发送到客户端，并具有支持 i18n 的 `JhiAlertComponent` 和 `JhiAlertErrorComponent` 组件，可以在整个生成的应用程序中使用。

默认情况下，当从 HTTP 响应中捕获到错误时，JHipster 将显示错误通知。

要显示自定义通知或警告，请在将 `AlertService` 注入到您的控制器、指令或服务后使用以下方法。

快捷方法 `success`、`info`、`warning` 和 `error` 将有 5 秒的默认超时，可以配置：

```ts
this.alerts.push(
    this.alertService.addAlert(
        {
            type: 'danger',
            msg: 'you should not have pressed this button!',
            timeout: 5000,
            toast: false,
            scoped: true
        },
        this.alerts
    )
);
```


## 使用 Angular CLI

Angular CLI 用于构建和测试 JHipster 应用程序。
然而，我们添加了一个自定义的 webpack 配置文件，以通过添加 BrowserSync、ESLint（Angular CLI 目前仍在使用 TSLint）、合并 JSON 翻译文件并在构建完成或失败时添加通知来改善开发者体验。

### 概述

[Angular CLI](https://cli.angular.io/) 是一个用于开发、构建和维护 Angular 应用程序的工具。JHipster 生成 Angular CLI 配置文件，因此 Angular CLI 工作流程适用于 JHipster。

这种集成是通过在应用程序根文件夹中生成 `angular.json` 文件并在 `package.json` 文件中添加其依赖项来完成的。

### 用法

```shell
ng help
```

### 构建

您可以使用 `ng build` 来构建您的前端，但我们仍然建议使用提供的 NPM 脚本，如 `npm start`、`npm run build` 等。请查看我们的[“在开发中使用”文档](/development/)和我们的[“在生产中使用”文档](/production/)。

### 生成组件、指令、管道和服务

您可以使用 `ng generate`（或 `ng g`）命令来生成 Angular 组件：

```shell
ng generate component my-new-component
ng g component my-new-component # using the alias

# Components support relative path generation
# Go to src/app/feature/ and run
ng g component new-cmp
# your component will be generated in src/app/feature/new-cmp
# but if you were to run
ng g component ../newer-cmp
# your component will be generated in src/app/newer-cmp
```

### 测试

为了在 JHipster 应用程序上保持一致性，测试可以通过 `npm` 命令获得：

```shell
npm test
```

### i18n

JHipster 使用 `ngx-translate` 依赖项来实现翻译功能。Angular CLI i18n 基于默认的 Angular i18n 支持，这与 JHipster 不兼容。

### 运行服务器

如果您更喜欢使用 Angular CLI 来开发您的应用程序，您可以使用其专用命令直接运行您的服务器。

```shell
ng serve
```
