JHipster 对错误处理有一流的支持：它提供错误页面和自定义机制来处理服务器端的业务和技术错误。


## 错误页面

JHipster 生成一个单页应用程序（SPA），但它仍然需要为不能（或无法）访问应用程序的人提供自定义错误页面。

### 动态错误页面

JHipster 提供了一个通用错误页面，它是一个 [Thymeleaf](https://www.thymeleaf.org/) 模板，位于 `src/main/resources/templates/error.html`。

该页面将显示服务器端错误消息，例如，如果用户尝试访问不存在的页面，它将显示 404 错误，告诉用户找不到页面。

### 静态 404 错误页面

JHipster 提供了一个特定的静态 404 错误页面，位于 `src/main/webapp/404.html`。默认情况下，JHipster 不使用这个页面：它在这里为在 JHipster 之前使用代理的项目（Apache/NGinx 等）提供，以便代理也可以显示 404 错误页面，即使 JHipster 应用程序不可用。

它需要在前端代理上进行特定配置。


## API 错误

为了处理 Spring MVC REST 错误，JHipster 使用 [Zalando 的 Problem Spring Web 库](https://github.com/zalando/problem-spring-web)，以便提供丰富的、基于 JSON 的错误消息。

为了帮助终端用户，对于每个已知问题，这个库将提供一个指向特定错误页面的链接，该页面将提供更多细节。这些链接在 `ErrorConstants` 类中配置，默认指向这个网站。在您的应用程序中，您应该自定义这些链接，并将它们指向您自己的 API 文档。
