:::note

对于使用某些类型安全性的微服务，这个实体不会被创建，详情请参阅[这里](/creating-microservices)。

:::

这个实体是一个特殊的实体，因为 JHipster 在内部创建和管理它。

它包含一些基本信息：
- 名字和姓氏，
- 登录名，
- 电子邮件地址，
- 密码（非明文），
- 权限，
- 等。

从头开始创建应用程序将为您生成一些默认用户，如 `admin` 或 `guest` 用户。


## 可能的关系

以下是从/到此实体的可能关系：
- 与此实体的 `多对一` 关系（`Car` 可以与 `User` 有多对一关系）。
  这将在您的新实体仓库中生成一个特定的查询，您可以按当前安全用户过滤您的实体，这是一个常见的需求。在生成的 Angular/React 客户端 UI 中，您将在 `Car` 中有一个下拉框来选择 `User`。
- 与 `User` 实体的 `多对多` 和 `一对一` 关系，但另一个实体 **必须** 是关系的拥有者（`Team` 可以与 `User` 有多对多关系，但只有团队可以添加/删除用户，用户不能添加/删除团队）。在前端客户端 UI 中，您也能够在多选框中选择 `User`。


## 修改 User 实体

如果您遇到需要修改 `User` 实体的问题，我们建议不要这样做。
修改此默认实体可能会根据更改的性质破坏您的应用程序。

相反，还有其他可用的解决方案，如：
- 创建一个由 `User` 实体组成的实体，
- 扩展 `User` 实体

### 使用组合

如果您需要向实体添加新字段，或向其添加关系，
您只需创建另一个实体，例如：

```jdl
entity ApplicationUser {
  additionalField Integer min(42) max(42)
}

relationship OneToOne {
  ApplicationUser{internalUser(login)} to @OnDelete("CASCADE") @Id User with builtInEntity
}
```

以下是此代码片段的作用：
- 创建一个名为 `ApplicationUser` 的新实体，带有一个字段，
- 从此实体到标准 `User` 实体创建一个关系：
  - 我们使用 `OneToOne` 关系来将 JHipster 创建的实体链接到这个新实体，
  - 我们使用单向关系，以便不修改内部管理的 `User` 实体。

这是推荐的解决方案，因为它可以使用 JDL 完成。
这个解决方案非常适合向 `User` 实体添加新字段和关系（除其他事项外），而不实际修改它。

### 使用继承

这个解决方案与前一个做同样的事情，但不像第一个那么直接，因为您需要：
- 手动创建一个新实体，
- 调整代码以使其使用这个新实体，
- 可能需要自己管理数据库迁移以持久化这个新实体（取决于更改的性质）。

然而，它具有与前一个相同的优点：您无需手动更改 `User` 实体。

### 创建您自己的默认 User 实体

这个方法实际上不推荐，但可以通过使用用户管理跳过选项（JDL 中的 `skipUserManagement` 应用选项）来实现。

JHipster 在某些情况下在内部使用此选项（对于某些选项），使用它将：
- 不生成任何用户管理代码（前端和后端），
- 允许您更新 `User` 实体（向其添加/删除任何字段），

此外，您必须创建实体并自己处理用户管理。

**最好保持它为 `false`，因为前两个解决方案相当容易实现**。
