JHipster 提供了多个选项来在运行时监控您的应用程序。


## 生成的仪表盘

对于单体应用程序和网关，JHipster 生成多个仪表盘来监控每个应用程序。
这些仪表盘在运行时可用，是进行监控的最简单方法。

![JHipster Metrics page](/images/jhipster_metrics_page.png)

### 指标仪表盘

指标仪表盘使用 Micrometer 来提供应用程序性能的详细视图。

它提供以下指标：

- JVM
- HTTP 请求
- 缓存使用情况
- 数据库连接池

通过点击 JVM 线程指标旁的展开按钮，您将获得正在运行的应用程序的线程转储，这对于找出被阻塞的线程非常有用。

### 健康仪表盘

健康仪表盘使用 Spring Boot Actuator 的健康端点来提供应用程序各个部分的健康信息。Spring Boot Actuator 开箱即用地提供了许多健康检查，您可以添加特定于应用程序的健康检查。

### 日志仪表盘

日志仪表盘允许在运行时管理正在运行的应用程序的 Logback 配置。
您可以通过点击按钮来更改 Java 包的日志级别，这在开发和生产中都非常方便。


## 安全指标

JHipster 在使用 JWT 认证类型的项目中跟踪 JWT 相关的安全指标。

特别地，JHipster 跟踪令牌验证错误数量（即无效令牌数量），使用名为 `security.authentication.invalid-tokens` 的自定义计量器，并使用以下计量器标签记录此类验证错误的原因：
- `invalid-signature`：JWT 签名验证失败；
- `expired`：JWT 已过期；
- `unsupported`：JWT 格式与应用程序期望的格式不匹配；
- `malformed`：JWT 构造不正确。

这些指标在生成的仪表盘中不可用，但它们作为应用程序指标公开，可以[转发到受支持的第三方监控系统](#forwarding-metrics-to-a-supported-third-party-monitoring-system-jmx-prometheus)进行可视化。


## JHipster Registry

JHipster Registry 有[自己的文档页面](/jhipster-registry)。

它主要提供与前一节相同的监控仪表盘，但它在单独的服务器上运行。因此，设置起来稍微复杂一些，但强烈建议将仪表盘运行在正在运行的应用程序之外：否则，当应用程序出现错误时，仪表盘将不可用。


## ELK (Elasticsearch, Logstash, Kibana) 技术栈

ELK 技术栈通常用于日志聚合和搜索，它由以下组件组成：

- [Elasticsearch](https://www.elastic.co/products/elasticsearch) 用于索引数据（日志和指标）
- [Logstash](https://www.elastic.co/products/logstash) 用于管理和处理从应用程序接收的日志
- [Kibana](https://www.elastic.co/products/kibana) 用于通过美观的界面可视化日志

:::警告

JHipster 支持将日志转发到 Logstash，但从 JHipster 版本 7 开始，我们不再提供任何 ELK 技术栈 Docker 部署和即用型仪表盘。这曾经是不再维护的 [JHipster Console](https://github.com/jhipster/jhipster-console) 子项目的一部分。我们建议现有用户迁移到其他 ELK 解决方案。

:::

### 将日志转发到 Logstash

要配置 JHipster 应用程序将其日志转发到 Logstash，请在其 `application-dev.yml` 或 `application-prod.yml` 中启用 logstash 日志记录：

```yaml
jhipster:
    logging:
        logstash:
            enabled: true
            host: localhost
            port: 5000
            queueSize: 512
```

要收集这些日志，在 Logstash 端，可以提供一个简单的 `logstash.conf` 文件：

```
input {
    tcp {
        port => "5000"
        type => syslog
        codec => json_lines
    }
}

output {
    elasticsearch {
        hosts => ["${ELASTICSEARCH_HOST}:${ELASTICSEARCH_PORT}"]
        index => "logs-%{+YYYY.MM.dd}"
    }
}
```

有关如何设置 ELK 技术栈的更多信息，请参阅 [Elastic 官方文档](https://www.elastic.co/guide/en/elastic-stack/current/index.html)。


## 将指标转发到受支持的第三方监控系统（JMX、Prometheus）

JHipster 默认以 [Prometheus](https://prometheus.io/) 格式公开应用程序指标。
它在 `management/prometheus` 下公开。
通过 [spring boot actuator](https://docs.spring.io/spring-boot/docs/current/reference/html/production-ready-features.html#production-ready-metrics) 也支持将指标转发到其他系统。

如果您希望禁用指标端点的公开，可以在 `src/main/resources/application.yml` 中禁用它。

```yaml
management:
    prometheus:
        export:
            enabled: false
```

prometheus 端点默认情况下是不受保护的。如果您希望通过 spring security 保护它，可以通过向 prometheus 端点添加基本认证来实现，
因为 prometheus 可以处理受基本认证保护的抽取端点。

创建一个新的配置文件（例如 `BasicAuthConfiguration.java`）。

```java
@Configuration
@Order(1)
@ConditionalOnProperty(prefix = "management", name = "metrics.export.prometheus.enabled")
public class BasicAuthConfiguration {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .antMatcher("/management/prometheus/**")
            .authorizeRequests()
            .anyRequest().hasAuthority(AuthoritiesConstants.ADMIN)
            .and()
            .httpBasic().realmName("jhipster")
            .and()
            .sessionManagement()
            .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            .and().csrf().disable();
        return http.build();
    }
}
```

您可以使用默认的 `admin/admin` 登录。您必须在 prometheus 配置中添加以下配置，以便 prometheus 仍然可以抽取您的应用程序。

```
basic_auth:
    username: "admin"
    password: "admin"
```

您可以通过 `docker-compose -f src/main/docker/monitoring.yml up -d` 在本地计算机上启动预配置的 Grafana 和 Prometheus 实例，查看
预置的 [jvm/micrometer 仪表盘](https://grafana.com/grafana/dashboards/4701)。

![Grafana Micrometer Dashboard](/images/monitoring_grafana_micrometer.png)

:::注意

与以前的 JHipster 版本不同，JHipster 5.8 指标报告开箱即用地仅支持 JMX 和 Prometheus。请查看 Metrics 官方文档，了解如何设置其他报告器，如 [Graphite](https://docs.spring.io/spring-boot/docs/current/reference/html/production-ready-features.html#production-ready-metrics-export-graphite)。

:::


## Zipkin

JHipster 应用程序可以通过 [Spring Boot Actuator Tracing](https://github.com/spring-projects/spring-boot/blob/main/spring-boot-project/spring-boot-docs/src/docs/asciidoc/actuator/tracing.adoc) 与 [Zipkin](http://zipkin.io/) 集成，为您的微服务架构提供分布式跟踪。要启用 Zipkin 跟踪，请使用 `zipkin` maven/gradle 配置文件打包您的应用程序。这将触发向 Zipkin 服务器报告 span，并在请求标头和日志中添加关联 ID（TraceId、SpanId 和 ParentId）。

Zipkin 还提供服务依赖关系图功能，让您可以随时间可视化微服务之间的依赖关系。

有关如何设置您的应用程序向 Zipkin 报告跟踪信息的更多信息，请参阅 [Spring Boot Production-ready Features](https://docs.spring.io/spring-boot/docs/current/reference/html/actuator.html#actuator.micrometer-tracing)。
