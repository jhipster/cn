为 JHipster 应用程序设置持续集成 (CI) 比经典的传统 Spring MVC 应用程序更加复杂，因为需要维护由 2 个软件堆栈组成的构建的复杂性：

- 使用 Maven 或 Gradle 的 Java 后端代码
- 使用 NodeJS、NPM 的 JavaScript 前端

每个堆栈都带有自己的依赖管理（Maven 工件、NPM 包），可能需要解决潜在的冲突。

JHipster 应该开箱即用地支持以下 CI 系统：

- Jenkins：
  - [设置 Jenkins 1](/setting-up-ci-jenkins1/)
  - [设置 Jenkins 2](/setting-up-ci-jenkins2/) （推荐）
- Travis：参考 [Travis 文档](https://docs.travis-ci.com/user/getting-started/)
- GitLab CI：参考 [GitLab CI 文档](https://about.gitlab.com/gitlab-ci/)
- Azure Pipelines：参考 [Azure Pipelines 文档](https://docs.microsoft.com/fr-fr/azure/devops/pipelines/?view=vsts)
- GitHub Actions：参考 [GitHub Actions 文档](https://github.com/features/actions)
- CircleCI：参考 [CircleCI 文档](https://circleci.com/docs/)


## 运行子生成器

要在您的项目文件夹中生成这些配置文件，请运行此命令：

```shell
jhipster ci-cd
```

然后回答所有问题。

### 您想要生成什么 CI/CD 流水线？

您想要生成的 CI/CD 流水线：

- Jenkins 流水线
- Azure Pipelines
- GitLab CI
- GitHub Actions
- Travis CI
- CircleCI

**注意**：当您选择 Jenkins 流水线时，将生成一个新的 `src/main/docker/jenkins.yml` 文件。
因此，您可以通过运行以下命令在本地测试 Jenkins：

```shell
docker-compose -f src/main/docker/jenkins.yml up -d
```

### 您是否希望在 Docker 容器中执行构建？（Jenkins / GitLab）

如果安装了 Docker，您可以在 Docker 容器中执行构建。

### 在 GitLab CI 中，在 Docker 容器中执行构建（提示：GitLab.com 使用 Docker 容器）？（GitLab）

如果您使用私有的 GitLab CI，您可以直接使用运行器。

如果您使用官方的 GitLab.com 流水线，您需要使用 Docker 容器。

### 您是否希望将构建状态发送到 GitLab？（Jenkins）

如果您的 Jenkins 依赖于 GitLab 仓库，您可以将构建状态发送到 GitLab。您的 Jenkins 必须正确配置。

### 您希望包含哪些任务/集成？

- 将您的应用程序部署到 *Artifactory*
- 使用 *Sonar* 分析您的代码
- 构建和发布 *Docker* 镜像
- *Snyk*：安全漏洞的依赖扫描（需要 SNYK_TOKEN）
- 部署到 *Heroku*（需要在 CI 服务上设置 HEROKU_API_KEY）
- 您是否希望启用 Cypress Dashboard（需要在 CI 服务上设置 CYPRESS_PROJECT_ID 和 CYPRESS_RECORD_KEY）

### 将您的应用程序部署到 *Artifactory*（Jenkins / GitLab）

- *Artifactory*：快照的 distributionManagement 的 ID 是什么？
- *Artifactory*：快照的 distributionManagement 的 URL 是什么？
- *Artifactory*：发布的 distributionManagement 的 ID 是什么？
- *Artifactory*：发布的 distributionManagement 的 URL 是什么？

### 使用 *Sonar* 分析您的代码

- *Sonar*：Sonar 服务器的名称是什么？

选择在 Jenkins 配置中定义的 Sonar 服务器名称。

- *Sonar*：Sonar 服务器的 URL 是什么？
- *Sonar*：Sonar 服务器的组织是什么？

在这里，您可以选择将 Sonar 分析推送到 [SonarCloud.io](https://sonarcloud.io)。
在这种情况下，您必须添加 `SONAR_TOKEN` 环境变量。

### 构建和发布 *Docker* 镜像

- *Docker*：Docker 注册表的 URL 是什么？

默认情况下，您可以使用 Docker Hub：[https://registry.hub.docker.com](https://registry.hub.docker.com)

- *Docker*：Docker 注册表的 Jenkins 凭据 ID 是什么？

默认情况下，您可以使用：`docker login`

- *Docker*：Docker 注册表的组织名称是什么？

### Snyk：安全漏洞的依赖扫描

您必须添加 `SNYK_TOKEN` 环境变量（检查您的 [Snyk 账户](https://app.snyk.io/account)）

查看完整文档：[https://snyk.io/](https://snyk.io/)

### Cypress Dashboard：在 Cypress 提供的 Web 应用程序中记录您的测试

您必须添加 `CYPRESS_PROJECT_ID` 和 `CYPRESS_RECORD_KEY` 环境变量（检查您的 [Dashboard 项目](https://dashboard.cypress.io/)）

您可以通过将 `CYPRESS_ENABLE_RECORD` 环境变量值更改为 false 来禁用记录。

查看完整文档：[cypress.io/dashboard](https://www.cypress.io/dashboard/)

### 部署到 *Heroku*

- *Heroku：您的 Heroku 应用程序的名称是什么？

您必须添加 `HEROKU_API_KEY` 环境变量。

注意：在使用 Heroku 部署之前，您需要在本地使用 [Heroku 子生成器](/heroku)。
它将创建 CI 工具所需的所有文件。


## 附加信息

根据您的操作系统和推送项目的位置，在使用 CI/CD 之前，您可能需要使包装器可执行。

如果您使用 Maven：

- `chmod +x mvnw`
- `git update-index --chmod=+x mvnw`

如果您使用 Gradle：

- `chmod +x gradlew`
- `git update-index --chmod=+x gradlew`
