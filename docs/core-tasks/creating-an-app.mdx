## 快速开始

首先，创建一个空目录，您将在其中创建您的应用程序：

```shell
mkdir myapplication
```

进入该目录：

```shell
cd myapplication/
```

要生成您的应用程序，请输入：

```shell
jhipster
```

回答生成器提出的问题，以创建适合您需求的应用程序。这些选项在[下一节](#生成应用程序时提出的问题)中有详细描述。

应用程序生成后，您可以使用 Maven（Linux/MacOS/Windows PowerShell 中使用 `./mvnw`，Windows Cmd 中使用 `mvnw`）或 Gradle（Linux/MacOS/Windows PowerShell 中使用 `./gradlew`，Windows Cmd 中使用 `gradlew`）启动它。

:::note

如果您使用 Maven 并在首次运行 `./mvnw` 命令后修改了前端文件，那么您必须运行 `./mvnw -Pwebapp` 才能看到最新的前端版本（Gradle 会自动检测前端更改并在需要时重新编译前端）。

:::

应用程序将在 [http://localhost:8080](http://localhost:8080) 可用

:::warning

如果您希望对 JavaScript/TypeScript 代码进行热更新(live reload)，您需要运行 `npm start`。您可以转到[在开发中使用 JHipster](/development/) 页面获取更多信息。

:::

如果您使用热更新(live reload)，那么您可以通过 `./mvnw -P-webapp` 或 `./gradlew -x webapp` 排除客户端任务来加快服务器启动。这特别能加快 Gradle 的速度。


## 生成应用程序时需要回答的问题

_有些问题会根据您前面做出的选择有所不同。例如，如果您没有选择 SQL 数据库，您就不需要配置 Hibernate 缓存。_

### 选择应用程序类型(Which type of application would you like to create?)

您的应用程序类型取决于您是否希望使用微服务架构。关于微服务的完整说明可以在[这里](/microservices-architecture/)找到，如果不确定，请使用默认的单体应用程序(Monolithic application)。

您可以使用：

*   单体应用程序(Monolithic application)：这是一个经典的、一站式应用程序。它更容易使用和开发，是我们推荐的默认选择。
*   微服务应用程序(Microservice application)：在微服务架构中，这是服务中的一个。
*   微服务网关(Microservice gateway)：在微服务架构中，这是一个路由和保护请求的边缘服务器。

### 应用程序名称(What is the base name of your application?)

这是您应用程序的名称。

### 默认Java包名(What is your default Java package name?)

您的 Java 应用程序将使用这个作为其根包。这个值由 Yeoman 存储，以便下次运行生成器时最后一个值将成为默认值。
您可以通过提供新值来覆盖它。

### 选择身份验证类型(Which _type_ of authentication would you like to use?)

以下是所有可能的选项：

*   JWT 身份验证：使用 [JSON Web Token (JWT)](https://jwt.io/)，这是默认选择，也是大多数人使用的。
*   OAuth 2.0 / OIDC 身份验证：这使用 OpenID Connect 服务器，如 [Keycloak](https://www.keycloak.org/)、[Auth0](https://developer.auth0.com) 或 [Okta](https://developer.okta.com)，在应用程序外部处理身份验证。这比 JWT 更安全，但需要设置 OpenID Connect 服务器，因此略显复杂。请注意，默认情况下 JHipster 将从 OpenID Connect 服务器同步用户数据，为此需要一个数据库。
*   HTTP 会话身份验证：经典的基于会话的身份验证机制，这是人们通常使用 [Spring Security](http://docs.spring.io/spring-security/site/index.html) 做的。

您可以在我们的[保护您的应用程序](/security/)页面上找到更多信息。

### 选择数据库类型(Which _type_ of database would you like to use?)

您可以在以下选项中选择：

- SQL 数据库（H2、MySQL、MariaDB、PostgreSQL、MSSQL、Oracle），您将使用 Spring Data JPA 访问
- [MongoDB](/using-mongodb/)
- [Cassandra](/using-cassandra/)
- [Couchbase](/using-couchbase/)
- [Neo4j](/using-neo4j/)
- 无数据库（仅在使用带有 JWT 身份验证的[微服务应用程序](/microservices-architecture/)时可用）

### 选择生产数据库类型(Which _production_ database would you like to use?)

这是您将在"production"配置文件中使用的数据库。要配置它，请修改您的 `src/main/resources/config/application-prod.yml` 文件。

如果您想使用 Oracle，在[使用 Oracle 数据库](/using-oracle/)时，您可能需要了解当前的限制。

### 选择开发数据库类型(Which _development_ database would you like to use?)

这是您将在"development"配置文件中使用的数据库。您可以使用：

*   H2，在内存中运行。这是使用 JHipster 的最简单方式，但当您重启服务器时，您的数据将丢失。
*   H2，将数据存储在磁盘上。这是比在内存中运行更好的选项，因为您不会在应用程序重启时丢失数据。
*   与您为生产环境选择的相同数据库：设置起来稍显复杂，但最终在与生产环境中使用的相同数据库上工作应该更好。这也是使用 liquibase-hibernate 的最佳方式，如[开发指南](/development/)中所述。

要配置它，请修改您的 `src/main/resources/config/application-dev.yml` 文件。

### 是否使用 Spring Cache(Do you want to use the Spring cache abstraction?)

Spring 缓存抽象允许使用不同的缓存实现：您可以使用 [ehcache](http://ehcache.org/)（本地缓存）、[Caffeine](https://github.com/ben-manes/caffeine)（本地缓存）、[Hazelcast](http://www.hazelcast.com/)（分布式缓存）、[Infinispan](http://infinispan.org/)（分布式缓存）、[Memcached](https://memcached.org/)（另一个分布式缓存）或 [Redis](https://redis.io/)（配置为单服务器缓存）。这可以对您应用程序的性能产生非常积极的影响，因此这是一个推荐的选项。

### 是否使用 Hibernate 二级缓存(Do you want to use Hibernate 2nd level cache?)

只有在您选择使用 SQL 数据库（因为 JHipster 将使用 Spring Data JPA 访问它）并在上一个问题中选择了缓存提供程序时，此选项才可用。

[Hibernate](http://hibernate.org/) 是 JHipster 使用的 JPA 提供程序，它可以使用缓存提供程序来大大提高其性能。因此，我们强烈建议您使用此选项，并根据您应用程序的需要调整您的缓存实现。

### 选择使用Maven还是Gradle(Would you like to use Maven or Gradle?)

您可以使用 [Maven](http://maven.apache.org/) 或 [Gradle](http://www.gradle.org/) 构建您生成的 Java 应用程序。Maven 更稳定、更成熟。Gradle 更灵活、更容易扩展、更时尚。

### 选择使用的其他技术(Which other technologies would you like to use?)

可以选择多个，可以向应用程序添加一个或多个其他技术。可用的技术有：

#### 使用 swagger-codegen 的 API 优先开发

此选项通过将 [Swagger-Codegen](https://github.com/swagger-api/swagger-codegen) 集成到构建中，让您可以为您的应用程序进行 [API 优先开发](/doing-api-first-development)。

#### 使用 ElasticSearch 的搜索引擎

[Elasticsearch](https://github.com/elastic/elasticsearch) 将使用 Spring Data Elasticsearch 进行配置。您可以在我们的 [Elasticsearch 指南](/using-elasticsearch/)中找到更多信息。

#### 使用 Hazelcast 的集群 HTTP 会话

默认情况下，JHipster 仅使用 HTTP 会话来存储 [Spring Security](http://docs.spring.io/spring-security/site/index.html) 的身份验证和授权信息。您可以选择在 HTTP 会话中放入更多数据。
使用 HTTP 会话在集群中运行时会导致问题，特别是如果您不使用带有"粘性会话"的负载均衡器。
如果您想在集群内复制您的会话，请选择此选项来配置 [Hazelcast](http://www.hazelcast.com/)。

#### 使用 Spring Websocket 的 WebSocket

可以使用 Spring Websocket 启用 Websocket。我们还提供了一个完整的示例，展示如何高效地使用该框架。

#### 使用 Apache Kafka 的异步消息

使用 [Apache Kafka](/using-kafka/) 作为发布/订阅消息代理。

#### 使用 Apache Pulsar 的异步消息

使用 [Apache Pulsar](/using-pulsar/) 作为发布/订阅消息代理。

### 选择客户端框架类型(Which Framework would you like to use for the client?)

要使用的客户端框架。

您可以使用：

*   Angular
*   React
*   Vue

### 选择Bootswatch 主题(Would you like to use a Bootswatch theme?)

要使用的客户端主题。

您可以使用 [Bootswatch](https://bootswatch.com/) 中的任何主题，或者保持默认主题。

### 您想为 CSS 使用 Sass 样式表预处理器吗？

[Sass](https://sass-lang.com/) 是简化 CSS 设计的绝佳解决方案。要高效使用，您需要运行 [Webpack](https://webpack.js.org) 开发服务器，它将自动配置。

### 是否启用国际化支持(Would you like to enable internationalization support?)

默认情况下，JHipster 在客户端和服务器端都提供出色的国际化支持。但是，国际化会增加一些开销，管理起来也稍显复杂，因此您可以选择不安装此功能。

请注意，JHipster 仅涵盖 UI 国际化。对于数据国际化，您需要在 JPA/Hibernate 层中自行编码。

### 您想使用哪些测试框架？

默认情况下，JHipster 提供 Java 单元/集成测试（使用 Spring 的 JUnit 支持）和 JavaScript 单元测试（使用 Jest）。作为选项，您还可以添加对以下内容的支持：

*   使用 Gatling 的性能测试
*   使用 Cucumber 的行为测试
*   使用 Protractor 的 Angular 集成测试

您可以在我们的["运行测试"指南](/running-tests/)中找到更多信息。

### 您想使用增量 Liquibase 更改日志吗？

JHipster 可选地为您创建增量更改日志，这样您就不需要重新创建数据库或手动生成 Liquibase 差异。

随时使用 `--incremental-changelog` 选项运行 JHipster 来启用它。

执行 JHipster 时，实体包含两种状态：

*   已保存到磁盘的旧状态
*   在内存中的新状态（从 jdl 或提示生成）

在它们之间生成差异并创建更改日志。

支持的功能：

*   创建/删除字段
*   创建/删除关系
*   JDL 和提示

不支持属性更改，如类型和约束。

冲突情况：

*   `--fork` 选项，因为它保存到磁盘会覆盖旧状态。

### 您是否想从 JHipster 市场安装其他生成器？

[JHipster 市场](/modules/marketplace/) 是您可以安装由第三方开发人员编写的附加模块的地方，为您的项目添加非官方功能。


## 使用蓝图

JHipster 5 引入了蓝图的概念。蓝图是 JHipster 模块，可以提供自定义客户端/服务器端模板，用于覆盖 JHipster 的模板。例如，[Kotlin 蓝图](https://github.com/jhipster/jhipster-kotlin) 将大部分 Java 服务器端代码替换为 Kotlin。

例如，要使用 Kotlin 蓝图，在生成应用程序时传递蓝图名称，如下所示。

```bash
jhipster --blueprint kotlin
```

蓝图的名称保存在 `.yo-rc.json` 中，在执行子生成器（如 `entity`、`spring-controller` 和 `spring-service`）时将自动使用。

如果蓝图没有实现特定的子生成器，它将被跳过，并使用相同子生成器的 JHipster 模板。

**注意：** 一个应用程序只能使用一个蓝图，尚不支持多个蓝图。


## 命令行选项

您也可以使用一些可选的命令行选项运行 JHipster。输入 `jhipster app --help` 可以找到这些选项的参考。

以下是您可以传递的选项：

* `--help` - 打印生成器的选项和用法
* `--blueprint` - 指定要使用的蓝图。例如 `jhipster --blueprint kotlin`
* `--skip-cache` - 不记住提示答案（默认：false）
* `--skip-git` - 不自动将生成的项目添加到 Git（默认：false）
* `--skip-install` - 不自动安装依赖（默认：false）
* `--skip-client` - 跳过客户端应用程序生成，所以您只有 Spring Boot 后端代码生成（默认：false）。
* `--skip-server` - 跳过服务器端应用程序生成，所以您只有前端代码生成（默认：false）。
* `--skip-user-management` - 跳过用户管理生成，包括后端和前端（默认：false）
* `--i18n` - 在跳过客户端生成时禁用或启用 i18n，否则无效（默认：true）
* `--auth` - 在跳过服务器端生成时指定身份验证类型，否则无效，但使用 `skip-server` 时为必需
* `--db` - 在跳过服务器端生成时指定数据库，否则无效，但使用 `skip-server` 时为必需
* `--skip-checks` - 跳过必需工具的检查（默认：false）
* `--jhi-prefix` - 在服务、组件和状态/路由名称前添加前缀（默认：jhi）
* `--entity-suffix` - 在实体类名后添加后缀（默认：空字符串）
* `--dto-suffix` - 在 DTO 类名后添加后缀（默认：DTO）
* `--prettier-java` - 使用 [prettier-java](https://github.com/jhipster/prettier-java) 格式化所有 Java 类（默认：false）
* `--experimental` - 启用实验性功能。请注意，这些功能可能不稳定，可能随时发生破坏性更改
* `--skip-fake-data` - 跳过为开发生成虚假数据
* `--creation-timestamp` - 为可重现构建设置时间戳。时间戳应该是可解析的 js 日期，例：2019-01-01。必须与 --with-entities 或 import-jdl 一起使用（generator-jhipster > 6.5.1）


## 提示

您也可以使用 Yeoman 命令行选项，如 `--force` 可以自动覆盖现有文件。因此，如果您想重新生成整个应用程序（包括其实体），您可以运行 `jhipster --force`。
