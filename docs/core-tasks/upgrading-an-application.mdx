# <i class="fa fa-level-up"></i> 升级应用程序

1. [选项 1 - 自动升级](#option-1---automatic-upgrade)
2. [选项 2 - 手动升级](#option-2---manual-upgrade)

## 选项 1 - 自动升级

这有助于：

* 在现有应用程序中获得最新的 JHipster 功能
* 在有重要的错误修复或安全更新时获得更改
* 保留您在代码库中的更改，并将它们与新生成的代码合并

:::warning

在进行升级之前，请仔细阅读本页面，以了解升级过程的工作原理

:::

### 需求

要使此子生成器工作，您需要从 [http://git-scm.com](http://git-scm.com/) 安装 `git`。

### 运行升级子生成器

进入应用程序的根目录：

`cd myJHipsterProject/`

要升级您的应用程序，请输入：

`npx generator-jhipster@latest upgrade`

一个替代方案是使用全局安装：

```
npm install -g generator-jhipster@latest
jhipster upgrade
```

以下是您可以传递的选项：

* `--skip-checks` - 在项目重新生成期间禁用检查
* `--silent` - 隐藏生成过程的输出

### 从 JHipster 7 和之前版本升级

[migrate blueprint](https://github.com/jhipster/generator-jhipster-migrate) 是升级子生成器的高级版本。如果您需要升级 JHipster 7 应用程序，建议您使用 migrate blueprint。例如，假设您有一个 7.9.3 应用程序。

运行 `jhipster-migrate` 升级到最新版本。解决冲突、提交并庆祝！

有关工作示例，请参见 21-Points Health 项目的以下拉取请求。

- [Upgrade to JHipster 7.9.4](https://github.com/mraible/21-points/pull/248)
- [Upgrade to JHipster 8.2.1](https://github.com/mraible/21-points/pull/249)

### 升级过程的分步解释

以下是 JHipster 升级子生成器处理的步骤：

1. 检查是否有新版本的 JHipster 可用（如果您使用 `--force` 则不适用）。
2. 检查应用程序是否已初始化为 `git` 存储库，否则 JHipster 将为您初始化一个并将当前代码库提交到主分支。
3. 检查以确保存储库中没有未提交的本地更改。如果发现未提交的更改，进程将退出。
4. 检查是否存在 `jhipster_upgrade` 分支。如果没有，将创建一个分支：有关此步骤的详细信息在"首次升级的特定步骤"部分中提供。
5. 切换到 `jhipster_upgrade` 分支。
6. 将 JHipster 全局升级到最新可用版本。
7. 清理当前项目目录。
8. 使用 `jhipster --force` 命令重新生成应用程序。
9. 将生成的代码提交到 `jhipster_upgrade` 分支。
10. 将 `jhipster_upgrade` 分支合并回启动 `npx jhipster upgrade` 命令的原始分支。
11. 现在您需要继续解决合并冲突（如果有的话）。

恭喜，您的应用程序现在已升级到最新版本的 JHipster！

### 首次升级的特定步骤

在首次运行 JHipster 升级子生成器时，为了避免删除您的所有更改，会运行一些额外步骤：

1. 创建一个孤立的 `jhipster_upgrade` 分支（它没有父分支）。
2. 生成整个应用程序（使用您当前的 JHipster 版本）。
3. 在 `master` 分支上进行块合并提交：对 `master` 分支上的代码库不进行任何更改；这是一种实用的方式，在 Git 中记录 `master` 的 HEAD 与当前 JHipster 版本是最新的。

#### 建议

* 不要在 `jhipster_upgrade` 分支上提交任何内容。这个分支专用于 JHipster 升级子生成器：每次运行子生成器时，都会创建一个新的提交。

* 如果您从非常旧的版本更新（例如从 5.0.0 到最新版本），我们建议在每个次要/补丁版本之间逐步更新，并执行测试以确保应用程序按预期工作。

* JHipster 社区中有一些有用的方法来设计应用程序，以使更新过程更容易，并减少合并冲突的数量。我们推荐使用 [JHipster Side-by-Side 方法](https://www.youtube.com/watch?v=Gg5CYoBdpVo)。  

## 选项 2 - 手动升级

对于手动升级，首先使用以下命令升级您的 JHipster 版本：

```shell
npm install -g generator-jhipster
```

删除您项目的 `node_modules` 文件夹，然后运行 `jhipster`：

```shell
rm -rf node_modules
jhipster
```

您也可以通过运行以下命令更新您的项目和所有实体：

```shell
jhipster --force
```

您也可以通过运行 `entity` 子生成器单独更新您的实体，即，如果您的实体名为 _Foo_：

```shell
jhipster entity Foo
```

### 关于重命名文件的提示

有时生成器中的文件可能会被重命名。如果您想查看 Git 重命名检测结果，您可以运行 `git add`（`git add .` 暂存所有文件），然后使用您喜爱的 Git 客户端查看更改。

如果许多文件被重命名，您可能希望在 Git 配置中增加 `diff.renameLimit` 以使 Git 重命名检测按预期工作。例如 `git config --replace-all diff.renameLimit 10000`。

默认情况下，Git 重命名检测使用 50% 的相似性阈值。要将相似性较低的文件视为重命名，您可以在 Git 命令中使用选项 `--find-renames=<n>`。例如 `git diff --staged --find-renames=30`。

### 查看您自己的更改

如果您希望查看生成项目后您所做的更改，您可以按照下面描述的步骤操作。

使用 `git clone` 将您的项目克隆到新文件夹。

从克隆的项目中删除所有文件和文件夹，除了 `.git`、`.jhipster` 和 `.yo-rc.json`。

找出您上次生成项目时使用的 JHipster 版本：查看项目根文件夹中的 `.yo-rc.json`，找出 `jhipsterVersion` 的值。

安装您上次生成项目时使用的 JHipster 版本：

```shell
npm install -g generator-jhipster@jhipsterVersionYouUsedLastTime
```

重新生成您的项目：

```shell
jhipster --force --skip-install
```

使用 `git diff` 您现在可以看到您的所有更改都被还原。如果您希望将您的所有更改看作是添加的，您可以将所有内容提交到 Git，然后还原最后一次提交。

### 查看 JHipster 更改

如果您希望查看 JHipster 所做的更改，您可以按照下面描述的步骤操作。

使用您上次生成项目时使用的 JHipster 版本生成项目：
* 创建一个新文件夹
* 将您项目的 `.yo-rc.json` 文件和 `.jhipster` 文件夹复制到这个新文件夹
* 找出您上次生成项目时使用的 JHipster 版本：查看 `.yo-rc.json`，找出 `jhipsterVersion` 的值
* 安装您上次生成项目时使用的 JHipster 版本：`npm install -g generator-jhipster@jhipsterVersionYouUsedLastTime`
* 在创建的文件夹中运行：`jhipster --skip-install`

使用最新的 JHipster 生成项目：
* 创建一个新文件夹
* 将您项目的 `.yo-rc.json` 文件和 `.jhipster` 文件夹复制到这个新文件夹
* 安装最新的 JHipster 版本：`npm install -g generator-jhipster`
* 在创建的文件夹中运行：`jhipster --skip-install`

使用您喜爱的文件和文件夹比较工具比较这 2 个文件夹，以查看 JHipster 所做的更改。
