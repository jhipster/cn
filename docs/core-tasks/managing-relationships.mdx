当使用 JPA 时，[实体子生成器](/creating-an-entity)可以在实体之间创建关系。


## 介绍

关系仅在使用 JPA 时才有效。如果您选择使用 [Cassandra](/using-cassandra)，它们将不可用。如果您使用 [MongoDB](/using-mongodb/)、[Couchbase](/using-couchbase/) 或 [Neo4j](/using-neo4j)，关系具有不同的语义，但它们都可以使用。有关 Couchbase 和 MongoDB 关系的更多信息，请参考 [Couchbase 和 MongoDB 的嵌入实体](#embedded-entities-for-couchbase-and-mongodb)。

关系在两个实体之间工作，JHipster 将生成代码用于：

- 在生成的实体中使用 JPA 管理此关系
- 创建正确的 Liquibase 更改日志，以便在数据库中存在该关系
- 生成 Angular/React 前端，以便您可以在用户界面中以图形方式管理此关系


## JHipster UML 和 JDL Studio

本页面描述了如何使用标准命令行界面使用 JHipster 创建关系。如果您希望创建许多实体和关系，您可能更喜欢使用图形工具。

在这种情况下，可以使用三个选项：

- [JDL Studio](https://start.jhipster.tech/jdl-studio/)，我们的在线工具，使用我们的领域特定语言创建实体和关系。
- [JHipster IDE](/jhipster-ide/)，一个插件，为流行的 IDE 提供 JDL 文件的文本编辑支持。
- 已弃用：_[JHipster UML](/jhipster-uml/)，允许您使用 UML 编辑器。_

您可以通过运行 `jhipster jdl your-jdl-file.jh` 使用 `jdl` 子生成器从 JDL 文件生成具有关系的实体。


## 可用关系

由于我们使用 JPA，常规的一对多、多对一、多对多和一对一关系都可用。

## 双向一对多关系

让我们从两个实体开始，`Owner` 和 `Car`。一个所有者可以有多辆车，一辆车只能有一个所有者。

因此，一侧这是一对多关系（一个所有者有多辆车），另一侧这是多对一关系（多辆车有一个所有者）：

```
Owner (1) <-----> (*) Car
```

请注意，生成实体后，生成器将通知您在生成
文件时发生了一些错误。这是正常的，因为目标实体尚未生成，因此您可以安全地忽略此警告。

我们将首先创建 `Owner`。以下是 `Owner` 的相关 JHipster 问题：

```
jhipster entity Owner
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Car
? What is the name of the relationship? car
? What is the type of the relationship? one-to-many
? What is the name of this relationship in the other entity? owner
```

请注意，我们选择了有关关系名称的默认选项。

现在我们可以生成 `Car`：

```
jhipster entity Car
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Owner
? What is the name of the relationship? owner
? What is the type of the relationship? many-to-one
? When you display this relationship with Angular, which field from 'Owner' do you want to use? id
```

也可以使用下面的 JDL 实现相同的效果
```
entity Owner
entity Car

relationship OneToMany {
  Owner{car} to Car{owner}
}
```

就是这样，您现在在这两个实体之间有了一对多关系！在生成的 Angular/React 客户端 UI 中，您将在 `Car` 中有一个下拉框来选择 `Owner`。


## 双向多对一关系

这等同于在 JDL 文件中反转两侧后的双向一对多关系：


```
entity Owner
entity Car

relationship ManyToOne {
  Car{owner} to Owner{car}
}
```


## 单向多对一关系

在前面的示例中，我们有一个双向关系：从 `Car` 实例您可以找到其所有者，从 `Owner` 实例您可以获得其所有汽车。

单向多对一关系意味着汽车知道其所有者，但反之则不然。

```
Owner (1) <----- (*) Car
```

您有两个原因要这样做关系：

- 从业务角度来看，您只以这种方式使用您的实体。所以您不希望有一个允许开发人员做没有意义的事情的 API。
- 使用 `Owner` 实体时您有一个小的性能提升（因为它不必管理汽车集合）。

在那种情况下，您仍然首先创建 `Owner`，这次没有关系：

```
jhipster entity Owner
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? No
```

然后是 `Car` 实体，如前面的示例：

```
jhipster entity Car
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Owner
? What is the name of the relationship? owner
? What is the type of the relationship? many-to-one
? When you display this relationship with Angular, which field from 'Owner' do you want to use? id
```

这将像前面的示例一样工作，但您无法从 `Owner` 实体添加或删除汽车。在生成的 Angular/React 客户端 UI 上，您将在 `Car` 中有一个下拉框来选择 `Owner`。
这是相应的 JDL：

```
entity Owner
entity Car

relationship ManyToOne {
  Car{owner} to Owner
}
```


## 单向一对多关系

单向一对多关系意味着 `Owner` 实例可以获得其汽车集合，但反之则不然。这与前面的示例相反。

```
Owner (1) -----> (*) Car
```

这种类型的关系目前在 JHipster 中默认不提供，请参阅 [#1569](https://github.com/jhipster/generator-jhipster/issues/1569) 以获取更多信息。

您有两个解决方案：

- 执行双向映射，并使用它而不进行修改：这是我们推荐的方法，因为它更简单
- 执行双向映射，然后修改它以将其转换为单向映射：
    - 删除您的 `@OneToMany` 注解上的 "mappedBy" 属性
    - 生成所需的连接表：您可以执行 `mvn liquibase:diff` 来生成该表，请参阅[关于使用 Liquibase diff 的文档](/development/)

这在 JDL 中不受支持，因为它不在 JHipster 中。


## 同两个实体上的两个一对多关系

在这个示例中，一个 `Person` 可以是多辆汽车的所有者，也可以是多辆汽车的驾驶员：

```
Person (1) <---owns-----> (*) Car
Person (1) <---drives---> (*) Car
```

为此，我们需要使用关系名称，在之前的示例中我们使用了默认值。

生成 `Person` 实体，它与 `Car` 实体有两个一对多关系：

```
jhipster entity Person
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Car
? What is the name of the relationship? ownedCar
? What is the type of the relationship? one-to-many
? What is the name of this relationship in the other entity? owner
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Car
? What is the name of the relationship? drivenCar
? What is the type of the relationship? one-to-many
? What is the name of this relationship in the other entity? driver
```

生成 `Car` 实体，它使用与在 `Person` 实体中配置的相同关系名称：

```
jhipster entity Car
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Person
? What is the name of the relationship? owner
? What is the type of the relationship? many-to-one
? When you display this relationship with Angular, which field from 'Person' do you want to use? id
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Person
? What is the name of the relationship? driver
? What is the type of the relationship? many-to-one
? When you display this relationship with Angular, which field from 'Person' do you want to use? id
```

也可以使用下面的 JDL 实现相同的效果

```
entity Person
entity Car

relationship OneToMany {
  Person{ownedCar} to Car{owner}
}

relationship OneToMany {
  Person{drivenCar} to Car{driver}
}
```

现在 `Car` 可以有一个驾驶员和一个所有者，它们都是 `Person` 实体。在生成的 Angular/React 客户端 UI 上，您将在 `Car` 中有下拉框来为 `owner` 字段和 `driver` 字段选择 `Person`。


## 多对多关系

一个 `Driver` 可以驾驶多辆汽车，但一辆 `Car` 也可以有多个驾驶员。

```
Driver (*) <-----> (*) Car
```

在数据库层面，这意味着我们将在 `Driver` 和 `Car` 表之间有一个连接表。

对于 JPA，这两个实体中的一个需要管理关系：在我们的情况下，这将是 `Car` 实体，它将负责添加或删除驾驶员。

请注意，在生成实体后，生成器将通知您在生成文件时发生了一些错误。这是正常的，因为目标实体尚未生成，您可以安全地忽略此警告。

让我们生成关系的非拥有方，即具有多对多关系的 `Driver`：

```
jhipster entity Driver
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Car
? What is the name of the relationship? car
? What is the type of the relationship? many-to-many
? Is this entity the owner of the relationship? No
? What is the name of this relationship in the other entity? driver
```

然后生成具有多对多关系拥有方的 `Car`：

```
jhipster entity Car
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Driver
? What is the name of the relationship? driver
? What is the type of the relationship? many-to-many
? Is this entity the owner of the relationship? Yes
? What is the name of this relationship in the other entity? car
? When you display this relationship on client-side, which field from 'Driver' do you want to use? This field will be displayed as a String, so it cannot be a Blob id
```

也可以使用下面的 JDL 实现相同的效果

```
entity Driver
entity Car

relationship ManyToMany {
  Car{driver} to Driver{car}
}
```

就是这样，您现在在这两个实体之间有了多对多关系！在生成的 Angular/React 客户端 UI 上，您将在 `Car` 中有一个多选下拉框来选择多个 `Driver`，因为 `Car` 是拥有方。

就是这样，您现在在这两个实体之间有了一对一关系！在生成的 Angular/React 客户端 UI 上，您将在 `Car` 中有一个下拉框来选择 `Driver`，因为 `Car` 是拥有方。

## 单向一对一关系

单向一对一关系意味着 `citizen` 实例可以获得其护照，但 `passport` 实例无法获得其所有者。

```
Citizen (1) -----> (1) Passport
```

首先生成 `Passport` 实体，与其所有者没有任何关系：

```
jhipster entity Passport
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? No
```

然后，生成 `Citizen` 实体：

```
jhipster entity Citizen
...
Generating relationships to other entities
? Do you want to add a relationship to another entity? Yes
? What is the name of the other entity? Passport
? What is the name of the relationship? passport
? What is the type of the relationship? one-to-one
? Is this entity the owner of the relationship? Yes
? Do you want to use JPA Derived Identifier - @MapsId? No
? What is the name of this relationship in the other entity? citizen
? When you display this relationship with Angular, which field from 'Passport' do you want to use? id
```

做完这些后，`Citizen` 拥有护照，但在 `Passport` 中没有定义 `Citizen` 实例。在生成的 Angular/React 客户端 UI 上，您将在 `Citizen` 中有一个下拉框来选择 `Passport`，因为 `Citizen` 是拥有方。
这是相应的 JDL：

```
entity Citizen
entity Passport

relationship OneToOne {
  Citizen{passport} to Passport
}
```

### 对于一对一关系使用 JPA 派生标识符(@MapsId)

[JPA 派生标识符](https://javaee.github.io/javaee-spec/javadocs/javax/persistence/MapsId.html)可以用于获得[最高效的映射](https://vladmihalcea.com/the-best-way-to-map-a-onetoone-relationship-with-jpa-and-hibernate/)。

这是先前单向一对一示例的相应 JDL：

```
entity Citizen
entity Passport

relationship OneToOne {
  Citizen{passport} to @Id Passport
}
```

这是先前双向一对一示例的相应 JDL：

```
entity Driver
entity Car

relationship OneToOne {
  Car{driver} to @Id Driver{car}
}
```

然而，根据业务需求，可能有些情况下应该避免这样做，因为它有以下约束：
**一旦在拥有方设置了 id(主键)，就不能使用 JPA/Hibernate 改变它。无论如何您都不应该改变它。**

**以下是有关用法的一些建议：**

在以下情况下使用 `@MapsId`：
* 依赖 - 如果拥有方（子实体）似乎高度依赖于非拥有方（父实体）。
* 关联值永远不会改变 - 如果您永远不会改变子实体的 id(主键)，一旦设置。

例如：

```
class User{}
class Profile{ @OneToOne @MapsId private User user; } // profile 只是为了那个用户
class Preferences{ @OneToOne @MapsId private User user; } // preference 只是为了那个用户
```

一旦为用户创建了配置文件或首选项，它就永远不会改变以指向另一个用户。

在以下情况下不要使用 `@MapsId`：
* 非依赖 - 如果拥有方（子实体）似乎不依赖于非拥有方（父实体）
* 关联值旨在改变 - 如果您认为子实体将来将指向另一个父实体。

例如：

```
class Car{ @OneToOne @JoinColumn(name="current_driver_id") Driver currentDriver} // 汽车将来可以由另一个驾驶员驾驶
class Driver{@OneToOne(mappedBy = "currentDriver") Car drivingCar} // 驾驶员将来驾驶另一辆汽车
```
汽车和驾驶员关联值在将来都可能改变。

:::note

有一个[关于使用 `@OneToOne` 和 `@MapsId` 的已知问题以及如何避免它](/tips/026_tip_issue_of_onetoone_with_mapsid_how_to_avoid_it.html)。

:::

## 设置获取数据策略为 eager (FetchType.EAGER)

所有关系都使用默认的 JPA FetchType：
- OneToMany: LAZY
- ManyToOne: EAGER
- ManyToMany: LAZY
- OneToOne: EAGER

由于 eager 获取类型，在 JSON 反序列化期间有一个[NPE 的已知问题](https://github.com/jhipster/generator-jhipster/issues/10981)。如果您想将 `OneToMany` 或 `ManyToMany` 关系设置为 `FetchType.EAGER`，您可以使用以下解决方案之一：
- 在关系上使用 `@JsonInclude(JsonInclude.Include.NON_EMPTY)`

例如：

```
@OneToMany(mappedBy = "parent", fetch = FetchType.EAGER)
@JsonInclude(JsonInclude.Include.NON_EMPTY)
private Set<Child> child = new HashSet<>();
```

- 在后端获取资源时，如果集合为空，则返回 null
- 使用 DTO 并处理空集合的边缘情况

## Couchbase 和 MongoDB 的嵌入实体

Couchbase 和 MongoDB 通过嵌入文档支持关系。有关 MongoDB 中嵌入文档的更多信息，请参阅 [https://docs.mongodb.com/manual/applications/data-models-relationships/](https://docs.mongodb.com/manual/applications/data-models-relationships/)，对于 Couchbase，请参阅 [https://docs.couchbase.com/server/5.1/data-modeling/modeling-relationships.html](https://docs.couchbase.com/server/5.1/data-modeling/modeling-relationships.html)。

您可以通过使用 `@embedded` 简单地定义嵌入文档。例如，要定义一对一关系：

```
entity Country {
  countryName String
}

@embedded
entity Region {
  regionName String
}


relationship OneToOne {
  Country to Region
}
```

同样，对于一对多关系：

```
entity Country {
  countryName String
}

@embedded
entity Region {
  regionName String
}


relationship OneToMany {
  Country to Region
}
```

对于多对多关系，您可以在两个方向上简单地使用 `@embedded` 关键字：

```
@embedded
entity Country {
  countryName String
}

@embedded
entity Region {
  regionName String
}


relationship ManyToMany {
  Country to Region
}
