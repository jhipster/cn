## 介绍

创建应用程序后，您将希望创建实体(_Entity_)。例如，您可能想创建一个 _Author_ 和一个 _Book_ 实体。对于每个实体，您需要：

* 一个数据库表
* 一个 Liquibase 更改集
* 一个 JPA 实体
* 一个 Spring Data JPA 仓库
* 一个 Spring MVC REST 控制器，具有基本的 CRUD 操作
* 一个 Angular 路由器、组件和服务
* 一个 HTML 视图
* 集成测试，以验证一切都按预期工作
* 性能测试，以查看一切是否运行顺畅

如果您有多个实体，您可能希望在它们之间建立关系。为此，您将需要：

* 一个数据库外键
* 用于管理此关系的特定 JavaScript 和 HTML 代码

"entity"子生成器将创建所有必要的文件，并为每个实体提供 CRUD 前端（参见 [Angular 项目结构](/using-angular/) 和 [React 项目结构](/using-react/)）。可以通过运行 `jhipster entity <entityName> --[options]` 来调用子生成器。输入 `jhipster entity --help` 可以找到这些选项的参考。

以下是支持的选项。

* `--table-name <table_name>` - 默认情况下，JHipster 将根据您的实体名生成表名，如果您希望使用不同的表名，可以通过此选项传递。
* `--angular-suffix <suffix>` - 如果您希望您的所有 Angular 路由都具有自定义后缀，可以使用此选项传递。
* `--client-root-folder <folder-name>` - 在客户端为实体使用根文件夹名称。默认情况下，单体应用为空，网关为微服务的名称。
* `--regenerate` - 这将重新生成现有实体，而不问任何问题。
* `--skip-server` - 这将跳过服务器端代码，只生成客户端代码。
* `--skip-client` - 这将跳过客户端代码，只生成服务器端代码。
* `--skip-db-changelog` - 这将跳过数据库更改日志的生成（对于 SQL 数据库使用 Liquibase）。
* `--db` - 在跳过服务器端生成时指定数据库，否则无效。

:::warning

不要为您的实体选择短名称（参见 <a href="https://github.com/jhipster/generator-jhipster/issues/8446" target="_blank" rel="noopener">此票据</a>）。

:::


## JHipster UML 和 JDL Studio

此页面描述了如何使用标准命令行界面在 JHipster 中创建实体。如果您想创建许多实体，您可能更喜欢使用图形工具。

在这种情况下，有两个选项可用：

* [JHipster UML](/jhipster-uml/)，允许您使用 UML 编辑器。
* [JDL Studio](https://start.jhipster.tech/jdl-studio/)，我们的在线工具，使用我们的领域特定语言 [JDL](/jdl/intro/) 创建实体和关系。

如果您使用了 JDL Studio：

* 您可以使用 `jdl` 子生成器，通过运行 `jhipster jdl your-jdl-file.jh` 从 JDL 文件生成实体。

  * 如果您不想在导入 JDL 时重新生成您的实体，可以使用 `--json-only` 标志来跳过实体创建部分，只在 `.jhipster` 文件夹中创建 json 文件。

  ```shell
  jhipster jdl ./my-jdl-file.jdl --json-only
  ```

  * 默认情况下，`jdl` 只重新生成已更改的实体，如果您希望重新生成所有实体，请传入 `--force` 标志。请注意，这将覆盖您对实体文件的所有本地更改

  ```shell
  jhipster jdl ./my-jdl-file.jdl --force
  ```

* 如果您想使用 JHipster UML 而不是 `jdl` 子生成器，您需要通过运行 `npm install -g jhipster-uml` 来安装它，然后运行 `jhipster-uml yourFileName.jh`。


## 实体字段

对于每个实体，您可以添加任意数量的字段。您需要输入字段名称和它们的类型，JHipster 将为您生成所有所需的代码和配置，从 Angular HTML 视图到 Liquibase 更改日志。

这些字段不能包含您正在使用的技术中的保留关键字。例如，如果您使用 MySQL：

* 您不能使用 Java 保留关键字（因为您的代码将无法编译）
* 您不能使用 MySQL 保留关键字（因为您的数据库架构更新将失败）


## 字段类型

JHipster 支持许多字段类型。此支持取决于您的数据库后端，因此我们使用 Java 类型来描述它们：Java `String` 在 Oracle 或 Cassandra 中的存储方式不同，而 JHipster 的优势之一就是为您生成正确的数据库访问代码。

* `String`：Java 字符串。其默认大小取决于底层后端（如果您使用 JPA，默认为 255），但您可以使用验证规则来更改它（例如，设置最大大小为 1024）。
* `Integer`：Java 整数。
* `Long`：Java 长整数。
* `Float`：Java 浮点数。
* `Double`：Java 双精度浮点数。
* `BigDecimal`：[java.math.BigDecimal](https://docs.oracle.com/javase/8/docs/api/java/math/BigDecimal.html) 对象，当您需要精确的数学计算时使用（通常用于金融操作）。
* `LocalDate`：[java.time.LocalDate](https://docs.oracle.com/javase/8/docs/api/java/time/LocalDate.html) 对象，用于在 Java 中正确管理日期。
* `Instant`：[java.time.Instant](https://docs.oracle.com/javase/8/docs/api/java/time/Instant.html) 对象，用于表示时间戳，时间线上的瞬时点。
* `ZonedDateTime`：[java.time.ZonedDateTime](https://docs.oracle.com/javase/8/docs/api/java/time/ZonedDateTime.html) 对象，用于表示给定时区中的本地日期时间（通常是日历预约）。请注意，REST 和持久性层都不支持时区，因此您应该最好使用 `Instant`。
* `Duration`：[java.time.Duration](https://docs.oracle.com/javase/8/docs/api/java/time/Duration.html) 对象，用于表示时间量。
* `LocalTime`：[java.time.LocalTime](https://docs.oracle.com/javase/8/docs/api/java/time/LocalTime.html) 对象，用于表示不带时区的本地时间。例如，可用于定义营业时间。
* `UUID`：[java.util.UUID](https://docs.oracle.com/javase/8/docs/api/java/util/UUID.html)。
* `Boolean`：Java 布尔值。
* `Enumeration`：Java 枚举对象。选择此类型时，子生成器将询问您希望在枚举中包含哪些值，并将创建一个特定的 `enum` 类来存储它们。
* `Blob`：Blob 对象，用于存储一些二进制数据。选择此类型时，子生成器将询问您是否要存储通用二进制数据、图像对象或 CLOB（长文本）。图像将在 Angular 端进行特殊处理，以便可以向最终用户显示。


## 验证

可以为每个字段设置验证。根据字段类型，将提供不同的验证选项。

验证将自动生成在：

* HTML 视图，使用 Angular、React 或 Vue 验证机制
* Java 域对象，使用 [Bean Validation](http://beanvalidation.org/)

Bean 验证然后将用于在以下情况下自动验证域对象：

* Spring MVC REST 控制器（使用 `@Valid` 注解）
* Hibernate/JPA（实体在保存前会自动验证）

验证信息还将用于生成更精确的数据库列元数据：

* 必填字段将被标记为不可为空
* 唯一字段将创建唯一约束
* 具有最大长度的字段将具有相同的列长度

验证有一些限制：

* 我们不支持 Angular、React 和 Bean Validation 的所有验证选项，因为我们只支持客户端和服务器端 API 的共同选项
* 正则表达式模式在 JavaScript 和 Java 中的工作方式不同，因此如果您配置了一个，您可能需要调整其中一个生成的模式
* JHipster 生成适用于通用实体的单元测试，而不知道您的验证规则：生成的测试可能不会通过验证规则。在这种情况下，您需要更新单元测试中使用的示例值，以便它们通过验证规则。

## 为业务逻辑生成单独的服务类

拥有单独的服务类允许拥有更复杂的逻辑，相比于直接使用 Spring REST 控制器。拥有服务层（无论是否带有接口）将允许您使用 DTO（参见下一部分）。

这与使用 Spring 服务子生成器的逻辑相同。


## 数据传输对象 (DTOs)

默认情况下，JHipster 实体不使用 DTO，但如果您选择拥有服务层（参见上一部分），它们作为一个选项可用。这里是文档：[使用 DTOs](/using-dtos/)。


## 过滤

可选的，存储在 SQL 数据库中的实体可以使用 JPA 进行过滤。这里是文档：[过滤您的实体](/entities-filtering/)。


## 分页

请注意，如果您使用 [Cassandra](/using-cassandra/) 创建了应用程序，分页功能不可用。这将在未来版本中添加。

分页使用 [Link 头](http://tools.ietf.org/html/rfc5988)，就像 [GitHub API](https://developer.github.com/v3/#pagination) 中一样。JHipster 在服务器（Spring MVC REST）和客户端（Angular/React）两端都提供了此规范的自定义实现。

生成实体时，JHipster 提供 4 种分页选项：

* 无分页（在这种情况下，后端将不被分页）
* 基于 [Bootstrap 分页组件](https://getbootstrap.com/docs/4.3/components/pagination/) 的完整分页系统
* 基于 [无限滚动指令](http://sroze.github.io/ngInfiniteScroll/) 的无限滚动系统


## 更新现有实体

实体配置保存在 `.jhipster` 目录中的特定 `.json` 文件中。因此，如果您使用现有实体名再次运行子生成器，您可以更新或重新生成实体。

当您为现有实体运行实体子生成器时，您将被问一个问题“您是否要更新实体？这将替换此实体的现有文件，您的所有自定义代码将被覆盖”，并提供以下选项：

* `是，重新生成实体` - 这将重新生成您的实体。提示：运行子生成器时传递 `--regenerate` 标志可以强制执行此操作
* `是，添加更多字段和关系` - 这将为您提供添加更多字段和关系的问题
* `是，删除字段和关系` - 这将为您提供从实体中删除现有字段和关系的问题
* `否，退出` - 这将退出子生成器而不更改任何内容

您可能因以下原因而要更新实体：

* 您要向现有实体添加/删除字段和关系
* 您要将实体代码重置为其原始状态
* 您已更新了 JHipster，并希望使用新模板生成实体
* 您已修改了 `.json` 配置文件（格式与生成器提出的问题非常接近，因此并不复杂），因此您可以拥有实体的新版本
* 您已复制/粘贴了 `.json` 文件，并希望一个与复制实体非常相似的新实体

:::tip

要一次性重新生成所有实体，您可以使用以下命令（删除 `--force` 可在文件已更改时提出问题）。

:::

* Linux & Mac: ``for f in `ls .jhipster`; do jhipster entity ${f%.*} --force ; done``
* Windows: `for %f in (.jhipster/*) do jhipster entity %~nf --force`


## 教程

这是一个关于创建两个实体（Author 和 Book）的简短教程，它们之间有一对多关系。

:::warning

如果您希望对 JavaScript/TypeScript 代码进行“热更新”，您需要运行 `npm start`。您可以转到[在开发中使用 JHipster](/development/) 页面获取更多信息。

:::

### 生成“Author”实体

由于我们希望在 Author 和 Book 之间建立一对多关系（一个作者可以写多本书），我们需要首先创建 Author。在数据库层面，JHipster 然后将能够在 Book 表上添加外键，链接到 Author 表。

`jhipster entity author`

回答有关此实体字段的下一个问题，Author 具有：

* 一个类型为“String”的“name”
* 一个类型为“LocalDate”的“birthDate”

然后回答有关关系的问题，Author 具有：

* 与“book”实体的一对多关系（该实体尚不存在）

### 生成“Book”实体

`jhipster entity book`

回答有关此实体字段的下一个问题，Book 具有：

* 一个类型为“String”的“title”
* 一个类型为“String”的“description”
* 一个类型为“LocalDate”的“publicationDate”
* 一个类型为“BigDecimal”的“price”

然后回答有关关系的问题，Book：

* 与“author”实体有多对一关系
* 这个关系使用“name”字段（来自 Author 实体）来显示

### 检查生成的代码

使用 `mvn test` 运行生成的测试套件，该套件将测试 Author 实体和 Book 实体。

启动应用程序（例如使用 `mvn`），登录并在“实体”菜单中选择“Author”和“Book”实体。

检查数据库表，查看您的数据是否正确插入。

### 改进生成的代码

生成的文件包含所有基本的 CRUD 操作，如果您不需要超过 CRUD 操作的功能，则不需要修改。

如果您要修改生成的代码或数据库架构，您应该遵循我们的[开发指南](/development/)。

如果您需要一些更复杂的业务行为，您可能需要使用服务子生成器添加 Spring `@Service` 类。
