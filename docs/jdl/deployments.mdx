## 语法

部署声明如下：

```jdl
deployment {
  <deployment option name> <deployment option value>
}
```

- 类似于应用程序，部署声明通过指定选项键和值来工作


## 示例

### 基本示例

```jdl
deployment {
  deploymentType docker-compose
  appsFolders [foo, bar]
  dockerRepositoryName "yourDockerLoginName"
}
```

### 多个部署

如果您想要多个部署，可以这样做：

```jdl
// 将在 'docker-compose' 文件夹下创建
deployment {
  deploymentType docker-compose
  appsFolders [foo, bar]
  dockerRepositoryName "yourDockerLoginName"
}

// 将在 'kubernetes' 文件夹下创建
deployment {
  deploymentType kubernetes
  appsFolders [foo, bar]
  dockerRepositoryName "yourDockerLoginName"
}
```

您可以为每个 `deploymentType` 设置一个部署。在 `appsFolders` 中定义的应用程序应该在您创建部署的同一文件夹中，或者在 `directoryPath` 中定义的文件夹中。

例如，上面的情况您需要有这样的文件夹结构：

```
.
├── yourJdlFile.jdl
├── foo
├── bar
├── kubernetes // 将由 JDL 创建
└── docker-compose // 将由 JDL 创建
```


## 可用的部署选项

以下是 JDL 中支持的部署选项：

|JDL 选项名称                |默认值          |可能的值                       |备注                                                                                                                                      |
|----------------------------|-------------------|--------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
|deploymentType              |docker-compose     |docker-compose, kubernetes, openshift |-                                                                                                                                            |
|directoryPath               |`../`              |-                                     |相对路径。必须用双引号包裹                                                                                                                     |
|appsFolders                 |[]                 |-                                     |应用程序的目录名称，用逗号分隔。必须是列表，例如 [foo, bar]                                                                                    |
|clusteredDbApps             |[]                 |-                                     |具有集群数据库的应用程序的目录名称，用逗号分隔。必须是列表，例如 [foo, bar]                                                                    |
|gatewayType                 |SpringCloudGateway |-                                     |当 serviceDiscoveryType 为 `no` 时，此值被忽略                                                                                              |
|monitoring                  |no                 |no, prometheus                        |-                                                                                                                                            |
|serviceDiscoveryType        |consul             |consul, eureka, no                    |-                                                                                                                                            |
|dockerRepositoryName        |-                  |-                                     |docker 仓库的名称或 URL。必须用双引号包裹                                                                                                   |
|dockerPushCommand           |`docker push`      |-                                     |要使用的 docker push 命令。必须用双引号包裹                                                                                                  |
|kubernetesNamespace         |default            |-                                     |仅当 deploymentType 为 kubernetes 时适用                                                                                                   |
|kubernetesUseDynamicStorage |false              |true, false                           |仅当 deploymentType 为 kubernetes 时适用，启用 kubernetesStorageClassName 选项                                                             |
|kubernetesStorageClassName  |-                  |-                                     |仅当 deploymentType 为 kubernetes 时适用，可以留空（两个双引号）                                                                             |
|kubernetesServiceType       |LoadBalancer       |LoadBalancer, NodePort, Ingress       |仅当 deploymentType 为 kubernetes 时适用                                                                                                   |
|ingressDomain               |-                  |-                                     |当 kubernetesServiceType 为 `Ingress` 时的 Ingress 域名。必须用双引号包裹。仅当 deploymentType 为 kubernetes 时适用                        |
|ingressType                 |nginx              |nginx, gke                            |kubernetes ingress 类型，仅当 `kubernetesServiceType` 设置为 Ingress 时设置                                                               |
|istio                       |false              |true, false                           |仅当 deploymentType 为 kubernetes 时适用                                                                                                   |
|openshiftNamespace          |default            |-                                     |仅当 deploymentType 为 openshift 时适用                                                                                                    |
|storageType                 |ephemeral          |ephemeral, persistent                 |仅当 deploymentType 为 openshift 时适用                                                                                                    |
|registryReplicas            |2                  |-                                     |使用 openshift 部署类型时的副本数量                                                                                                        |
