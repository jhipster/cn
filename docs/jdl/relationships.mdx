## 关系类型

在 `relationship` 关键字后提及。

有四种关系类型：
  - `OneToOne`
  - `OneToMany`
  - `ManyToOne`
  - `ManyToMany`

要了解更多关于关系和可实现的功能，您可以访问[专门页面](/managing-relationships)。

关于复数名称的说明：JHipster 会处理它们，因此您不需要在关系中处理。


## 关系方法

在源实体和目标实体之后提及，使用 `with` 关键字。

支持的方法：

- `builtInEntity`：当目标实体是内置实体（如 `User` 和 `Authority`）时必需


## 多个关系主体

如果您厦倦在 JDL 文件中有 _n_ 个相同类型的关系，别担心！有一个解决方案。

以此 JDL 示例为例：

```jdl
relationship OneToOne {
  A to B
}
relationship OneToOne {
  B to C
}
relationship OneToOne {
  C to D
}
relationship OneToOne {
  D to A
}
```

解决方案是将每个关系主体放在一个关系声明内，如下所示：

```jdl
relationship OneToOne {
  A to B,
  B to C,
  C to D,
  D to A
}
```

这种语法在以下情况下非常有用：

- 您有很多相同类型的关系，
- 您想知道关系是什么，
- 您不想浪费时间在 JDL 文件中查找它们


## 语法

关系声明如下：

```jdl
relationship (OneToMany | ManyToOne | OneToOne | ManyToMany) {
  @<option>("<option value>")+ <from entity>[{<relationship name>[(<display field>)]}] to @<option>("<option value>")+ <to entity>[{<relationship name>[(<display field>)]}]+
}
```

- `(OneToMany | ManyToOne| OneToOne | ManyToMany)` 是您关系的类型，
- `<option>` 是支持的值之一：`Id | OnDelete | OnUpdate`。请确保将此放在关系的正确一侧。首字母大小写不敏感（jdl 导出将生成大写）。
- `<option value>` 是给定选项的适合的可选值之一：`NO ACTION | RESTRICT | CASCADE | SET NULL | SET DEFAULT`
- `<from entity>` 是拥有关系的实体的名称：源，
- `<to entity>` 是关系指向的实体的名称：目标，
- `<relationship name>` 是以另一端为类型的字段的名称，
- `<display field>` 是应该在选择框中显示的字段的名称（默认：`id`），
- `required` 注入的字段是否必需。
- `with builtInEntity` 关系目标是否为内置实体
- 您可以有多个关系主体
  - 有关更多信息，请参阅[多个关系主体](#多个关系主体)部分！


## 示例

### 基本示例

```jdl
relationship OneToOne {
  A to B
}
```

请注意，此示例与以下相同：
```jdl
relationship OneToOne {
  A{b} to B{a}
}
```
不指定注入字段是拥有双向关系的简写形式。

另一个示例：
```jdl
relationship OneToOne {
  A{b} to B
}
```
这将生成一个单向关系。您只能通过实体 A 找到实体 B，但不能通过实体 B 找到实体 A。

### 包含注入字段

```jdl
relationship ManyToMany {
  A{b} to B{a}
}
```

这是一个双向关系，意味着两个实体都将生成并拥有另一个实体的"实例"。

### 包含方法

```jdl
relationship OneToOne {
  A to User with builtInEntity
}
```

### 包含选项

```jdl
relationship ManyToOne {
   A to @OnDelete("SET NULL") @OnUpdate("CASCADE") B
}
```
注意： 

在 Hibernate/JPA 中，删除在与子实体具有多对一关系的父实体取决于关系配置和级联行为。

级联删除：启用时，删除父实体会自动删除其关联的子实体。这通过在父实体类的 @OneToMany 注解中使用 CascadeType.REMOVE 来实现。

```java
@OneToMany(mappedBy = "parent", cascade = CascadeType.REMOVE)
private List<ChildEntity> children;
```

不级联删除：如果未启用，删除具有子实体的父实体将导致外键约束冲突。您必须在删除父实体之前手动删除或解除子实体。
请谨慎使用级联删除，因为它可能导致意外的数据丢失。

防止删除错误的替代方案：在 JDL 中使用 @OnDelete 注解，该注解将为级联删除配置数据库模式，或在生成的 Java 代码中添加 cascade = CascadeType.REMOVE（如果适用）。

### 包含必需侧

用于使至少一个关系侧必需。

```jdl
relationship ManyToMany {
  A{b required} to B{a}
}

// 或

relationship ManyToMany {
  A{b} to B{a required}
}

或

relationship ManyToMany {
  A{b(name) required} to B{a required}
}
```

### 反身关系

反身关系是源实体和目标实体相同的关系。

```jdl
relationship ManyToMany {
  A{parent} to A{child}
}
```

#### 关于必需反身关系的说明

如[此处](https://github.com/jhipster/generator-jhipster/issues/11495)所注，不支持对同一实体的必需关系。问题在于子实体**始终**必须有一个父实体，而父实体又必须有一个父实体，以此类推。
一个可能的解决方案是拥有显式的根和子实体。

### 注释

可以对关系添加注释：

```jdl
relationship OneToOne {
  /** 此注释将放在实体 A 中的 b 之前 */
  A{b}
  to
  /** 此注释将放在实体 B 中的 a 之前 */
  B{a}
}
```

这里适用相同的注释规则。
这些注释将由 JHipster 后续添加为 Javadoc 注释。JDL 拥有自己的注释类型：
  - // 一个被忽略的注释
  - /** 不被忽略的注释 */

因此，任何以 `//` 开头的内容都被认为是 JDL 的内部注释，不会被计为 Javadoc。
请注意，以 `#` 开头的 JDL Studio 指令在解析期间将被忽略。
