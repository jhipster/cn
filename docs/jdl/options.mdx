在 JHipster 中，您可以为实体指定选项，如分页或 DTO。
您可以使用 JDL 做同样的事情，可以在实体上使用注解，或使用以下语法：

```jdl
entity A {
  name String required
}
entity B
entity C

dto A, B with mapstruct

paginate A with infinite-scroll
paginate B with pagination
paginate C with pager  // pager 仅在 AngularJS 中可用

service A with serviceClass
service C with serviceImpl
```

可用选项的完整列表[在此处](#available-options)。


## 如何使用

有两种选项：

- 一元（无选项值）
- 二元（有值）

有三种方式将选项应用于实体：

- 使用选项名称（`dto`、`readOnly` 等），请参阅示例
- 使用注解
- 使用 `use XYZ` 形式

不建议混合使用，因为这会降低可读性。


## 语法

对于常规形式：
```
<option name> <option entity list>

或

<option name> <option entity list> with <option value>

或

<option name> <option entity list> with <option value> except <option excluded entity list>

或 

<option name> <option entity list> except <option excluded entity list>
```

- 对于一元选项：
  - 需要选项名称和列表
  - 排除的实体是可选的，使用 `except` 关键字（有关更多详细信息，请参阅下文）
- 对于二元选项：
  - 实体列表在 `with` 关键字和选项值之前
  - 同样，排除的实体在末尾使用 `except` 关键字

对于注解：
```
@<option name>
entity <entity name>

或

@<option name>(<option value>)
```

- 类似于 Java，注解可以在括号中取值
  - 根据选项，值可能是可选的，也可能是不可选的


## use XYZ 选项

使用 use-option 形式，您可以在实体上指定一些选项。
它是在 JHipster Code 2020 期间创建的，其创建的原因是：

- 解决选项禁用问题（在 JHipster 中有多种方式说“不”：`no, false, none`）
- 提供一种按实体分组选项的方法

```jdl
entity A
entity B
entity C

use serviceClass for * except C
use mapstruct, serviceImpl, infinite-scroll for A, B
use pagination for C
```

|Use 选项值    |备注                                                                                                              |
|-----------------|-----------------------------------------------------------------------------------------------------------------|
|mapstruct        |是否为您的实体创建 DTO，如果实体有 DTO 但没有服务，则将使用 'serviceClass'               |
|serviceClass     |                                                                                                                 |
|serviceImpl      |                                                                                                                 |
|pagination       |当应用程序使用 Cassandra 时，禁止将分页作为选项                                               |
|infinite-scroll  |当应用程序使用 Cassandra 时，禁止将分页作为选项                                               |
|elasticsearch    |需要应用程序启用 searchEngine 选项                                                                   |
|couchbase        |需要应用程序启用 searchEngine 选项                                                                   |


## 示例

每个示例将有三种形式：

- 常规形式
- 基于注解的形式
- use 形式（如果适用）

### 基本一元示例

常规：
```jdl
entity A

readOnly A
```

基于注解：
```
@readOnly
entity A
```

### 基本二元示例

常规：
```jdl
entity A

dto A with mapstruct
```

基于注解：
```
@dto(mapstruct)
entity A
```

使用 `use` 关键字：
```jdl
entity A

use mapstruct, serviceImpl, pagination for A
```

### all、* 示例

`all` 和 `*` 是别名。

常规：
```jdl
entity A
entity B

dto all with mapstruct
```

基于注解：
```
@dto(mapstruct)
entity A

@dto(mapstruct)
entity B
```

使用 `use` 关键字：
```jdl
entity A
entity B

use mapstruct, serviceImpl, pagination for *
```

### 包含排除的 all、* 示例（一元）

常规：
```jdl
entity A
entity B

skipClient * except A
```

基于注解：
```
entity A

@skipClient
entity B
```

使用 `use` 关键字：
```
entity A
entity B

use mapstruct, serviceImpl, pagination for * except A
```

### 包含排除的 all、* 示例（二元）

常规：
```jdl
entity A
entity B

dto all with mapstruct except A
```

基于注解：
```
entity A

@dto(mapstruct)
entity B
```

使用 `use` 关键字：
```
entity A
entity B

use mapstruct, serviceImpl, pagination for all except A
```

### 包含自定义值的选项

```
entity A
entity B

microservice all with mySuperMS
```

### 混合示例

常规：
```
entity A
entity B
entity C

readOnly B, C
dto * with mapstruct except C
service * with serviceClass except C
search A with elasticsearch
```

基于注解：
```
@dto(mapstruct)
@search(elastisearch)
@service(serviceClass)
entity A

@readOnly
@dto(mapstruct)
@service(serviceClass)
entity B

@readOnly
entity C
```


## 关于服务

不指定服务将创建一个资源类，该类将直接调用仓库接口。这是默认且最简单的选项，请参阅 A。

`service with serviceClass`（请参阅 B）将使资源调用服务类，该类将调用仓库接口。
`service with serviceImpl`（请参阅 C）将创建一个服务接口，该接口将被资源类使用。

该接口由一个具体类实现，该类将调用仓库接口。

除非确定，否则使用无服务是最简单的选项，适用于 CRUD。如果您将有很多业务逻辑使用多个仓库，请使用带有类的服务，这使它成为服务类的理想选择。JHipsters 不喜欢不必要的接口，但如果您喜欢它们，请使用带有 impl 的服务。

```
entity A
entity B
entity C

// A 没有服务
service B with serviceClass
service C with serviceImpl
```


## 微服务相关选项

从 JHipster v3 开始，可以创建微服务。您可以在 JDL 中指定一些选项来生成您的实体：
微服务的名称和搜索引擎。

您可以这样指定微服务的名称（JHipster 应用程序的名称）：

```
entity A
entity B
entity C
microservice * with mysuperjhipsterapp except C
microservice C with myotherjhipsterapp
search * with elasticsearch except C
```

第一个选项用于告诉 JHipster 您希望您的微服务处理您的实体，而第二个选项指定您希望如何以及是否搜索您的实体。


## 自定义注解

在 JDL 中可以使用自定义注解，例如：

```
@customAnnotation(customValue)
entity A
```

其主要用例是用于蓝图：有时，您需要为实体甚至字段提供自定义选项。
对于常规选项（`dto`、`pagination` 等），这些选项将像在 CLI 中一样在 JSON 中生成。
然而，对于自定义选项，它们将在转储的 JSON 中在 `options` 键下生成。

|------------------------|-----------|----------|--------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|

|JDL 选项名称（字段）   |默认值      |可能的值                                                                     |备注                                                                                                                                                                        |

|defaultValueComputed   |undefined   |生成列默认值的数据库函数，例如 "NOW(6)"                                      |这将使用给定的函数在数据库级别生成默认值                                                                                                                                      |
