在此页面中，您将了解 JDL 以及如何创建应用程序和周围的一切。


## 生成内容

### 使用文件

您可以使用 JDL 文件来生成实体：

- 创建一个扩展名为 '.jh' 或 '.jdl' 的文件，
- 声明您的应用程序、部署、实体和关系，或使用 [JDL-Studio](https://start.jhipster.tech/jdl-studio/) 或 [JHipster IDE](https://www.jhipster.tech/jhipster-ide/) 创建并下载文件，
- 如果您只是创建实体，那么在您的 JHipster 应用程序根文件夹中运行 `jhipster jdl my_file.jdl`。
- 如果您要创建应用程序，那么在一个文件夹中运行 `jhipster jdl my_file.jdl`。

然后, _就没有然后了_，您就完成了！

如果您在团队中工作，也许您希望有多个文件而不是一个。
我们添加了此选项，这样您就不需要手动将所有文件连接成一个，您只需运行：

```shell
jhipster jdl my_file1.jdl my_file2.jdl
```

如果您不想在导入 JDL 时重新生成您的实体，可以使用 `--json-only` 标志来跳过
实体创建部分，只在 `.jhipster` 文件夹中创建 json 文件。

```shell
jhipster jdl ./my-jdl-file.jdl --json-only
```

默认情况下，`jdl` 只重新生成已更改的实体，如果您希望重新生成所有实体，
那么请传入 `--force` 标志。
请注意，这将覆盖您对实体文件的所有本地更改：

```shell
jhipster jdl ./my-jdl-file.jdl --force
```

如果您想在项目中使用它，可以通过以下方式添加：

```shell
npm install jhipster-core --save
```

将其安装在本地，并将其保存在您的 `package.json` 文件中。

### 使用内联 JDL

生成内容的另一种方法是在 CLI 中传递 JDL 代码，如下所示：
`jhipster jdl --inline "application { config { baseName jhipster, applicationType microservice } }"`。

这种生成内容的方式在生成实体时特别有用。

现在，我们将从小的 JDL 内容开始，以了解生成内容的各种方式。
这里的重点是代码的生成。关于语法的解释在其他部分中进行。

下面是我们将使用的基本内容：

```jdl
application {
  config {
    baseName jhipster
    applicationType microservice
  }
}
```

这是一个名为 "jhipster" 的非常基本的微服务应用程序，我们将看到从此示例生成应用程序的各种方法。

您将看到，通过这个小示例，您已经设法从头开始创建一个应用程序。


## 使用远程 JDL 文件

您也可以在 `jdl` 命令中使用 URL。只需传递 URL 而不是文件名，如下所示

```shell
jhipster jdl https://my-site.com/my.jdl

jhipster jdl https://gist.githubusercontent.com/user/id/raw/id/myapp.jdl
```

您也可以通过只指定文件名从我们的 [JDL 示例仓库](https://github.com/jhipster/jdl-samples) 获取远程 JDL 文件，我们将自动解析 URL

```shell
jhipster jdl default.jdl
```


## 生成应用程序

如我们在上一个示例中所见，生成应用程序相当简单，让我们取上一个示例
并向其中添加更多内容：

```jdl
application {
  config {
    baseName jhipster
    applicationType microservice
    serverPort 4242
    buildTool gradle
  }
}
```

让我们分解一下：

- `application` 是说您要声明一个应用程序的关键字
- `config` 说您要指定配置
  - 我们稍后会看到您也可以在应用程序中声明实体
- `baseName`、`applicationType` 等是调整应用程序的关键字

这就是您使用 JDL 创建应用程序的方法。
要查看所有支持的应用程序选项，请转到[此页面](/jdl/applications)。


## 生成实体

生成实体稍显复杂一些。
您也可以转到专门的[实体页面](/jdl/entities-fields)以了解更多关于实体可以做什么。

### 生成基本实体

```jdl
entity A
```

此实体没有字段，甚至没有显式的表名（尽管 JHipster 会从实体名称为您设置一个）。
这是声明实体的最简单方法。

请注意，此形式等同于：

```jdl
entity A(a) {}
```

我们添加了表名和大括号。
默认情况下，JHipster 根据指定的实体名称生成表名。

在声明字段时需要大括号。

### 添加注释

这是向实体添加注释的方法：

```jdl
/**
 * 这是一个简单的实体
 */
entity A
```

如果后端是 Java，这将添加 Javadoc 注释。

### 应用程序中的实体

要在应用程序中只生成某些实体，可以使用 `entities` 关键字：

```jdl
application {
  config {}
  entities A, B
}

application {
  config {}
  entities C
}

entity A
entity B
entity C
```

这在微服务架构中特别有用。


## 生成字段

字段在实体中声明，通过为实体指定主体：

```jdl
entity MyEntity {
  name String
  closed Boolean
}
```

除了这两个类型外，还有更多类型，请在[实体和字段页面](/jdl/entities-fields)中查看。

### 添加注释和验证

与向实体添加注释的方式相同,我们也可以向字段添加注释:

```jdl
entity MyEntity {
  /** 我的字段 */
  name String required minlength(2) maxlength(50)
}
```

验证取决于字段类型,并且也在[实体和字段页面](/jdl/entities-fields)中详细说明。


## 枚举

枚举是具有固定值的类型:

```jdl
enum Type {
  A,
  B(b)
}

entity E {
  name Type
}
```

请注意枚举的值是可选的。

它们只有一个验证:`required`。

您可以查看专门的[枚举页面](/jdl/enums)以了解枚举的详细信息。


## 添加关系

实体之间的关系也是可用的,并使用 `relationship` 关键字声明。

```jdl
entity A
entity B

relationship OneToOne {
  A{a} to B{b}
}
```

这是我们可以看到的:

- `OneToOne` 是关系类型
  - 还有 `OneToMany`、`ManyToMany` 和 `ManyToOne`
- 我们声明关系的源和目标(从 `A` 到 `B`)
- 我们还在每个实体中声明注入的字段(`B` 中的 `a` 和 `A` 中的 `b`)
  - 这意味着关系是双向的

要了解更多关于关系的信息,您可以转到[专门的页面](/managing-relationships/)。

### 单向还是双向关系?

根据您设计模型的方式,您可能需要单向关系而不是双向关系。
这可以通过不指定注入字段来实现,如下所示:

```jdl
relationship OneToOne {
  A{a} to B
}
```

您也可以不指定它们,至少会默认注入一个(源)

```jdl
relationship OneToOne {
  A to B
}
```

### 关系注释和验证

关系也有注释、验证(只有一个:`required`):

```jdl
relationship OneToOne {
  A{a} to B{b required}
}
```

在这个例子中我们可以看到:

- `required` 用于指定关系的一方是否必需
  - 而不是 0..1,这个一对一关系要求一方不能为空

要了解更多关于关系的信息,您可以转到专门的[关系页面](/jdl/relationships)


## 选项

与在 CLI 中将选项应用于实体的方式相同,您也可以在 JDL 中执行此操作:

```jdl
entity A
entity B
entity C

readOnly A
dto * with mapstruct
service * with serviceImpl
paginate A, B with pager
```

这里发生了一些有趣的事情:

- `dto`、`paginate` 和 `service` 是二元选项,因为它们需要实体列表和值
  - `with` 用于指定选项值
  - 注意 `*` 表示该选项将应用于所有实体
- `readOnly` 是一元选项,这意味着此类选项仅接受实体列表

有多种方法可以声明实体列表:

- 您可以逐个枚举它们:`A, B, C`
- 您可以选择所有实体:`*` 或 `all`
  - 您可以有例外来排除实体:`service * with serviceImpl except A, B`

### 注解

注解是声明选项的另一种方式,让我们重写上一个示例:

```jdl
@readOnly
@dto(mapstruct)
@service(serviceImpl)
@paginate(pager)
entity A

@dto(mapstruct)
@service(serviceImpl)
@paginate(pager)
entity B

@dto(mapstruct)
@service(serviceImpl)
entity C
```

与 Java 或 TypeScript 类似,注解是"装饰器",是实体的选项。

此示例与前一个示例等效,因为它们可用于生成相同的代码。

要了解更多关于选项的信息,您可以转到[选项页面](/jdl/options)


## 部署

最后,还可以使用 `deployment` 关键字从 JDL 文件生成部署,与 JHipster v5.7 及更高版本兼容:

```jdl
deployment {
  deploymentType docker-compose
  appsFolders [foo, bar]
  dockerRepositoryName "yourDockerLoginName"
}
```

_要导入一个或多个部署,您不需要在 JHipster 应用程序文件夹中。_

部署在[它们自己的页面](/jdl/deployments)中进行了描述。

JHipster 部署有一个配置,其中包含所有其他属性的默认值,使用前面的语法将确保您的部署使用默认值(就像您没有做任何特定选择一样)。
生成的部署将具有:

- deploymentType: `docker-compose`
- appsFolders: `foo, bar`
- dockerRepositoryName: `yourDockerLoginName`
- serviceDiscoveryType: `consul`
- gatewayType: `SpringCloudGateway`
- directoryPath: `../`
- 等等。

现在,如果您想要一些自定义选项:

```jdl
deployment {
  deploymentType kubernetes
  appsFolders [store, invoice, notification, product]
  dockerRepositoryName "yourDockerLoginName"
  serviceDiscoveryType no
  istio autoInjection
  kubernetesServiceType Ingress
  kubernetesNamespace jhipster
  ingressDomain "jhipster.192.168.99.100.nip.io"
}
```

这些选项只是 JDL 中可用内容的一个示例。
完整的选项列表可在部署页面中找到,[这里](/jdl/deployments)。


## 常量

JDL 支持数值常量。
这里有一个例子:

```jdl
DEFAULT_MIN_LENGTH = 1
DEFAULT_MAX_LENGTH = 42
DEFAULT_MIN_BYTES = 20
DEFAULT_MAX_BYTES = 40
DEFAULT_MIN = 0
DEFAULT_MAX = 41

entity A {
  name String minlength(DEFAULT_MIN_LENGTH) maxlength(DEFAULT_MAX_LENGTH)
  content TextBlob required
  count Integer min(DEFAULT_MIN) max(DEFAULT_MAX)
}
```


## 导出到 JDL 文件

如果您的应用程序中已经有实体并且希望拥有 JDL 文件,别担心!您不必从头开始编写它,因为有一个子生成器可以为您完成。

在您的应用程序根文件夹中运行 `jhipster export-jdl <FILE_NAME>`,您将把所有应用程序、实体、关系和选项导出到单个 JDL 文件中。

注意:您也可以不向子生成器提供文件名,导出的 JDL 文件将以应用程序的基本名称命名。例如,如果您的应用程序名为 'mySuperApp',那么您的 JDL 文件将是 `mySuperApp.jdl`。
