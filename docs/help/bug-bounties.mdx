## 介绍

在 [JHipster 错误跟踪器](https://github.com/jhipster/generator-jhipster/issues)上开启的任何问题都可以有一个 "$$ bug-bounty $$" 标签：解决该问题的人将获得资金，根据问题不同可能是 $100、$200、$300 或 $500！


## 谁可以创建 bug 悬赏？

- [白银、黄金和铂金赞助商](/sponsors)
- [项目领导者和管理委员会](/team/)。


## bug 悬赏值多少钱？

在 "$$ bug-bounty $$" 标签旁边，应该有一个 "$100"、"$200"、"$300" 或 "$500" 标签，表示 bug 悬赏的价值。


## 当前开放的 bug 悬赏列表在哪里？

Bug 悬赏主要在主项目上可用，但也可以在 GitHub 上 JHipster 组织下的子项目上开放。

- [所有项目上开放的 bug 悬赏](https://github.com/search?l=&p=1&q=is%3Aissue+is%3Aopen+label%3A%22%24%24+bug-bounty+%24%24%22+user%3Ajhipster+state%3Aopen&ref=advsearch&type=Issues&utf8=%E2%9C%93)
- [主项目的开放 bug 悬赏](https://github.com/jhipster/generator-jhipster/labels/%24%24%20bug-bounty%20%24%24)
- [JHipster VueJS 子项目的开放 bug 悬赏](https://github.com/jhipster/jhipster-vuejs/labels/%24%24%20bug-bounty%20%24%24)

快乐验鸭 :-))


## 如何创建 bug 悬赏

一旦创建了问题，它可以通过两种操作获得 bug 悬赏标签：

- 白银或黄金赞助商添加评论要求添加 bug 悬赏标签，并在 GitHub 上提及其中一位[项目领导者](/team/)。
- [项目领导者](/team/)和[管理委员会](/team/)直接添加 bug 悬赏标签，因为他们认为这是一个重要的新功能、关键错误、长期存在的问题或耗时的任务。如果您正在处理一个问题，并且认为它值得悬赏，请不要犹豫向其中一位项目领导者询问。

要有效，bug 悬赏应该由[项目领导者](/team/)或[管理委员会](/team/)添加 [\$\$ bug-bounty \$\$](https://github.com/jhipster/generator-jhipster/labels/%24%24%20bug-bounty%20%24%24) 标签。它还应该有一个 "$100"、"$200"、"$300" 或 "$500" 标签来说明它的价值，但如果忘记了该标签，默认值为 "$100"。


## 如何获得奖金

一旦创建了 bug 悬赏，任何人都可以提供修复方案（甚至[项目领导者](/team/)和[管理委员会](/team/)！）。我们的目标是花费这笔钱，以便尽快修复某些问题。

为了申请奖金，您必须：

- 创建一个 Pull Request 来修复带有 "\$\$ bug-bounty \$\$" 标签的问题。
- 为了自动关闭问题，您必须有一个带有 `Fix` 关键字的提交消息。例如，`Fix #1234` 来关闭问题 `#1234`。
- 该 Pull Request 必须由核心团队的某人合并。如果有多个 Pull Request，核心团队成员会选择最新的一个或最好的一个 - 这取决于团队成员决定什么对项目最好。
- 然后您可以[在 JHipster OpenCollective 上添加 $100、$200、$300 或 $500 的支出](https://opencollective.com/generator-jhipster/expenses/new)。您必须在描述中添加您的 Pull Request 链接（例如：`$100 bug bounty claim for https://github.com/jhipster/generator-jhipster/pull/1234`）。
- 然后，您必须在您的 Pull Request 上添加评论，说明您申请了奖金，并附上您的 OpenCollective 支出链接。这是为了确保修复问题和申请奖金的是同一人。
- 该支出将由[项目领导者](/team/)或[管理委员会](/team/)验证，您将在您的 Paypal 账户上收到奖金。
