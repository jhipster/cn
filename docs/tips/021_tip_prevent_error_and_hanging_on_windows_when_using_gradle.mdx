# 防止在 Windows 上使用 Gradle 时出现错误/挂起

## /!\ 此提示自 JHipster v4.1.1 起已弃用，因为我们已升级到 Gradle 3.4

__Tip submitted by [@kaidohallik](https://github.com/kaidohallik)__

## 问题描述

如果在 Windows 上使用 cmd.exe 执行 Gradle 任务，则可能会发生错误或挂起：

1. 有时进程只是挂起
2. 有时会发生错误

```
FAILURE: Build failed with an exception.

* What went wrong:
Unable to process incoming event 'ProgressComplete ' (ProgressCompleteEvent)
```

## 何时出现问题

在某个命令向此 cmd.exe 窗口输出了一些关键符号和/或大量符号后，就会出现问题。
问题的出现取决于屏幕缓冲区大小高度。它越高，不出现错误/挂起的机会就越大。
但是即使使用最大的屏幕缓冲区大小高度（9999），问题也会重现。

## 解决方法

使用以下开关使用 Gradle 时，问题永远不会发生：

* `gradlew --info`
* `gradlew --debug`
* `gradlew --console plain`

有时可以通过以下操作防止问题：

* 增加 cmd.exe 窗口的屏幕缓冲区大小高度，例如增加到最大可能值 9999
* 打开新的 cmd.exe 窗口并使用它来执行 Gradle 任务

在 JHipster 应用程序中，此问题已在以下 Gradle 任务中重现：

* gulpConstantDev
* gulpBuildWithOpts
* npmInstall
* webpack

存在一个 hack，可以防止 JHipster 应用程序中出现此错误/挂起。只需将以下代码放入你的 `build.gradle`：

```
tasks.withType(NodeTask) {
    doLast {
        println()
    }
}
tasks.withType(com.moowork.gradle.node.npm.NpmTask) {
    doLast {
        println()
    }
}
```

## 附加信息

目前有一个关于所述错误/挂起问题的开放 [Gradle 问题](https://github.com/gradle/gradle/issues/882)。
在未来版本的 Gradle 中，所述错误/挂起问题可能不再存在。
