__Tip submitted by [@yelhouti](https://github.com/yelhouti)__

假设你需要在代码编译后更新前端变量的值。（例如：你的 IdP URL、用于联系的电子邮件...）

一种方法是将其作为 application.yml 的一部分，并让后端使用新的自定义端点将其返回给前端，就像我们在使用 OAuth2 时在 `AuthInfoResource.java` 中所做的那样。

另一种方法是创建一个名为 `env.js` 的新文件，它可以消除对此端点的需求，并提供更好的灵活性和更少的代码，如下所示：

```javascript
window.__env = window.__env || {};
window.__env.myDynamicVariable = 'http://127.0.0.1:8090';
```

下面的代码创建一个全局 `__env` 变量（如果尚未声明）。

它可以在你的 Angular 文件中访问，但我们建议通过 constants.ts 公开它，如下所示：
```typescript
@ts-ignore
export const MY_DYNAMIC_VARIABLE = window.__env.myDynamicVariable;
```
使用 Kubernetes 时，这种格式的文件可以挂载为 configMap，这就是为什么我们保持如此简单的键值语法。

现在我们需要确保 `index.html` 通过在 `<head>` 中添加 script 标签来加载它，如下所示：
```html
    ...
    <!-- jhipster-needle-add-resources-to-root - JHipster will add new resources here -->
    <script src="env.js"></script>
```
然后告诉 webpack 将其原样复制到打包的代码中：
```javascript
// jhipster-needle-add-assets-to-webpack - JHipster will add/remove third-party resources in this array
{ from: './<%= MAIN_SRC_DIR %>env.js', to: 'env.js' },
```

我们建议将该文件添加到 `.eslintignore.ejs` 以保持简洁的语法：
```
src/main/webapp/env.js
```
