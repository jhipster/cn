**Tip submitted by [@kaidohallik](https://github.com/kaidohallik)**

以下行为至少在 Visual Studio Code 中会发生。

如果生成全栈应用程序（不跳过服务器和客户端），前端开发者希望看到尽可能少的文件，并且仅在 IDE 中打开文件夹 `src/main/webapp/app`，那么 IDE 不会识别以 `app` 开头的导入。这些导入是红色的，开发者无法看到这些导入类的内容，也无法单击跳转到这些导入类。路径 `app` 是在生成的应用程序根文件夹中的 `tsconfig.json` 文件中定义的，因此如果打开某个子文件夹，则缺少此信息。


## 可能的解决方案 1

添加文件 `src/main/webapp/app/tsconfig.json`，其内容如下：

```json
{
    "extends": "../../../../tsconfig.json"
}
```

对于测试，添加文件 `src/test/javascript/spec/tsconfig.json`，内容相同：

```json
{
    "extends": "../../../../tsconfig.json"
}
```

之后，如果仅打开文件夹 `src/main/webapp/app` 或 `src/test/javascript/spec`，Visual Studio Code 会解析路径 `app`。


## 可能的解决方案 2

* 在应用程序根文件夹添加 Node 脚本 `remove-import-alias.js`，它将导入别名替换为相对路径：

```js
const fs = require('fs');

removeImportAlias = function(dir, level, additionalPath) {
  fs.readdirSync(dir).forEach(function(file) {
    if (fs.statSync(dir + file).isDirectory()) {
      removeImportAlias(dir + file + '/', level + 1, additionalPath);
    } else if (file.endsWith('.ts')) {
      fs.readFile(dir + file, 'utf8', function (err, content) {
        if (err) {
          console.log(err);
        } else {
          let path = '../'.repeat(level);
          if (additionalPath) {
            path += additionalPath;
          }
          if (!path) {
            path = './';
          }
          const newContent = content.replace(/import \{ (.*) \} from 'app\/(.*)';/g, `import { $1 } from '${path}$2';`);
          fs.writeFile(dir + file, newContent, 'utf8', function (err) {
            if (err) {
              console.log(err);
            }
          });
        }
      });
    }
  });
};

removeImportAlias(`./src/main/webapp/app/`, 0);
removeImportAlias(`./src/test/javascript/spec/`, 0, '../../../main/webapp/app/');
```

* 将 `remove-import-alias.js` 添加到 `.eslintignore`
* 运行添加的脚本：`node remove-import-alias.js`
* 从 `tsconfig.json` 文件的 `compilerOptions.paths` 部分删除 `app/*`
