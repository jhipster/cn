Elasticsearch 是一个选项，在您的数据库之上添加搜索功能。

这个选项有一些限制：

* 它只适用于 SQL 数据库和 MongoDB。Cassandra 和 Couchbase 支持将在未来添加（欢迎帮助！）。
* 在您的数据库和 Elasticsearch 之间没有自动复制机制，所以您可能会有不同步的数据。因此，您可能需要编写一些特定代码来同步您的数据，例如使用 Spring `@Scheduled` 注解，每天晚上运行。
  * 这也意味着如果您的数据库在您的应用程序之外被更改，您的搜索索引将不同步。[Elasticsearch Reindexer](https://www.jhipster.tech/modules/marketplace/#/details/generator-jhipster-elasticsearch-reindexer) JHipster 模块可以在这些情况下提供帮助。

当选择 Elasticsearch 选项时：

* Spring Data Elasticsearch 与 Spring Boot 的自动配置一起使用。它可以使用 `spring.elasticsearch.*` 配置属性进行配置。
* "repository" 包有一个新的子包，叫做 "search"，它保存所有 Elasticsearch 仓库。
* "User" 实体在 Elasticsearch 中被索引，您可以使用 `/api/_search/users/:query` REST 端点查询它。
* 当使用[实体子生成器](/creating-an-entity)时，生成的实体会自动被 Elasticsearch 索引，并在 REST 端点中使用。搜索功能也被添加到 UI 中，所以您可以在主 CRUD 屏幕中搜索您的实体。


## 在开发中使用

在开发中，JHipster 使用嵌入式 Elasticsearch 实例运行。如果您设置了 `SPRING_DATA_URIS` 环境变量（或在您的 `application-dev.yml` 中添加了 `spring.elasticsearch.uris` 属性），您也可以使用外部 Elasticsearch 实例。

运行外部 Elasticsearch 实例的最简单方法是使用提供的 Docker Compose 配置：

```shell
docker-compose -f src/main/docker/elasticsearch.yml up -d
```

然后设置一个环境变量指向它：

```shell
export SPRING_DATA_URIS=http://localhost:9200
```

## 在生产中使用

在生产中，JHipster 期望一个外部 Elasticsearch 实例。默认情况下，应用程序寻找在 localhost 上运行的 Elasticsearch 实例。这可以通过在 `application-prod.yml` 文件中使用标准的 Spring Boot 属性进行配置。


## 在 Heroku 上使用

在 Heroku 上，[Bonsai Elasticsearch](https://elements.heroku.com/addons/bonsai) 被配置为一个附加组件。JHipster 被自动配置为与其通信。

不幸的是，截至 JHipster 7.9.3，Elasticsearch [在 Heroku 上无法开箱即用](https://github.com/jhipster/generator-jhipster/issues/20315)。要解决这个问题，您可以使用 Elasticsearch 创建 Docker 镜像并将其部署到可以运行它的地方，或者您可以使用 Elastic Cloud。我们不会自动配置 [Elasticsearch 附加组件](https://elements.heroku.com/addons/foundelasticsearch)，因为其最便宜的计划是 67 美元/月，这似乎有点贵。


## 使用 Elastic Cloud

您可以在 Elastic Cloud 上[开始免费试用](https://cloud.elastic.co/registration)。登录后，创建一个部署。使用默认设置，选择 **7.17.7** 作为版本，并按 **创建部署**。

**警告**：使用最新版本将导致“无法解析响应主体”错误。

从下一个屏幕下载您的凭据并点击 **继续**。然后，从菜单中选择 **管理此部署** 并复制 Elasticsearch 端点。

在 Heroku 上将凭据和端点 URL 设置为新的 `ELASTIC_URL` 环境变量。

```shell
heroku config:set ELASTIC_URL=https://elastic:<password>@<endpoint-url>
```

然后，修改 `heroku.gradle` 来移除 Bonsai 的解决方案（不再工作）并更新 `application-heroku.yml` 以使用 `ELASTIC_URL`：

```yaml
spring:
  ...
  elasticsearch:
    uris: ${ELASTIC_URL}
```

将您的应用程序重新部署到 Heroku，一切都应该按预期工作。
