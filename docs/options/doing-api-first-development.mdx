# <i class="fa fa-search"></i> 进行 API 优先开发

当生成 JHipster 应用并被提示“您想要使用哪些其他技术？”时，选择 `API first development using OpenAPI-generator` 选项来利用 [OpenAPI-generator](https://github.com/OpenAPITools/openapi-generator)，如下所示：

```shell
# ... other prompts answered ...
? Which other technologies would you like to use? (Press <space> to select, <a> to toggle all, <i> to invert selection,
and <enter> to proceed)
 ◯ Apache Kafka as asynchronous messages broker
 ◯ Apache Pulsar as asynchronous messages broker
❯◉ API first development using OpenAPI-generator
```

此选项将配置构建工具，[Maven 或 Gradle](https://openapi-generator.tech/docs/plugins)，从 OpenAPI (Swagger) 规范 (OAS) 文件生成 API 代码。支持 Swagger v2 和 OpenAPI v3 格式。

## API 优先开发的理由

在 API 优先开发中，也称为“合约优先开发”，API 规范是首先编写的，然后从 API 规范生成代码。这与从代码生成文档形成对比。

API 优先开发提供以下优势：

- API 是为消费者设计的，而不是作为实现的结果。
- 规范文件可以用于在开发中模拟新的服务器端点，进一步解耦前端和后端。
- 使用规范文件不需要一个活动的服务器。

## 默认配置

此指南将使用 JHipster 的默认配置，该配置利用了 Spring 的委托模式。[OpenAPI Generator for Spring](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/spring.md) 生成的代码将产生用于实现的模型和委托。

插件的默认配置如下所示（Maven），并在 `pom.xml` 的项目级 `build` 配置文件中定义。JHipster 为 Gradle 项目适配了该配置。

```xml
<plugin>
    <!--
        Plugin that provides API-first development using openapi-generator-cli to
        generate Spring-MVC endpoint stubs at compile time from an OpenAPI definition file
    -->
    <groupId>org.openapitools</groupId>
    <artifactId>openapi-generator-maven-plugin</artifactId>
    <version>${openapi-generator-maven-plugin.version}</version>
    <executions>
        <execution>
            <goals>
                <goal>generate</goal>
            </goals>
            <configuration>
                <inputSpec>${project.basedir}/src/main/resources/swagger/api.yml</inputSpec>
                <generatorName>spring</generatorName>
                <apiPackage>demo.jhipster.myapp.web.api</apiPackage>
                <modelPackage>demo.jhipster.myapp.service.api.dto</modelPackage>
                <supportingFilesToGenerate>ApiUtil.java</supportingFilesToGenerate>
                <skipValidateSpec>false</skipValidateSpec>
                <configOptions>
                    <!-- the delegatePattern is only available to the spring generator -->
                    <delegatePattern>true</delegatePattern>
                    <title>jhipster</title>
                    <useSpringBoot3>true</useSpringBoot3>
                </configOptions>
            </configuration>
        </execution>
    </executions>
</plugin>
```

> ℹ️ JHipster 用户始终被鼓励根据环境的具体情况或组织内采用的标准来调整构建工具。JHipster 为项目提供了正确的基础，并提供了在大规模环境中经过测试的工具和实践。如果 JHipster 使用 Spring 委托模式不是组织的标准，可以删除 `configOption:delegatePattern`（默认为 `false`）。
>
> 如常，用户需要理解对 JHipster 默认行为进行更改的影响。正如 JHipster 无法教用户如何使用 Spring，对 Spring 的更改可能导致 JHipster 无法记录的行为。

## 使用 openapi-generator-maven-plugin

OpenAPI 规范 (OAS) 文件由生成器从插件的 `inputSpec` 元素中定义的文件读取。JHipster 的 OAS 默认位置是 `src/main/resources/swagger/api.yml`。插件从 OAS 生成接口和数据传输对象 (DTO) 供实现使用。接口具有默认方法，这些方法会响应 `501 Not implemented` HTTP 状态和空主体。

### 使用 OpenAPI 规范开发 API

本指南将使用 OpenAPI 的经典宠物店规范以简化操作，因为编写 OAS 超出了本指南的范围。API 开发者可以使用 [swagger-editor](http://editor.swagger.io) 等工具编写 OAS 并将其放在 `src/main/resources/swagger/api.yml` 中。许多 IDE 也提供了 OAS 编辑工具。

#### 专业提示

JHipster 在选择 `API first development using OpenAPI-generator` 时，为 Swagger Editor 提供了位于 `src/main/docker/swagger-editor.yml` 的 Docker Compose 描述符。要在本地使用此编辑器，请运行 `docker compose -f src/main/docker/swagger-editor.yml up -d`。

### JHipster 的分层架构和 ArchUnit 技术结构测试

在实现由 OpenAPI Generator 插件生成的委托之前，请花时间审查和理解 JHipster 的分层架构设计。这种架构由 [TNG Tech 的 ArchUnit](https://www.archunit.org/motivation) 进行测试，并在 `src/test/java/com/mycompany/myapp/TechnicalStructureTest.java` 中定义。必须遵循委托类的正确实现，以便不违反这种分层架构。

## 实现指南

### Pet Store v3

以下，本指南将基于 OpenAPI Initiative 的 [JHipster 版本的 Expanded Pet Store v3](/doing-api-first-development/api/api.yml)（[在此处找到](https://github.com/OAI/OpenAPI-Specification/blob/main/examples/v3.0/petstore-expanded.yaml)）。这个 JHipster 版本将 `server:url` 设置为 JHipster 默认的 `http://localhost:8081/api`（其中端口默认为 `8081`，生成的控制器的基路径为 `/api`，与默认的 `SecurityConfiguration#filterChain(HttpSecurity,  MvcRequestMatcher.Builder)` 实现匹配）。

### 生成服务器源代码

```bash
./mvnw generate-sources
```
或对于 gradle：
```bash
./gradlew openApiGenerate
```

### 验证工具

验证 `target/generated-sources` 中的生成类在类路径上可用于实现。大多数 IDE 会查找并自动配置这些目录。请参阅 IDE 的文档来解决任何问题。

### 审查生成的类

花一些时间审查 `generated-sources`。

```text
target/generated-sources
└── openapi
    └── src
        └── main
            └── java
                └── demo
                    └── jhipster
                        ├── service
                        │   └── api
                        │       └── dto
                        │           ├── Error.java
                        │           ├── NewPet.java
                        │           └── Pet.java
                        └── web
                            └── api
                                ├── ApiUtil.java
                                ├── PetsApi.java
```

> ⚠️OpenAPI Generator 负责创建 DTO（“模型”）和委托。实现**不得**放在 `target/generated-sources` 中。这些类随时可能被生成，因此**不应该**提交到源代码控制。

#### 实现委托

实现类将使用 Spring `@Service` 注解。

##### 创建 API 包

在 `web` 层中创建 `api` 包，即 `mkdir -p src/main/java/demo/jhipster/web/api`。请参阅[专业提示](#pro-tip-1)。

##### 重写 PetApi 的方法

OpenAPI Generator 为 OAS 中定义的每个 `paths` 元素在 `demo.jhipster.web.api.PetApi` 接口中使用 `operationId` 创建 `@RequestMapping` 方法。OAS 的编写超出了本指南的范围，但请在 `demo.jhipster.web.api.PetApi` 中观察每个 `@RequestMapping` 注解和生成的方法。一个显著的例子是 `operationId: find by pet id` 和生成的接口方法 `findPetById`，在下面的例子中被重写：

```java
package demo.jhipster.web.api;

import demo.jhipster.service.api.dto.Pet;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

@Service
public class PetsApiDelegateImpl implements PetsApiDelegate {

    private final List<Pet> pets = new ArrayList<>();

   @Override
    public ResponseEntity<Pet> findPetById(Long id) {
        Pet pet = getPets().stream().filter(p -> id.equals(p.getId())).findAny().orElse(null);
        if (pet != null) {
            return ResponseEntity.ok(pet);
        }
        return new ResponseEntity<>(null, HttpStatus.NOT_FOUND);
    }

    private List<Pet> getPets() {
        Pet pet0 = new Pet();
        pet0.setId(1L);
        pet0.setName("Chessie Cat");
        pet0.setTag("cat");
        pets.add(pet0);
        return pets;
    }
}
```

##### 专业提示

如果 OpenAPI Generator 没有产生所需的类型或代码，请查看文档。JHipster 默认设置通常适应大多数 API。考虑查看[提供的插件](https://github.com/OpenAPITools/openapi-generator/tree/master/modules/openapi-generator-maven-plugin)的 `importMappings` 和 `typeMappings` 选项以获得额外的灵活性。

### 在开发中模拟端点

向 Delegate 接口提供 `NativeWebRequest` bean 可以为尚未被重写的方法返回示例响应体。端点仍然会响应 `501 Not Implemented` HTTP 状态码，但示例响应可能对在实际实现之前模拟端点很有用。

> ℹ️ OAS 示例提供了文档中的示例响应体。每个操作的 `schemas` **必须**定义一个 `example`，以便 OpenAPI Generator 生成响应体。以下代码片段很有帮助：

```yaml
# ...
# trimmed for brevity
components:
  schemas:
    Pet:
      allOf:
        - $ref: '#/components/schemas/NewPet'
        # trimmed for brevity
      example:
        name: Chessie Cat
        id: 1
        tag: cat
```

#### 重写 Delegate 实现的默认构造函数

在正确定义 OAS 后，将 `NativeWebRequest` 添加到实现中，如下所示。以下示例实现中显示了每个步骤，并遵循：

1. 向实现添加 `NativeWebRequest request` 属性。
2. 重写默认的无参数构造函数，`public PetsApiDelegateImpl(NativeWebRequest request){...}`
3. 重写 `demo.jhipster.web.api.PetsApiDelegate#getRequest()` 返回 `Optional<NativeWebRequest>`。

```java
package demo.jhipster.web.api;

import demo.jhipster.service.api.dto.Pet;
// imports trimmed for brevity

@Service
public class PetsApiDelegateImpl implements PetsApiDelegate {

    private final NativeWebRequest request;
    private final List<Pet> pets = new ArrayList<>();

    public PetsApiDelegateImpl(NativeWebRequest request) {
        this.request = request;
    }

    /**
     * Provides the NativeWebRequest to the implementation class.
     */
    @Override
    public Optional<NativeWebRequest> getRequest() {
        return Optional.ofNullable(request);
    }

    @Override
    public ResponseEntity<Pet> findPetById(Long id) {
        // previously shown above
    }

    /**
     * Implements the method used at the RequestMapping of /pets in the PetsApi.
     * <p>
     * Returns an HTTP Status of 501 Not Implemented with an example response body defined
     * OpenAPI Specification file and generated by the OpenAPI Generator for Spring.
     */
    @Override
    public ResponseEntity<List<Pet>> findPets(List<String> tags, Integer limit) {
        return PetsApiDelegate.super.findPets(tags, limit);
    }

    private List<Pet> getPets() {
        // previously shown above
    }
}
```

### 身份验证

JHipster 默认情况下在 `demo.jhipster.config.SecurityConfiguration#filterChain(HttpSecurity,  MvcRequestMatcher.Builder)` 中保护 `/api/**`，需要身份验证，例如 `.requestMatchers(mvc.pattern("/api/**")).authenticated()`。

身份验证超出了本指南的范围。但是，查看 `demo.jhipster.security.jwt.TokenAuthenticationIT` 集成测试可以为在 Insomnia、Postman、curl 和其他 HTTP 工具中测试身份验证提供一些见解。例如，可以使用 Docker 生成 JWT Bearer 令牌，如下所示：

```shell
docker run --rm --name jwt-cli bitnami/jwt-cli encode \
-S b64:<JHIPSTER_JWT_SECRET> \
-P 'auth=["ROLE_ADMIN"]' \
-e=$(date -v+60S +%s) \ # man date; produce an epoch system time + 60 seconds, macOS date command shown
-s anonymous \
-A HS512 \
--no-typ
```

这将为 API 调用生成一个 Bearer 令牌，如下所示：

```shell
curl -v -H "Accept: application/json" -H "Authorization: Bearer <ENCODED_TOKEN>" http://localhost:8081/api/pets/1
```
