在 JHipster 中可以在两个层面使用缓存：

- 使用 Spring Cache 抽象，这是在生成应用程序时的一个特定问题，使用 Spring Boot `@EnableCaching` 注解。这需要根据您的具体业务需求进行调整，并且在比 Hibernate 二级缓存更高的层面工作。
- 作为 Hibernate 二级缓存，缓存解决方案可以为您的应用程序提供巨大的性能提升，这也是人们通常在 JHipster 中所做的。请注意，这个选项仅适用于 SQL 数据库，并且如果您选择使用 Spring Cache。

Spring Cache 和 Hibernate 二级缓存将使用相同的缓存解决方案，但不在同一层面工作：我们不建议对相同对象同时使用两者，因为这将使缓存失效问题变得更加复杂。相反，我们建议您使用：

- Spring Cache 用于更高层次或聚合对象，就像您通常在 DTO 中使用的那样
- Hibernate 二级缓存用于映射到数据库的实体，以减少 SQL 请求的数量

JHipster 支持以下缓存实现：
1. Ehcache，
2. Caffeine，
3. Hazelcast，
4. Infinispan，
5. Memcached，
6. Redis。

它们都在下面有详细介绍。


## 通用配置

缓存在 `CacheConfiguration` 类中配置，也可以使用 JHipster [通用应用属性](/common-application-properties/)进行调整。


## 使用 Ehcache 缓存

[Ehcache](http://www.ehcache.org/) 是 JHipster 中单体应用的默认缓存。Ehcache 启动非常快，所以它是“正常”单体应用的完美解决方案。

在 JHipster 中，Ehcache 无法作为分布式缓存工作，因为它没有允许以编程方式添加新节点的 API。

Ehcache 在 `CacheConfiguration` Spring 配置 bean 中配置，该 bean 在 JHipster [通用应用属性](/common-application-properties/)中定义了 2 个属性（`time-to-live-seconds` 和 `max-entries`）。可以在您应用程序的特定 `ApplicationProperties` Spring 配置 bean 中添加更多属性。

默认情况下，`time-to-live-seconds` 在 `dev` 和 `prod` 模式中的默认值都是 3600 秒（1 小时），`max-entries` 在 `dev` 模式中的默认值是 100 个条目，在 `prod` 模式中是 1,000 个条目。

这些值应该根据您的具体业务需求进行调整，JHipster 监控屏幕可以帮助您更好地了解您应用程序中的缓存使用情况。请也参阅 Ehcache 文档来精细调整这些值。


## 使用 Caffeine 缓存

[Caffeine](https://github.com/ben-manes/caffeine) 是一个[高性能](https://github.com/ben-manes/caffeine/wiki/Benchmarks)、[接近最优](https://github.com/ben-manes/caffeine/wiki/Efficiency)的缓存库，是 JHipster 中单体应用使用的 Ehcache 的替代品。

与 Ehcache 类似，Caffeine 无法作为分布式缓存工作。

Jhipster 为 Caffeine 生成了与 Ehcache 相同的默认配置。但是，您可能希望添加额外的选项来根据您的需求进行精细调整。Caffeine 缓存配置在 `CacheConfiguration` Spring 配置 bean 中完成，而您应用程序的特定属性可以添加到 `ApplicationProperties` bean 中。您可能会发现以下三个文件在定义您自己的 Caffeine 配置时很有用。

- 我们在 `CacheConfiguration` bean 中使用 [`CaffeineConfiguration`](https://github.com/ben-manes/caffeine/blob/master/jcache/src/main/java/com/github/benmanes/caffeine/jcache/configuration/CaffeineConfiguration.java) 类来添加 Caffeine 属性。

- 您可能会发现 [`TypesafeConfigurator`](https://github.com/ben-manes/caffeine/blob/master/jcache/src/main/java/com/github/benmanes/caffeine/jcache/configuration/TypesafeConfigurator.java) 和 [`reference.conf`](https://github.com/ben-manes/caffeine/blob/master/jcache/src/main/resources/reference.conf) 作为所有支持的 Caffeine 属性的参考很有用。


## 使用 Hazelcast 缓存

[Hazelcast](https://hazelcast.com/) 可以作为本地缓存（如 Ehcache）工作，也可以作为分布式缓存工作。因此：

- 它是微服务的默认选项，因为我们期望微服务能够扩展
- 它是网关的默认选项，因为我们期望它们能够扩展，并且因为 Hazelcast 用于分发[网关限率信息](/api-gateway/#rate-limiting)
- 在单体应用中使用时，Hazelcast 需要手动配置 [JHipster Registry](/jhipster-registry/) 才能扩展

对于扩展应用程序，Hazelcast 将使用配置的服务发现来查找新节点，并水平扩展。对于微服务和网关，这将适用于 JHipster Registry 和 Consul，对于单体应用，这只有在您手动配置 JHipster Registry 时才有效。

当添加新节点时，它将向服务发现注册自己（例如，它将在 JHipster Registry 中可用），并查找相同类型的其他节点。如果它找到一个或多个相同类型的节点，它将与它们创建一个集群缓存：您应该在每个节点的日志中看到一条消息，如下面的例子：

```
[172.18.0.10]:5701 [dev] [3.7]
Members [4] {
Member [172.18.0.10]:5701 - 3cbddfcd-0229-4cd5-be55-4611927a9071 this
Member [172.18.0.5]:5701 - 204d457d-f6fe-43f2-8e8d-497e96b3f08e
Member [172.18.0.14]:5701 - 7804d535-86fb-46be-b2a5-d7801dc6a4df
Member [172.18.0.11]:5701 - 6114ae28-56cd-4840-a575-4d73a6003744
}
```

为了与 Hazelcast 更好地配合使用，JHipster 包含对 Hazelcast Management Center 的支持：

- 请注意，您只能免费监控 2 个节点，因为这是一个专有产品。但这已经足够测试您的应用程序了。
- 它使用 JHipster [通用应用属性](/common-application-properties/)配置，使用键 `jhipster.cache.hazelcast.management-center`，在您的 `application-dev.yml` 和 `application-prod.yml` 文件中。请注意，默认情况下它是关闭的。
- JHipster 生成一个 Docker Compose 配置来运行 Hazelcast Management Center。请阅读我们的 [Docker Compose 文档](/docker-compose/)，并使用 `docker-compose -f src/main/docker/hazelcast-management-center.yml up -d` 运行应用程序。


## 使用 Infinispan 缓存

[Infinispan](https://infinispan.org/) 是一个高性能缓存解决方案，可以作为内存本地缓存以及集群缓存工作。它提供对多种缓存模式的支持：
  - [本地](https://infinispan.org/docs/9.4.x/user_guide/user_guide.html#local_mode)
  - [无效化](https://infinispan.org/docs/9.4.x/user_guide/user_guide.html#invalidation_mode)
  - [分布式](https://infinispan.org/docs/9.4.x/user_guide/user_guide.html#replicated_mode)
  - [复制](https://infinispan.org/docs/9.4.x/user_guide/user_guide.html#distribution_mode)
  - [分散](https://infinispan.org/docs/9.4.x/user_guide/user_guide.html#scattered_mode)

在 JHipster 中，Infinispan 可以用于：

- 作为 Spring Cache 抽象的实现
- 作为 Hibernate 二级缓存

以下是预配置的默认配置：

- 实体在无效化缓存模式下操作
- 对于应用程序特定的缓存，预定义了三种缓存配置
  - **local-app-data** 用于缓存节点本地数据
  - **dist-app-data** 用于跨节点分布式缓存数据（副本数量由分布式副本计数决定）
  - **repl-app-data** 用于跨节点复制数据

可以使用 JHipster [通用应用属性](/common-application-properties/)精细调整缓存中每个单独操作模式的逐出、生存时间和最大条目数，以及分布式模式的副本计数。为应用程序特定的缓存精细调整 `jhipster.cache.infinispan` 中的属性，为 Hibernate 的二级缓存精细调整 `spring.jpa.properties`。

如果启用了 JHipster Registry，那么节点列表将从注册表中填充。如果没有启用 JHipster Registry，节点发现将基于 Infinispan Jar 包中的 `config-file` 中定义的默认传输设置。Infinispan 原生支持大多数平台的发现，如 Kubernets/OpenShift、AWS、Azure 和 Google。

尽管 Infinispan 9.0.0.Final GA 及更高版本通过使用原生 KUBE_PING 发现增加了在 Kubernetes 和 OpenShift 上运行 Infinispan 嵌入式缓存应用程序的支持，但 Hibernate 依赖关系尚未更新到 9.x 版本，因此在 Kubernetes 和 OpenShift 上不支持原生发现。但是，您可以通过使用 JHipster Registry 进行实例发现来运行应用程序。


## 使用 Memcached 缓存

[Memcached](https://memcached.org/) 是一个开源分布式缓存。它与 JHipster 支持的其他缓存实现相比有很大不同：

- Memcached 无法作为 Hibernate 二级缓存工作，它仅支持 Spring Cache 抽象。
- Memcached 仅与远程服务器一起工作，没有本地缓存。因此，您的对象总是被序列化/反序列化并通过网络传输，这意味着如果您有一小组可以适合内存的对象，它可能效率较低。
- 它能够扩展，并且操作成本低廉。大多数大型云提供商如 Heroku、GCP 或 AWS 都支持 Memcached。因此，与其他缓存实现相比，拥有一个分布式（和便宜的）Memcached 集群要容易得多。

JHipster 使用流行的 [Xmemcached](https://github.com/killme2008/xmemcached) Java 客户端访问 Memcached，并使用通常的 JHipster [通用应用属性](/common-application-properties/)配置其最重要的属性。

请注意，每个缓存都必须在 `CacheConfiguration` 配置 bean 内配置为特定的 Spring bean。

由于 Memcached 需要在其类加载器中序列化/反序列化对象，它在使用 Spring Boot devtools（使用特定的类加载器进行应用程序类的热重载）时不起作用。这就是为什么 Memcached 在 dev 模式下默认关闭的原因。

与 JHipster 一样，提供了一个 Docker Compose 配置，以便您可以在您的机器上启动 Memcached 服务器。为了使用它，请运行 `docker-compose -f src/main/docker/memcached.yml up -d`。


## 使用 Redis 缓存

[Redis](https://redis.io/) 是一个开源的内存数据结构存储，可以用作高性能的缓存解决方案。根据您的配置，您可以选择使用 Redis 作为单个服务器节点或作为分布式缓存。

JHipster 使用 [Redisson](https://redisson.org/) 作为 redis Java 客户端，主要有 2 个原因：
- 它被 Redis 强烈推荐
- 它提供了 JCache (JSR-107) 实现

它允许与其他缓存保持一致，因为我们在可用时使用 JCache 实现，并在 Spring 缓存和 Hibernate 二级缓存之间共享相同的 redis 连接。
