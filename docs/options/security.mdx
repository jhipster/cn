要在单页 Web 应用程序（如 JHipster 生成的应用程序）中使用 Spring Security，您需要 XHR 登录/注销/错误视图。我们已经配置了 Spring Security 以正确使用这些视图，并为您生成所有 JavaScript 和 HTML 代码。

默认情况下，JHipster 带有两个不同的用户：

* "user"，这是一个具有 "ROLE_USER" 授权的普通用户。默认密码是 "user"。
* "admin"，这是一个具有 "ROLE_USER" 和 "ROLE_ADMIN" 授权的管理员用户。默认密码是 "admin"。

"ROLE_USER" 和 "ROLE_ADMIN" 这两个授权对实体提供相同的访问权限，这意味着 "user" 被授权执行与 "admin" 相同的 CRUD 操作。当应用程序投入生产时，这种行为可能会成为问题，因为 "user" 可以删除任何实体。有关改进访问控制的更多详细信息，请参见此[博客文章](https://blog.ippon.tech/improving-the-access-control-of-a-jhipster-application/)。

出于安全原因，您应该在生产环境中更改这些默认密码。


## JSON Web Tokens (JWT)

[JSON Web Token (JWT)](https://jwt.io/) 身份验证是一种无状态安全机制，因此如果您希望在多个不同服务器上扩展应用程序，这是一个不错的选择。

请注意，这是使用[微服务架构](/microservices-architecture/)时的默认选项。

这种身份验证机制在 Spring Security 中默认不存在，它是 JHipster 对[Java JWT 项目](https://github.com/jwtk/jjwt)的特定集成。

这个解决方案使用一个安全令牌来保存用户的登录名和权限。由于令牌是签名的，用户无法篡改它。

JHipster 自动跟踪无效 JWT 作为自定义应用程序指标，请参阅[监控文档](/monitoring/#security-metrics)。

### 保护 JWT

- JHipster 使用一个密钥，可以使用两个 Spring Boot 属性进行配置：`jhipster.security.authentication.jwt.secret` 和 `jhipster.security.authentication.jwt.base64-secret`。
第二个选项使用 Base64 编码的字符串，因此被认为更加安全，因此推荐使用。如果同时配置了两个属性，出于遗留原因，将使用 `secret` 属性（安全性较低）。
如果您不使用 Base64 属性，在应用程序启动时将显示警告。
- 这些密钥应该具有最少 512 位的长度：如果它们不够长，您将无法使用它们登录。如果发生这种情况，控制台上将有明确的警告来解释该问题。
- 密钥在 `application-*.yml` 文件中配置。由于这些密钥必须保密，您**应该**为生产环境配置文件以安全的方式存储它们。
可以使用常用的 Spring Boot 属性配置进行设置：使用 Spring Cloud Config 服务器（如 [JHipster Registry](/jhipster-registry/)），
使用环境变量，甚至是系统管理员通过 SCP 将特定的 `application-prod.yml` 文件放在与应用程序可执行 WAR 文件相同的目录中。
- 您**应该**更改默认的 "user" 和 "admin" 密码。最简单的方法是部署您的应用程序，以 "user/user" 然后 "admin/admin" 登录，并为每个用户使用 "账户 > 密码" 菜单更改密码。


## 基于会话的身份验证

这是 "经典" 的 Spring Security 身份验证机制，但我们已经显著改进了它。它使用 HTTP Session，因此它是一个有状态机制：如果您计划在多个服务器上扩展应用程序，您需要一个具有粘性会话的负载均衡器，以便每个用户停留在同一台服务器上，或者考虑添加 [Spring Session](https://spring.io/projects/spring-session) 将会话存储在数据库中而不是内存中。

### 保护基于会话的身份验证

- 对于记住我的身份验证，记住我密钥在 `application-dev.yml` 和 `application-prod.yml` 文件中配置，作为 `jhipster.security.remember-me.key` 属性。由于这个密钥必须保密，您**应该**为生产环境配置文件以安全的方式存储它。可以使用常用的 Spring Boot 属性配置进行设置：使用 Spring Cloud Config 服务器（如 [JHipster Registry](/jhipster-registry/)），使用环境变量，甚至是系统管理员通过 SCP 将特定的 `application-prod.yml` 文件放在与应用程序可执行 WAR 文件相同的目录中。
- 您**应该**更改默认的 "user" 和 "admin" 密码。最简单的方法是部署您的应用程序，以 "user/user" 然后 "admin/admin" 登录，并为每个用户使用 "账户 > 密码" 菜单更改密码。

### 改进的记住我机制

我们已经修改了 Spring Security 记住我机制，使您有一个唯一的令牌，该令牌存储在您的数据库中（SQL 或 NoSQL 数据库，取决于您在生成期间的选择！）。我们还存储比标准实现更多的信息，因此您可以更好地了解这些令牌的来源：IP 地址、浏览器、日期...我们还生成一个完整的管理界面，您可以在其中使会话无效，例如如果您忘记在另一台计算机上注销。

### Cookie 盗用保护

我们已经添加了一个非常完整的 cookie 盗用保护机制：我们将您的安全信息存储在 cookie 中，以及数据库中，每次用户登录时我们都会修改这些值并检查它们是否被篡改。这样，如果有人盗取了您的 cookie，他们最多只能使用一次。


## OAuth 2.0 和 OpenID Connect

OAuth 是一个有状态安全机制，像 HTTP Session 一样。Spring Security 提供了出色的 OAuth 2.0 和 OIDC 支持，这被 JHipster 所利用。如果您不确定 OAuth 和 OpenID Connect (OIDC) 是什么，请参见 [What the Heck is OAuth?](https://developer.okta.com/blog/2017/06/21/what-the-heck-is-oauth)

### Keycloak

[Keycloak](https://www.keycloak.org) 是与 JHipster 配置的默认 OpenID Connect 服务器。

要登录您的应用程序，您需要让 [Keycloak](https://www.keycloak.org) 运行起来。JHipster 团队为您创建了一个 Docker 容器，其中包含默认的用户和角色。使用以下命令启动 Keycloak。

```shell
docker-compose -f src/main/docker/keycloak.yml up
```
或者，您可以使用 `npm` 如下：

```shell
npm run docker:keycloak:up
```

如果您想在 Docker Compose 中使用 Keycloak，请务必阅读我们的 [Docker Compose 文档](/docker-compose/)，并为 Keycloak 正确配置您的 `/etc/hosts`。

:::note
**关于 JHipster 7.8.1 和 Apple Silicon (M1) 上的 Keycloak 16.1.0 的注意事项**

Keycloak v18 之前的版本可能在 Apple Silicon 的兼容模式下表现异常，解决方案不是很明显。您可以在本地构建 Keycloak 镜像来解决这个问题：

```shell
git clone git@github.com:keycloak/keycloak-containers.git
cd keycloak-containers/server
git checkout 16.1.0
docker build -t jboss/keycloak:16.1.0 .
```

:::

`src/main/resources/config/application.yml` 中的安全设置是为这个镜像配置的。请参阅上面关于 `/etc/hosts` 的注意事项，并注意 `issuer-uri` 可能需要更改

```yaml
spring:
  ...
  security:
    oauth2:
      client:
        provider:
          oidc:
            issuer-uri: http://localhost:9080/auth/realms/jhipster
            # localhost 将绑定到客户机（容器），而不是主机
            # 要将 Keycloak 作为守护进程运行，即 npm run docker:keycloak:up，必须编辑 /etc/hosts
            # 并且 issuer-uri 应该如下：
            # issuer-uri: http://keycloak:9080/auth/realms/jhipster
        registration:
          oidc:
            client-id: web_app
            client-secret: web_app
            scope: openid,profile,email
```

Keycloak 默认使用嵌入式 H2 数据库，因此如果您重启 Docker 容器，您将丢失创建的用户。要保留您的数据，请阅读 [Keycloak Docker 文档](https://hub.docker.com/r/jboss/keycloak/)。一个解决方案，同时保留 H2 数据库，是执行以下操作：

- 添加一个将被持久化的卷：`./keycloak-db:/opt/jboss/keycloak/standalone/data`
- 将迁移策略从 `OVERWRITE_EXISTING` 更改为 `IGNORE_EXISTING`（在命令部分）

在生产环境中，Keycloak 要求您使用 HTTPS。有多种方法可以实现这一点，包括使用将管理 HTTPS 的反向代理或负载均衡器。我们建议您阅读 [Keycloak HTTPS 文档](https://www.keycloak.org/docs/latest/server_installation/index.html#setting-up-https-ssl)以了解有关此主题的更多信息。

### Auth0

如果您想使用 [Auth0](https://auth0.com/) 而不是 Keycloak，请按照下面的配置步骤：

#### 使用 Auth0 管理控制台创建 OIDC 应用

- 在 https://auth0.com/signup 创建一个免费开发者账户。成功注册后，您的账户将与一个唯一的域名关联，如 `dev-xxx.us.auth0.com`
- 创建一个类型为 `Regular Web Applications` 的新应用程序。切换到 `Settings` 选项卡，并配置您的应用程序设置，如：
    - Allowed Callback URLs: `http://localhost:8080/login/oauth2/code/oidc`
    - Allowed Logout URLs: `http://localhost:8080/`
    - 注意：如果您使用 Consul，也要为端口 8500 添加 URL。
    - 注意：如果您使用 JHipster Registry，也要为端口 8761 添加 URL。
- 导航到 **User Management** > **Roles** 并创建名为 `ROLE_ADMIN` 和 `ROLE_USER` 的新角色。
- 导航到 **User Management** > **Users** 并创建一个新的用户账户。点击 **Role** 选项卡以向新创建的用户账户分配角色。
- 导航到 **Actions** > **Flows** 并选择 **Login**。创建一个名为 `Add Roles` 的新动作，并使用默认触发器和运行时。将 `onExecutePostLogin` 处理程序更改为如下：

  ```js
  exports.onExecutePostLogin = async (event, api) => {
    const namespace = 'https://www.jhipster.tech';
    if (event.authorization) {
      api.idToken.setCustomClaim('preferred_username', event.user.email);
      api.idToken.setCustomClaim(`${namespace}/roles`, event.authorization.roles);
      api.accessToken.setCustomClaim(`${namespace}/roles`, event.authorization.roles);
    }
  }
  ```
- 选择 **Deploy** 并将 `Add Roles` 动作拖到您的登录流程中。

_如果您希望自动化所有这些步骤，请在 Auth0 CLI 项目中的 [issue #351](https://github.com/auth0/auth0-cli/issues/351) 上添加一个 👍。_

#### 配置 JHipster 应用程序使用 Auth0 作为 OIDC 提供者

在您的 `JHipster` 应用程序中，修改 `src/main/resources/config/application.yml` 以使用您的 Auth0 设置：

```yaml
spring:
  ...
  security:
    oauth2:
      client:
        provider:
          oidc:
            # 确保包含结尾斜杠！
            issuer-uri: https://{your-auth0-domain}/
        registration:
          oidc:
            client-id: {clientId}
            client-secret: {clientSecret}
            scope: openid,profile,email,offline_access
jhipster:
  security:
    oauth2:
      audience: https://{your-auth0-domain}/api/v2/
```

如果您对 `issuer-uri` 值有疑问，那么您可以从 **Applications** > **\{Your Application}** > **Settings** > **Advanced Settings** > **Endpoints** > **OpenID Configuration** 获取该值。删除 `.well-known/openid-configuration` 后缀，因为 Spring Security 将添加该后缀。

您可以从 **Applications** > **API** > **API Audience** 字段使用默认的 `Auth0 Management API` 受众值。您也可以定义自己的自定义 API 并使用标识符作为 API 受众。

- 在运行 `Cypress` 测试之前，通过覆盖 `CYPRESS_E2E_USERNAME` 和 `CYPRESS_E2E_PASSWORD` 环境变量来指定 `Auth0` 用户详细信息。有关更多详细信息，请参阅 [Cypress 文档](https://docs.cypress.io/guides/guides/environment-variables#Setting)。

```shell
export CYPRESS_E2E_USERNAME=<your-username>
export CYPRESS_E2E_PASSWORD=<your-password>
```

_注意_：Auth0 要求用户在首次登录时提供授权同意。Cypress 测试套件目前不处理同意流程。为了缓解这个问题，您可以使用已经通过交互式登录授权应用程序访问权限的用户账户。

#### 使用环境变量

您也可以使用环境变量来覆盖默认值。例如：

```shell
export SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_OIDC_ISSUER_URI="https://{your-auth0-domain}/"
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_ID="{client-id}"
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_SECRET="{client-secret}"
export JHIPSTER_SECURITY_OAUTH2_AUDIENCE="https://{your-auth0-domain}/api/v2/"
```

您可以将此内容放在 `~/.auth0.env` 文件中，并运行 `source ~/.auth0.env` 以使用 Auth0 覆盖默认的 Keycloak 设置，并使用 Maven 或 Gradle 启动您的应用程序。您应该能够使用您注册的凭据登录。

_注意_：如果您使用 `Windows`，您应该安装 [WSL](https://docs.microsoft.com/en-us/windows/wsl/install-win10)，这样 `source` 命令才能工作。

#### 在 Auth0 上为移动应用创建原生应用

如果您使用 JHipster 的 [Ionic](https://github.com/jhipster/generator-jhipster-ionic) 或 [React Native](https://github.com/jhipster/generator-jhipster-react-native) 蓝图开发移动应用，如果您使用 OIDC，您需要在 Auth0 上创建一个原生应用。

1. 创建一个 **Native** 应用程序并添加以下允许的回调 URL：

    - Ionic: `http://localhost:8100/callback,dev.localhost.ionic:/callback`
    - React Native: `http://localhost:19006/,https://auth.expo.io/@<username>/<appname>`

2. 将允许的注销 URL 设置为：

    - Ionic: `http://localhost:8100/logout,dev.localhost.ionic:/logout`
    - React: `http://localhost:19006/,https://auth.expo.io/@<username>/<appname>`

3. 设置允许的源 (CORS)：

    - Ionic: `http://localhost:8100,capacitor://localhost,http://localhost`
    - React Native: `http://localhost:19006`

#### 更新您的 Ionic 应用

更新 `ionic/src/environments/environment.ts` 以使用生成的客户端 ID。`server_host` 的值将从您的 JHipster 应用（在 `/api/auth-info`）中查找，但您可以将其定义为回退值。您还需要指定受众。例如：

```ts
const oidcConfig: IAuthConfig = {
  client_id: '<native-client-id>',
  server_host: 'https://<your-auth0-domain>/',
  ...
};

export const environment = {
  ...
  audience: 'https://<your-auth0-domain>/api/v2/',
  ...
};
```

重启您的 Ionic 应用并使用 Auth0 登录！

#### 更新您的 React Native 应用

将客户端 ID 复制到 `app/config/app-config.js`。

更新 `app/modules/login/login.utils.ts` 中的 `audience`：

```ts
audience: 'https://<your-auth0-domain>/api/v2/',
```

重启您的 React Native 应用并使用 Auth0 登录！

### Okta

如果您想使用 Okta 而不是 Keycloak，使用 [Okta CLI](https://cli.okta.com/) 可以很快完成。安装后，运行：

```shell
okta register
```

然后，在您的 JHipster 应用目录中，运行 `okta apps create jhipster`。这将为您设置一个 Okta 应用，创建 `ROLE_ADMIN` 和 `ROLE_USER` 组，使用您的 Okta 设置创建 `.okta.env` 文件，并在您的 ID 令牌中配置 `groups` 声明。

运行 `source .okta.env` 并使用 Maven 或 Gradle 启动您的应用程序。您应该能够使用您注册的凭据登录。

如果您使用 Windows，您应该安装 [WSL](https://docs.microsoft.com/en-us/windows/wsl/install-win10)，这样 `source` 命令才能工作。

如果您希望通过 Okta 管理控制台手动配置，请参阅下面的说明。

#### 使用 Okta 管理控制台创建 OIDC 应用

首先，您需要在 https://developer.okta.com/signup 创建一个免费开发者账户。完成后，您将获得自己的 Okta 域，名称类似于 `https://dev-123456.okta.com`。

修改 `src/main/resources/config/application.yml` 以使用您的 Okta 设置。提示：将 `{yourOktaDomain}` 替换为您组织的名称（例如，`dev-123456.okta.com`）。

```yaml
security:
  oauth2:
    client:
      provider:
        oidc:
          issuer-uri: https://{yourOktaDomain}/oauth2/default
      registration:
        oidc:
          client-id: {client-id}
          client-secret: {client-secret}
          scope: openid,profile,email
```

在 Okta 中创建一个 OIDC 应用以获取 `{client-id}` 和 `{client-secret}`。为此，请登录到您的 Okta 开发者账户并导航到 **Applications** > **Applications** > **Add Application** > **Create New App**。选择 **Web**、**OpenID Connect**，然后点击 **Create**。给应用一个您能记住的名称，并将 `http://localhost:8080/login/oauth2/code/oidc` 指定为登录重定向 URI。添加 `http://localhost:8080` 作为注销重定向 URI 并点击 **Save**。将客户端 ID 和密钥复制到您的 `application.yml` 文件中。

创建一个 `ROLE_ADMIN` 和 `ROLE_USER` 组（**Directory** > **Groups** > **Add Group**）并向其中添加用户。您可以使用注册时使用的账户，或创建一个新用户（**Directory** > **People** > **Add Person**）。导航到 **Security** > **API** > **Authorization Servers**，并点击 `default` 服务器。点击 **Claims** 选项卡并 **Add Claim**。将其命名为 `groups`，并将其包含在 ID Token 中。将值类型设置为 `Groups`，并将筛选器设置为正则表达式 `.*`。点击 **Create**。

![添加声明](/images/security-add-claim.png)

进行这些更改后，您应该就可以开始了！如果您有任何问题，请将其发布到 [Stack Overflow](https://stackoverflow.com/questions/tagged/jhipster)。确保用 "jhipster" 和 "okta" 标记您的问题。

要在运行 e2e 测试时使用 Okta，您可以设置环境变量。

```shell
export CYPRESS_E2E_USERNAME=<your-username>
export CYPRESS_E2E_PASSWORD=<your-password>
```

如果您使用的是 Protractor，请删除 `CYPRESS_` 前缀。

#### 使用环境变量

您也可以使用环境变量来覆盖默认值。例如：

```shell
export SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_OIDC_ISSUER_URI="https://{yourOktaDomain}/oauth2/default"
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_ID="{client-id}"
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_SECRET="{client-secret}"
```

您可以将此内容放在 `~/.okta.env` 文件中，并运行 `source ~/.okta.env` 以使用 Okta 覆盖 Keycloak。

然后，您可以在部署到 Heroku 时设置这些属性：

```shell
heroku config:set \
  SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_OIDC_ISSUER_URI="$SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_OIDC_ISSUER_URI" \
  SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_ID="$SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_ID" \
  SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_SECRET="$SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_SECRET"
```

<a name="create-native-app-okta"></a>
#### 在 Okta 上为移动应用创建原生应用

如果您使用 JHipster 的 [Ionic](https://github.com/jhipster/generator-jhipster-ionic) 或 [React Native](https://github.com/jhipster/generator-jhipster-react-native) 蓝图开发移动应用，如果您使用 OIDC，您需要在 Okta 上创建一个原生应用。

使用 [Okta CLI](https://cli.okta.com)，运行 `okta apps create`。选择默认应用名称，或根据需要更改它。选择 **Native** 并按 **Enter**。

- **Ionic**：将重定向 URI 更改为 `[http://localhost:8100/callback,dev.localhost.ionic:/callback]`，将注销重定向 URI 更改为 `[http://localhost:8100/logout,dev.localhost.ionic:/logout]`。
- **React Native**：对于重定向 URI，使用 `[http://localhost:19006/,https://auth.expo.io/@<username>/<appname>]`。

**注意**：`dev.localhost.ionic` 是默认方案，但您也可以使用更传统的方案，如 `com.okta.dev-133337`（其中 `dev-133337.okta.com` 是您的 Okta 组织 URL）。如果您更改了它，请确保更新 Ionic 应用的 `src/environments/environment.ts` 中的 `scheme`。

Okta CLI 将在您的 Okta 组织中创建一个 OIDC 应用。它将添加您指定的重定向 URI 并向 Everyone 组授予访问权限。

```shell
Okta application configuration:
Issuer:    https://dev-133337.okta.com/oauth2/default
Client ID: 0oab8eb55Kb9jdMIr5d6
```

**注意**：您也可以使用 Okta 管理控制台来创建您的应用。有关更多信息，请参阅[创建原生应用](https://developer.okta.com/docs/guides/sign-into-mobile-app/create-okta-application/)。

#### 更新您的 Ionic 应用

```ts
oidcConfig: {
  client_id: '<native-client-id>',
  server_host: 'https://<your-okta-domain>/oauth2/default',
  ...
}
```

您还需要为 `http://localhost:8100` 添加一个受信任的来源。在您的 Okta 管理控制台中，转到 **Security** > **API** > **Trusted Origins** > **Add Origin**。使用以下值：

- Name: `http://localhost:8100`
- Origin URL: `http://localhost:8100`
- Type: 勾选 **CORS 和 Redirect** 两项

点击 **Save**。

重启您的 Ionic 应用并使用 Okta 登录！

## HTTPS

您可以通过在您的 `SecurityConfiguration.java` 中添加以下配置来强制使用 HTTPS。

```java
// Spring MVC
http.requiresChannel(channel -> channel
    .requestMatchers(r -> r.getHeader("X-Forwarded-Proto") != null).requiresSecure());
    
// WebFlux
http.redirectToHttps(redirect -> redirect
    .httpsRedirectWhen(e -> e.getRequest().getHeaders().containsKey("X-Forwarded-Proto")));
```

参阅 Spring Security 的 [Servlet](https://docs.spring.io/spring-security/site/docs/5.5.x/reference/html5/#servlet-http-redirect) 和 [WebFlux](https://docs.spring.io/spring-security/site/docs/5.5.x/reference/html5/#webflux-http-redirect) 文档以获取更多信息。

这已经在 Heroku 和 Google Cloud 上进行了测试并已知可以工作。有关 Heroku 上的更多生产提示，请参见 [Preparing a Spring Boot App for Production on Heroku](https://devcenter.heroku.com/articles/preparing-a-spring-boot-app-for-production-on-heroku)。

## 实现细节泄露

每个失败/异常都被映射到一个[问题数据结构](https://github.com/zalando/problem)并返回给客户端。

```json
{  
  "type": "https://www.jhipster.tech/problem/problem-with-message",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "Database not reachable"
}
```

虽然 JHipster 默认不包含任何堆栈跟踪，但 `detail` 包含异常的 `message`，这可能会[泄露技术细节](https://github.com/jhipster/generator-jhipster/issues/12051)，您不希望通过 API 暴露这些信息。

```json
{  
  "type": "https://www.jhipster.tech/problem/problem-with-message",
  "title": "Bad Request",
  "status": 400,
  "detail": "JSON parse error: Cannot deserialize instance of 
       `java.util.LinkedHashMap<java.lang.Object,java.lang.Object>` out of VALUE_NUMBER_INT token; nested exception is com.fasterxml.jackson.databind.exc.MismatchedInputException: Cannot deserialize instance of `java.util.LinkedHashMap<java.lang.Object,java.lang.Object>` 
       out of VALUE_NUMBER_INT token\n at [Source: (PushbackInputStream); line: 1, column: 1]"
}
```

为了防止这种情况，JHipster 提供了一个专用机制来缓解实现细节的泄露：

* 检查已知异常并用通用消息替换消息（例如 `Unable to convert http message`）
* 检查消息是否包含潜在的包名（例如 `java.` 或 `.org`）并用通用消息替换（例如 `Unexpected runtime exception`）

日志仍包含详细的异常，因此您仍可以识别真正的问题，而来自外部的攻击者无法通过滥用您的 API 获得有价值的技术细节。

如果您需要修改逻辑（例如消息仍包含技术细节但未被检测到），您可以通过在 `ExceptionTranslator.java` 中的 `prepare` 方法中添加所需的逻辑来实现。
